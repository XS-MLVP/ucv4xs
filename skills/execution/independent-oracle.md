# 如何建立独立 oracle 并选对抽象层级

## 何时使用、准备什么

实现 expected、修正模型或复核模型与 RTL 全绿时使用。输入是行为需求、规范/设计合同版本、固定配置以及接口与架构对象的映射。

## 怎么做

1. 给每条关键答案标来源和适用条件：规范、确认的设计合同、固定配置、独立性质或仅实现观察。不能从实现观察反推答案，也不能把未经核实的第三方实现当作 golden。
2. 分开架构结果和协议检查。ISA 模型不自动验证模块内部握手、状态匹配和失效；协议模型也不证明最终架构语义。写清双方交界及未验证部分。
3. 显式绑定身份、单位和粒度：输入建立年龄/目的身份，不从 DUT 返回标签倒推；逐字节/逐元素语义不能被整体地址范围或物理槽号替代。
4. 用独立算法、固定答案或不变量交叉核对关键条件，特别是权限作用域、故障优先级、编码别名和状态清理。若只能从实现推测，登记待确认，不能通过改 expected 消除差异。
5. 将规范规定的复位/配置值固定为带来源的答案，不读取 live DUT 自证；运行时协商或实现自由度则单独建合同，不误当固定值比较。
6. 构造能区分原错误算法和正确算法的数据；运行冻结错误模型或 expected 变体，要求独立检查拒绝。仅翻转读数证明的是受检路径，不是模型语义独立性或 RTL mutation coverage。

## 产出

oracle 来源表（版本/条款/配置及适用边界）、身份/粒度映射、独立答案或性质位置、代表性错误算法、正负对照及尚未确认项。纯实现刻画标 characterization；若替换/性能行为有已确认需求，也须验证该需求，不能一概排除。

## 如何验收

选一条历史同源错误：即使 RTL 和旧模型同答，独立检查仍能指出差异。布局/槽号改变而语义不变时答案保持应有不变量；规范未定义字段不被过严比较。

案例：[十二类踩坑 P04/P05](../../docs/lessons/rtl-verification-soundness-20261026.md)。
