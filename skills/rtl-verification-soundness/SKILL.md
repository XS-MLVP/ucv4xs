# RTL 验证踩坑复盘与防复发手册

> 迁移说明：保留原工作区的十二类实际踩坑及其来源，更新仓库内链接。文中“当前 LSU”等范围及策略指历史工程；新仓库的判定规则见 [维护约定](../../docs/maintenance.md)。原文件哈希见 [迁移记录](../../docs/history/experience-import.json)，各工程经验与外部证据入口见 [经验索引](../../docs/lessons/README.md)。

**这份文档总结的不是“理想的验证应该怎么做”，而是我们已经怎样做错过，以及换一个模块后如何不再犯同一种错。**

前一版把经验整理成了公理、分类和通用流程，抽掉了最有价值的信息：为什么我们当时会相信一个错误结论，消除误报的动作又怎样制造了漏检。本版改用：

> **遇到的问题 → 当时的错误判断或处理 → 为什么会误报/漏检 → 应该怎样修 → 在下一个模块用什么检查阻止复发。**

阅读时不用照搬模块名、数值或历史运行结果；要迁移的是错误机制、区分性对照和验收条件。文末链接保留经验来源，避免再把推测写成“以前已经证明过”。

## 1. 先记住这条我们反复走过的弯路

```text
合法场景被检查器误报
  → 为了让测试继续，放宽一整段检查/增加整例 XFAIL
    → 正常例通过，真正错误也被放走
      → 覆盖率和通过数都很好看
        → 独立复核或上游反例才暴露漏检
```

另一个常见循环是：发现 RTL 与模型不一致 → 按 RTL 改模型 → 全绿 → 后来发现两者一起违反契约。

因此，**一次误报修复不能只验“原用例现在通过”，还要验“相邻的真实错误现在仍会失败”**；一次漏检修复也不能靠增加过严断言制造新误报。

全文统一区分三种结论：

- **确认 RTL 问题**：合法输入与环境下，真实 DUT 的可观察行为违反已确认要求。
- **确认验证问题**：检查器、激励、环境或用例有错；不等于 RTL 有错。
- **尚未证明**：有盲区、可疑源码或缺失证据；不等于已经排除，也不等于已确认缺陷。

这是经验文档，不是本轮签核报告；本文没有重跑仿真，也不把历史整改描述为所有模块均已实施。

## 2. 十二个坑：下一个模块应该先防什么

| 编号 | 我们实际遇到的坑 | 下一模块必须增加的动作 | 用什么证明不是口号 |
|---|---|---|---|
| P01 | 端口能塞进去，就当真实上游能发出 | 建生产者准入与不可撤回点清单 | 一组合法正例 + 一组应被拒绝的非法 fixture |
| P02 | 环境漏记并发握手，却归因 RTL 丢请求 | 同一采样沿捕获所有通道事件 | 同拍请求/响应及多通道对照 |
| P03 | 比较太严产生误报，再整段静音 | 按合同限定比较和放行粒度 | 合法例通过，邻近非法事件仍失败 |
| P04 | 模型照着 RTL 算，错得完全一致 | 给关键期望建立独立来源 | 原错误算法必须被固定答案/性质拒绝 |
| P05 | 用槽号、范围、协议布局代替真实语义 | 显式绑定身份、字节与抽象层级 | 改变布局但语义不变的对照 |
| P06 | 两条路径都测了，却没让它们真正竞争 | 构造错误实现与正确实现会给不同答案的输入 | 反转优先级等错误答案必须失败 |
| P07 | 主输出没了，就以为取消干净 | 检查全部禁止副作用及后续残留 | 当拍副作用 + 后续新事务续接检查 |
| P08 | 请求没接受或没排空，用例仍通过 | 建事务义务账本及有界收尾 | 拒绝全部/阻断完成时正式用例必须失败 |
| P09 | 测试写着、字段接着，其实没执行检查 | 对账实际 collection、字段、输入键与比较器 | 故意错字段、错键、失活测试能被发现 |
| P10 | 源码有断言，就以为 DUT 有检查点 | 核实生成产物与公开可观察点 | 找到实际断言或等价端口检查 |
| P11 | strict XFAIL、调相位或改期望被当成归因 | 每次 triage 给独立原因与反向对照 | 新失败不能被旧标记无条件吞掉 |
| P12 | 高覆盖和文件齐备被当成语义验收 | 结论逐条绑定证据、版本与未闭环项 | 错 run、缺日志、漏选反例时审计必须拒绝 |

下面逐条说明这些动作从哪里来、怎样实施、什么情况下还不能宣布解决。

## 3. P01：我们把“接口能驱动”误当成“生产者能产生”

**踩过的坑。** LSQ 复核发现：CBO.zero 的 fixture 沿用普通 8B Store 的 size/mask，却按真实 CBO 包的覆盖语义推导答案；另一个反例对已经获得不可撤回许可的普通 Store 再强行自取消。MMU 复核还发现 sfence 的 rs1/rs2 字段极性理解错误，以及被当成正例的大页 PPN 实际未对齐。Sbuffer 二次裁决则提醒：不能只看 Decoupled 接口名称，就追加 Irrevocable 式的全部保持约束。它们会制造非常像 RTL Bug 的失败。[^lsq-fp][^mmu][^sbuffer-recheck]

**错在哪里。** 测试只看到了下游 bundle，没有核实真实生产者的编码、对齐、互斥和历史状态；“ROB 尚未 retire”也被简化成“任意副作用仍可撤回”。参考的一半依据输入字段，另一半依据想象中的宏观指令语义。

**迁移办法。**

1. 给特殊操作记录生产者来源、编码定义、size/mask/对齐关系、许可前提及不可撤回点。编码必须取自当前固定版本，不凭名称或旧项目记忆。
2. fixture 先做准入检查，再送 DUT。涉及历史许可的场景，必须给出能产生该状态的合法序列。
3. 改正错误正例时，保留原非法输入为明确的负例或压力测试；不要因此放松 fault 检查。
4. 有 valid/ready 不等于与另一个总线协议相同；背压期间的 payload 保持、撤销和重发要求逐项核实，不能凭通用经验增加断言。

**防复发检查。** 同一 fixture builder 至少测试“合法输入能通过准入”和“违反一条关键约束会被拒绝”；正常路径用例必须真的出现 fire。

**边界。** 端口级越域压力仍可能有价值，但不能自动升级成当前生产路径或整机可触发 Bug；一个旧反例不合法，也不能推翻另一个独立的合法反例。

## 4. P02：我们把环境漏采样，误诊成了 RTL 并发错误

**踩过的坑。** MMU 的 service 用 if/continue 串行处理端口：发送响应时，另一个 ready=1 的请求已经 fire，却没被记录。由此出现“请求停顿”“预取替代 demand”“某延迟下双 beat 丢失”等解释。改成每沿捕获全部 fire 后，相关旧归因被撤回。增大 latency 后通过，只证明了时序相关，并没有证明原来的 RTL 根因。[^mmu]

**错在哪里。** 环境承担多个通道，却被实现成“一拍只服务一件事”；driver、monitor 和软件账本对真实握手的认识不一致。

**迁移办法。**

1. 在接口规定的采样时刻获取同一拍全部通道快照，再统一提交事件；不能因某通道进入分支而跳过其他通道采样。
2. 等待 A 通道时仍服务 B/C 通道，reset 同时清理 pending、记录和临时放行状态。
3. 对延迟做小范围对照，检查事件守恒和身份，而不只看最后是否返回。必要时使用有界 trace 定位，不默认保存逐周期大 dump。

**防复发检查。** 一个用例主动制造“旧响应返回 + 新请求接受”同拍，再制造两个入口同拍 fire；监视器记录数、事务 UID 与实际采样值逐项对齐。

**边界。** 没观察到事件，不等于 DUT 没产生事件；改变响应延迟或插入空拍使失败消失，不是根因证明。

## 5. P03：我们为消除假阳性开了大口子，随后制造假阴性

**踩过的坑。** ICache 为容忍模型没描述的合法预取 acquire，打开了 `allow_unexpected`；实现却对整个窗口的额外 acquire 静音。未接受请求带来的非法 acquire 也被一起放过。复核还指出：无效项残留载荷、未选通道、被掩码位如果被过严比较，会产生误报，并诱导人继续放宽检查。[^icache-errors][^icache-lessons]

**错在哪里。** “这一项在此条件下不保证”被改成了“这一段时间什么都不查”；模型表达不了合法额外事务，也被用来合理化关闭检查。

**迁移办法。**

1. 先确认字段在什么 valid/mask/选择条件下受合同约束；只对确实未定义的字段停止比较，留下原因。不能把所有 valid=0 的副带信号一概当 don't-care。
2. 对合法额外事件建立允许集合，绑定事务、地址、类型和窗口；仍记录明细，数量和重复性按具体合同校验。
3. 模型表达不了组合或额外事务，就扩展模型；暂时做不到，明确列为未验证，不生成“已检查”记录。

**防复发检查。** 成对保存：合法例外通过；同一放行窗口里多一个未授权地址/事务必须失败。对不保证的字段翻转应不误报，对仍保证的邻近字段翻转必须报错。

**边界。** 不要求所有信号都比较，也不追求“检查器越严越好”；目标是准确而非一刀切。

## 6. P04：我们把 RTL 的错误写进模型，又写成了合同

**踩过的坑。** LSU 的 Store tval 用例已经让输入 VA 与 TLB fullva 不同，却明确断言应使用输入 VA；模型和注释共同固化了错误。HWPF 计数条件已被发现互斥，却被归为“结构死逻辑，期望恒 0”。MMU 的另一类问题则是把 DUT 当前 PMA 初值读回当预期，初值错了也会一致通过。[^lsu-missed][^mmu]

**错在哪里。** “实现现在这样做”被替换成“应该这样做”。单纯多加同源模型比较、增加随机次数，不能推翻这个共同错误。

**迁移办法。**

1. 对异常地址、权限、取消、清理、计数等关键语义，先写一句可观察要求，再查接口和时序。
2. 期望标明来源：规范、已确认设计契约、固定配置或仅实现刻画。实现刻画不能作为独立正确性证明。
3. 保留同源模型做实现一致性检查，但另加不复用其错误条件的固定答案或性质；不能让“独立检查”再次调用同一 expected 函数。

**防复发检查。** 选一条最危险的旧错误算法，运行冻结的修前模型或对应错误变体，要求独立答案能拒绝它。数据必须让错误算法和正确算法产生不同结果，不能仅检查二者恰好相等的普通地址。

**边界。** 固定配置表比读 DUT 自证更独立，但仍只是配置级 oracle；检查器读数注错也不是 RTL mutation coverage。

## 7. P05：我们用错了表示层，模型与硬件“相等”仍答非所问

**踩过的坑。** LSQ 的同源复核和 VAGQ 的参考重建暴露了身份与粒度问题：物理槽位、内部窗口或分配布局不能天然代表程序年龄、架构元素或目的寄存器。VAGQ 后来明确分离协议入口与架构入口，并要求显式绑定目的身份。LSQ 还纠正过把 cacheline 粒度拿来推导 refill beat 的错误。[^lsq-source][^lsq-fp][^vagq]

**错在哪里。** 参考和 DUT 用的是同一种内部表示，比较全部输出也可能没有回答架构问题；从候选输出反推它应当属于谁，是循环论证。

**迁移办法。**

1. 明确区分架构对象、接口事务、物理槽位和内部片段；单位、地址域、年龄和身份逐项绑定。
2. 用独立输入和生产者契约建立身份，不从 DUT 返回标签反推。
3. 整体范围不能替代逐字节/逐元素覆盖；宽度、对齐、步距和余数必须分别算清。

**防复发检查。** 使用非零起点、回绕、部分覆盖或稀疏 mask；增加“改物理布局/标签但不改语义”的对照，答案应保持相应不变量。

**边界。** 模块协议 UT 通过不等于 ISA 正确；合成 producer、ACK 或内存代理也不是对应真实子系统的动态验证。

## 8. P06：用例名字写了“优先级/同时”，输入却不能区分对错

**踩过的坑。** Sbuffer 的 active-over-inflight 用例让旧数据占 lane0、新数据占 lane1，查询 lane1；虽然两类状态共存，却没有同字节竞争。把参考优先级反转，原用例仍通过。kill 用例没有真正的标签 mismatch，也不能证明 kill 抑制有效。LSU 把 CBO+IO 的一个样本当作整个 uncache 类，漏掉 CBO+NC；ICache 两条预取路径各自测试过，却没测同拍组合。[^sbuffer-audit][^sbuffer-recheck][^lsu-missed][^icache-errors]

**错在哪里。** 状态共存不等于竞争；操作先后出现不等于同时；bin 名字也不证明它表达的区分性语义被检查。

**迁移办法。**

1. 写用例前先问：“把优先级反过来/去掉 kill/把 NC 当 IO，哪一条输出一定改变？”答不出就先改激励。
2. 同一字节放不同的新旧值，设置真实 mismatch，令请求与响应在同一采样沿竞争同一状态。
3. 检查等价类是否真等价，逐个列编码/属性组合；随机边界用固定种子取值集合或定向扫描证明到达。

**防复发检查。** 保存一个正确答案和一个有代表性的错误答案；正确 DUT 对正确答案通过，对错误答案失败。覆盖采样同时关联实际竞争条件与检查位置。

**边界。** 扰动存活首先说明当前实验未区分某类错误，不能据此认定 RTL 有该错误；新增区分性检查通过，也不证明所有组合都正确。

## 9. P07：我们只证明“主流程停了”，没有证明“副作用消失了”

**踩过的坑。** LSU redirect 用例只查 `pipeOut_valid=0`，漏掉仍然有效的 ROB/RF/LQ 写。matchInvalid 用例只查 rollback，没查 replay need/cause 清理。ICache 的 flush/取消复盘也指出，只清指针不足以排除异常、目的地和优先级残留。[^lsu-missed][^icache-lessons]

**错在哪里。** 把一个可见标志当作整个语义；软件模型还可能保留同样的残留，因此多比较几个同源字段也不一定能发现。

**迁移办法。**

1. 对 kill/flush/redirect/异常/拒绝，逐项列出：必须发生、禁止发生、允许延后发生的副作用。
2. 检查下游请求、写回、队列写、异常/replay 信息、计数及占用变化，不只检查主 valid。
3. 做后续续接事务：新事务不得继承旧身份、异常或数据；被拒绝/撤销事务不得后来复活。时间界限依据接口契约。

**防复发检查。** 控制事件发生当拍检查全部禁止副作用，再发一个身份和数据都不同的新事务检查恢复；故意保留一个残留字段时，新检查必须失败。

**边界。** 不是所有取消都可在任意阶段发生，也不是所有事件都要求同拍清零；必须与 P01 的合法历史和不可撤回点一起判断。

## 10. P08：我们把“没有待检查对象”误当成“所有事务已完成”

**踩过的坑。** Sbuffer 正式用例在 offered=4、accepted=0 时仍可 PASS；另一正式用例排空预算耗尽，模型还有 8 行却正常返回。按 DUT 实际 fire 更新模型本身是合理的，真正缺口是没有独立的事务目标和收尾要求。ICache 经验还专门指出另一种假完成：按 valid 持续电平重复计数，用同一事务凑齐目标数，掩盖某入口从未工作。[^sbuffer-recheck][^icache-lessons]

**错在哪里。** 用同一个“已接受集合”同时决定 expected 和测试是否该继续，错误拒绝的请求从两边一起消失；driver 返回被误当成事务完成。

**迁移办法。**

1. 分开记录尝试发送、实际接受、仍待提交、明确放弃/拒绝、完成、合法取消和 outstanding，使用不可变事务 UID。
2. 明确用例承诺：是验证可拒绝，还是必须最终接受 N 笔？若要求最终接受，按合同保持或重试并设 watchdog，不能因 ready=0 默默放弃。
3. drain 预算耗尽必须失败；只有义务全部偿还或合法取消后才结束。活性要求及例外先由规范/合同确认，不能反向要求所有配置所有旧在途事务必定完成。
4. 按合同定义的 fire/完成事件计数，区分保持、重放和新事务；按 UID 和源分别对账，不凭聚合总数或“载荷相同”决定身份。

**防复发检查。** 在完整正式用例链上模拟“全部不接受”和“接受后永不完成”，应在目标计数或 watchdog 处失败；再以正常环境作通过对照。另让一个事务在背压下保持多拍，接受数不能因此增加；多入口流量须逐源核对身份与完成数。

**边界。** 直接用非法参数调用局部 helper，只能证明该 helper 缺少防御，未必证明正式路径可出现假通过。账本必须按本接口定义，不能机械套用 offered=accepted+rejected；持续待提交和重试都要单独计数。

## 11. P09：我们写了测试和字段，却没有真的执行到检查

**踩过的坑。** MMU 发现重复函数被后定义覆盖、字面量反斜杠 n 让测试留在注释里、两处恒真/条件逃逸断言；ICache 复核发现模型算了但比较器没比的死字段，以及提供了却没有激励置起的死开关。LSU 还发现输入键静默忽略和 factory 创建 DUT 未进入覆盖采集。[^mmu][^icache-lessons][^lsu-fn]

**错在哪里。** 文件存在、测试名称、断言数量、模型字段数被当成执行证据；未知键和缺失输出的默认补零又掩盖了接线错误。

**迁移办法。**

1. 对账定义、真实 collection 与选入的 nodeid；参数化节点、helper 和重复定义分开解释，不机械要求所有数字相等。
2. 对账“模型计算 → 观测采集 → 实际比较 → 哪条用例驱动”；未知输入键和必需缺失端口立即失败。
3. AST/grep 只用于筛查，再看调用链和语言语义；MMU 曾撤回对正常 Python 位运算优先级表达式的错误归因，不能把命中可疑文本就当缺陷。

**防复发检查。** 故意拼错一个输入键、去掉一个必需字段、翻转一个已声明受检输出，分别确认失败；收集审计可识别重名失活函数，覆盖采集能看到每个实际创建的 DUT。

**边界。** 一个 helper 内有断言，不能证明所有调用都执行了它；静态审计通过也不是检查器完整性证明。

## 12. P10：源码里有断言，不等于被测产物里有；没有端口也不能假装测过

**踩过的坑。** ICache 上游症状是 bank 断言触发，本地生成 DUT 却已裁掉该断言，必须改查未授权 acquire。LSU 的 StdExe 性能计数器未导出端口，现有证据只能是固定源码契约检查。[^icache-errors][^lsu-missed]

**错在哪里。** 把源码能力当生成产物能力，把“当前 UT 无法观察”当“已覆盖”或“不是问题”。

**迁移办法。**

1. 构建后核实关键断言是否存在并启用，公开端口是否包含受检字段；不能只检查原 Scala。
2. 直接断言不在，就寻找可观察后果并建立等价检查；间接观测较弱时写明边界。
3. 静态源码检查、纯模型检查、真实 DUT 动态证据分别列出。需要新导出点时遵守项目范围和 RTL 不修改约束，做不到就明确未动态验证。

**防复发检查。** 每条关键要求都能指出“生成产物中的断言”或“公开输出与实际检查位置”；两者都没有，就不能进入动态已验证清单。

**边界。** 故障读数注入不是改过 RTL 的 mutant；测试有波形文件也不自动证明该文件包含有时钟推进的真实活动。

## 13. P11：我们把“能让失败消失”当成“已经找到原因”

**踩过的坑。** MMU 整例 strict XFAIL 会吞掉任意断言、timeout 甚至 setup 错误；strict 只约束 XPASS，不约束失败原因。LSU 复盘指出，改模型、驱动键或相位可能把真实问题“修”成通过。Sbuffer 二次裁决还收窄了局部 helper 反例与扰动存活的结论，避免把检查缺口说成硬件错误。[^mmu][^lsu-missed][^sbuffer-recheck]

**错在哪里。** 修复动作和根因没有分开；实验相关性、覆盖不足、工具异常、测试缺陷、RTL 缺陷被混为一谈。

**迁移办法。**

1. 改 expected、相位、输入或环境前，保存原失败和当时源码，写清要验证的原因。
2. 用最小合法复现及邻近对照验证归因；修正验证错误后重跑原场景，不能仅删掉失败条件。
3. 当前 LSU 项目要求真实失败保持普通 FAIL，不引入 xfail/skip/waiver。其他项目的历史 XFAIL 只能作为被审计对象，不能作为本项目默认策略。

**防复发检查。** 对误报修复同时保存“合法场景不再误报”和“故意违反仍受保证的语义时会失败”；对漏检修复保存“原反例现在可检出”和“合法邻近场景不误报”。

**边界。** 区分未完成审计、已证实测试问题、已证实 RTL 问题和已有反证；缺原始 traceback/源码时保留未确认，不编造历史根因。

## 14. P12：我们把覆盖、归档和计数的完整，误当成验证结论完整

**踩过的坑。** LSU 原来的全绿结论被撤回：功能 bin 采样齐全，不等于每项都有独立结果检查；部分曾标“不可达”的点后来被合法父块用例命中。Sbuffer 新的功能重跑不能配上旧覆盖率冒充同轮结果；MMU 修正环境后的覆盖下降也不能回填旧高值。DCache 复核还发现功能点文档写了测试根本没断言的行为。[^lsu-fn][^lsu-coverage][^sbuffer-audit][^mmu][^dcache]

**错在哪里。** reached、checked、独立期望被合并；报告从旧数字或直觉生成，反过来成为验证依据；交付脚本只查文件齐全却被当语义验收。

**迁移办法。**

1. 每条功能点分别说明：什么输入到达、什么结果被检查、期望来自哪里；缺一项就如实列缺口，不创造“认证”标签替代证明。
2. “未命中”先是激励/观测缺口；宣称不可达必须给定合法域、参数和结构证据。逻辑恒零也要先问它是否违反功能意图。
3. 每个结果绑定 source epoch、RTL/build 哈希、种子、nodeid、console/JUnit 和 run 目录；保留旧失败，不用当前源码解释旧运行。
4. 修改报告生成器前检查旧 run 与硬编码计数，防止重生成覆盖后续人工复核结论；反例必须进入实际默认选择或被明确列为未选入。

**防复发检查。** 抽一个高风险功能点，从报告反查到实际断言、输入和运行；再故意提供旧 run、缺失日志或漏选反例的清单，交付审计应拒绝。逐 DUT 保留原始覆盖分母，明确展示汇总不等于独立证明。

**边界。** 重复种子、父子层症状和重复上游报告不重复计根因；审计脚本 PASS 只证明所声明的审计条件，不能证明所有语义正确。

## 15. 修一个问题，至少留下三样东西

不要只留下聊天结论、一个“fixed”状态或更多随机种子。

| 工件 | 要写什么 | 为什么必须有 |
|---|---|---|
| 经验条目 | 原错误假设、具体位置、误报还是漏检、证据边界 | 后来者知道不要重复哪个决策 |
| 成对回归 | 一个合法通过对照，一个有针对性的错误/反例对照 | 防止消除误报时制造漏检，或反过来 |
| 持续门禁 | 放在哪个 fixture/checker/runner/collection/报告审计入口 | 不依赖每个人记住一篇长文 |

推荐沿用以下最小记录，不要求新建庞大框架：

```yaml
lesson_id: Pxx
old_assumption: 当时相信了什么
observed_problem: 实际怎样误报或漏检
source: 冻结源码/报告/运行位置
change: 修改了激励、环境、期望还是检查器；为什么允许改
legal_control: 合法场景如何证明不误报
error_control: 哪个具体错误必须检出；注入在哪一层
guard_location: 下一个模块的具体持续检查入口
evidence: 两个对照的真实结果及来源
remaining_limit: 还没有证明什么
```

如果没有运行过，`evidence` 写待执行；不能因为模板填完就标“已解决”。

## 16. 换到下一个模块时，按四个时机落实

### 开始写用例前

- 看 P01/P04/P05：真实生产者允许什么？关键预期是否独立？身份、粒度和抽象层级是否明确？
- 输出一张简短表：要求、输入前提、观察结果、期望来源；不再凭旧报告直觉写功能点。

### 环境能驱动后

- 看 P02/P08/P09：同拍事件能否全部采到？有独立事务目标吗？未知键是否直接失败？
- 用一个多通道同拍对照和一个“没有接受/没有完成”对照，先验证环境不会制造红绿假象。

### 某条功能看起来通过后

- 看 P03/P06/P07/P10：错实现在哪个输入会答错？同拍竞争真发生了吗？取消有没有遗漏副作用？观察点在当前产物里吗？
- 对高风险检查做针对性读数/期望注错；明确这是检查器实验，不冒充 RTL 缺陷。

### 修改 triage 或准备汇报前

- 看 P11/P12：失败为何消失？对照还在吗？反例实际选入了吗？新结论是否绑定同一轮源码与结果？
- 有真实 FAIL 就报告 FAIL；未闭环就列未闭环。不能用提高覆盖率或“缺陷数符合预期”改写正确性结果。

## 17. 一张实际可用的复核表

不要机械勾选；每项填具体位置、结果或未完成原因。

| 要问的问题 | 对应经验 | 必填内容 |
|---|---|---|
| 是否重现了以前出过问题的生产者/编码约束？ | P01 | 定义来源 + 合法/非法 fixture |
| 同拍多通道会不会漏采，reset 会不会留 pending？ | P02 | 同拍对照 + 清理位置 |
| 消除误报是否只收窄到字段/事件，而非整段？ | P03 | 放行条件 + 邻近非法对照 |
| 模型与 RTL 一起错时，谁能指出？ | P04/P05 | 独立答案 + 身份/粒度来源 |
| 把优先级反过来、去掉 kill，原用例会失败吗？ | P06/P07 | 区分性输入 + 实际检查 |
| 0 笔接受、接受后不完成，还能 PASS 吗？ | P08 | 完整用例负向对照 |
| 声称有的检查，是否真的收集、驱动、比较？ | P09/P10 | nodeid + 公开信号/断言位置 |
| 修复后失败消失的原因是否有独立证据？ | P11 | 修前证据 + 修后成对对照 |
| 报告里的每个关键结论能否找到对应 run？ | P12 | 版本/哈希/日志 + 限制 |
