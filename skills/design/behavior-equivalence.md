# 如何划分行为等价类和关键组合

## 何时使用、准备什么

功能点只有指令清单、单路径用例或“覆盖率很高”时使用。输入是已定义的 [DUT 合同与合法域](requirements-boundary.md)、需求清单、状态历史及历史错误模型。

## 怎么做

先接收[模块行为清单](requirements-boundary.md#先建立模块行为清单不从现有用例反推需求全集)，
再给每个行为族划分场景。**行为族 ≠ 功能 ID ≠ 场景 ≠ 参数实例**：同一行为族可以关联
多个功能 ID；一个场景明确输入、前态和结果；参数只有改变可观察行为或检错能力时才
形成独立等价类。归类覆盖所有旧 ID，不代表以下场景矩阵已经建立。

1. **建立来源到 DUT 的映射。** 将能到达 DUT 的指令/上游事务映射到字段、编码、模式和历史条件。只有合同保证本层观察结果与状态转移相同，才能合并；字段相同但历史不同不能自动等价。映射必须逐族给出"本层 / 出域（谁承接）/ 未证明"结论，不得因没有用例就默认某族不存在。
2. **按模块找维度。** 至少检查操作类别、身份/年龄、地址/粒度、权限/属性、资源状态、取消/复位及并发关系；**再加一维"响应结果域"**（完成 / 故障 / 重放 / refill / tag 错误 / 翻译 miss）。最后一维最容易被忽略：刺激合法不代表响应只有一个值，只测干净响应会把"错误响应读错字段"整类漏掉。MMU 的 stage/fence/NAPOT 是模块实例，不是所有模块必填的固定分类。
3. **构造区分性样本。** 每一类写正确行为和代表性错误行为分别会输出什么。**错误必须同时出现在刺激侧和响应侧**：只注入"非法输入"不够，还要对同一合法刺激换一种响应（错误码、冲突、背压、miss），并断言它到达了正确输出。若样本使二者同答，换边界、数据或状态历史；不能靠用例名声称测到了优先级。
4. **分层安排组合。** 单维覆盖后，显式补关键交叉、边界和历史序列；pairwise/约束随机只能补充大空间，不能保证三维以上交互或时序性质。高风险交叉要有定向用例和选择理由。类别 × 结果域的矩阵要逐格给状态，空白格本身就是缺陷。
5. **检查时序而非只查静态状态。** 分别处理同拍竞争、背压多拍、先错后对、失效与 refill 交错、取消后续接、ID/槽位回绕。只有合同允许的序列才作为功能反例。
6. **把新反例回填到分类。** 发现同键异阶段、陈旧状态、权限作用域或编码别名问题时，检查原等价类为什么错误合并；不只增加孤立测试。**新增类别或新增结果域时同样回填**：改矩阵、改来源映射、补对应 nodeid，三者缺一即视为未完成。
7. **把分类做成可执行账本。** 矩阵尽量落成工程内可机读的数据结构（如 `function_points.py`），并用自检断言"每个类别 × 每个结果域都有状态；pass/fail 有证据；gap 有缺什么和怎么补"。只写在文档里的矩阵会在迭代中腐烂。

## 产出

| 类/组合 ID | 合法前提及构造序列 | 为什么可合并/必须拆开 | 正确/错误结果差异 | 断言/nodeid | 状态 |
|---|---|---|---|---|---|
| `<类>` | `<输入+历史>` | `<合同依据>` | `<区分点>` | `<位置>` | `<检查结果/不适用证据/残余>` |

另附一张**类别 × 结果域**矩阵（行=类别，列=完成/故障/重放/refill/tag 错误/翻译 miss 等），
每格标 `pass`/`fail`/`gap`/`na`/`out-of-domain`。空白格、只标 `pass` 却没有 nodeid、
`gap` 没有"缺什么+怎么补"，都按未完成处理。

有限矩阵的每项必须有处置；未展开的大空间单独说明抽样策略和残余，不能用"已 pairwise"声称全组合闭合。

场景表的每行还要给稳定 `behavior_id/scenario_id`、合法性与合同来源、前态构造、
独立预期、禁止副作用、完成义务和所需交叉。来源未确认、前态未到达、观察缺失、
检查被首错挡住和根本没有用例分别记录原因，不统称“未覆盖”。发现“无用例的应有
行为”时允许新增候选行和 gap，不必先有一个已通过的旧功能点。

设计审查、实现接通、运行判定是独立状态。历史某个 nodeid PASS 只有在同版本合同、
选定场景的全部必需义务实际比较并完成时，才能支持那一格；不能从行为族汇总 PASS
反推所有场景都 checked。响应域按本模块合同选择，域外结果给承接层，不强制给没有
错误响应端口的模块添加总线 fault/refill 列。

## 如何验收

- 来源映射没有静默遗漏；未分类项列为待分析，不强塞进"其他"。出域项要写出承接模块，不能只写"没测"。
- 每个类别至少有一个"错误响应"样本，且该样本在真实 DUT 上被观测到；只有干净响应覆盖的类别不算通过。
- 抽查优先级/同时性用例：故意反转选择规则时，样本必须出现可检查差异。
- 矩阵条目有真实检查或明确缺口，不能仅关联 `sample()`/bin 名。
- 不要求字面穷举所有指令和所有状态；结论受已定义类、组合及运行范围约束。
