# 恢复整份原预测，不能拼接两条分支的不同年龄

## 为什么补这个功能义务

先检查最大的BPU集成缺口：自然工作集的四个替换程序在Main方向写入归属检查失败，四个多条件前缀程序被短历史15位标签问题阻断。它们没有完成后续生命周期，不能简单归因于没有枚举更多bank。保留这些失败，不重复开发相同准备过程。

进一步核对恢复证据：已有恢复程序只检查一个短来源，已有双来源程序只检查学习。因此先定义[整份快照契约](saved-vector-contract.json)，补强008/009，而不是新增物理坐标功能点。353个功能编号、全部旧contract和其余351个定义均保持。

人的要求是：同一个预测窗口中，两条分支分别依赖短、长历史经验；恢复一份预测时，两条经验必须一起来自正确年龄，不能一条取年轻值、另一条取旧值，也不能把恢复误做成一次新读取。

## 怎样产生有区分度的证据

正常反馈建立三个来路，每个来路都有两条温态经验。三份向量中，短来源与长来源的计数分别都可区分。较早条件的基础预测为T、经验为NT；较晚条件相反。两条有效槽反向排列且带空洞，判断按指令位置，不按数组序号。

中级/晚级恢复、短来源服务较早/较晚条件、原历史匹配/改变历史而拒绝、无学习/并发学习，组成16个完整程序。PC和历史沿用已有身份用例，不枚举bank/set。

8个并发学习程序特意选择两份内部计数：短在前时原值为1/5、新值0/4；短在后时原值为6/2、新值5/1。两份新值都在恢复边界前或同边界已经实际写入；恢复仍消费原值，之后三个来路的新查询分别消费当前值或未变值。不是只看到override有效，也不是在饱和计数上观察无法区分的重复写入。

## 没有获得什么信用

这是真实独立UT切点的整份恢复验证，不是完整BPU/FTQ可达性证明，也不关闭1404个受约束历史游标行、4043个Ahead集成行或4022个短历史保护行。行缺口仍保留原分母和逐行语义关联。新增功能证据不能冒称行覆盖增长。

下一轮复用这些完整程序，转向尚未完整证明的集成行为，例如有效非零循环经验下TAGE与SC共同学习；若准备又被既有差异阻断，应保留精确反例并检查其他独立要求，不重复物理组合。
