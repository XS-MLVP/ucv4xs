# ITTAGE：间接目标身份、学习、区域容量与服务可见性

新增DUT刺激之前，审查剩余18项旧ID，保留019零置信跨区域学习的普通FAIL合同。
目标是原分支在原历史下拥有什么完整目标；provider、置信度、替换保护、
区域指针及保留版本分别有语义，不能只凭命中或低地址相同判定正确。

`ittage/Ittage.scala`与`IttageTable.scala`描述匹配、学习、区域目录和维护；
`model/semantic.py`从reset独立维护三张表、两bank、版本、读取快照与区域目录。
随机分配比较的是独立推导的合法候选集合，不是声称精确复刻每拍随机选择；
已检查合法的实际选择可作为原公开metadata反馈输入，不用实际SRAM修正golden。
`model/region.py`用不同编码的树PLRU描述16区域，且允许显式容量替换造成旧指针
重新解释。不能把预测器容量契约误写成无限保留完整目标。

ITTAGE原生行已全命中，但019仍FAIL，017仍有编码检查与硬件功能的证据边界。
因此不能用行满覆盖宣布功能完备。本轮不改RTL、参考算法或既有pytest判定。
地址语义以ITTAGE公共API的字节地址为准；硬件PrunedAddr省略位零的转换不是
让目标区域大小翻倍的理由。RAS/MicroRAS的API单位另在各自适配层明确。

### ITTAGE-001：冷身份不伪造目标来源，并给出合法学习机会

- 事件：reset后未学习的原PC/历史正常查询间接目标。
- 所有权：是否命中和可分配资格属于该原查询身份，不属于当前任意残留条目。
- 效果：不返回虚假有效provider，有候选时给出更长历史的合法分配机会。
- 观察：独立冷态和合法候选集合与实际命中、来源及分配metadata比较。
- 保持：查询不分配或触碰无关身份，不把无效目标原始位当作已预测目标。
- 范围：当前三表配置的冷查询；合法集合检查不等于精确随机序列验证。
- 证据边界：旧cold用例只检查有效性，默认参考补充合法集合；没有专属成对事件组。

### ITTAGE-002：合格间接分支反馈建立原历史的完整目标来源

- 事件：真实taken间接分支误预测反馈带原始metadata和合法分配候选。
- 所有权：学习属于原PC/历史，完整目标包含区域和偏移而不是只含低地址。
- 效果：建立规定置信初态的provider，fresh原身份查询返回完整目标。
- 观察：原反馈接纳、独立候选资格/目标压缩与实际后续命中完整地址比较。
- 保持：其他历史与不应替换的条目保持，原metadata不被编码过程修改。
- 范围：独立UT正常分配链；不是全部随机竞争、集成PHR或完整FTQ来源证明。
- 证据边界：单次分配命中不证明零置信重写或目录满后的目标持久性，分别另审。

### ITTAGE-003：原目标对错改变置信度，失信后的目标学习仍保持完整地址

- 事件：原provider分别收到确认旧目标或指出新目标的合格反馈。
- 所有权：置信与目标更新属于该原历史provider及其原快照，不属于当前另一个目标来源。
- 效果：正确增加、错误降低置信；达到可重写条件时学习完整新目标，而非仅改变命中表编号。
- 观察：独立逐次置信和目标期望与fresh provider/alternate完整metadata及最终选择比较。
- 保持：未参与历史、其他来源及原快照保持，不能用意外新分配掩盖原provider写错目标。
- 范围：声明的目标变化链；019无新表分配的跨区域反例仍独立保留，不能借003 PASS豁免。
- 证据边界：旧用例等待最终目标改变且只检查置信范围，默认参考才检查精确中间值；两端保持/反向恢复仍需专属DUT义务。

### ITTAGE-004：关闭使用资格时不暴露有效间接目标命中

- 事件：已学习或冷身份在enable关闭时进行正常查询。
- 所有权：有效命中属于该原请求的使用资格，不能只因内部仍有provider就返回有效纠正。
- 效果：公开有效性与hit被抑制，不把无效总线上的残留target当作预测。
- 观察：比较开启/关闭的同身份资格与定义metadata。
- 保持：单纯关闭查询不清空已学目标或修改其他身份。
- 范围：预测侧使用门控；训练门控和重新开启保留另由011检查。
- 证据边界：静态关闭不证明切换当拍所有在途响应的寿命策略。

### ITTAGE-005：最长来源失信时，目标选择回退到该分支的次长来源

- 事件：同一原历史有provider与alternate，反馈使provider置信降至零。
- 所有权：两份完整目标分别属于原历史的长/次长来源，不能互借当前metadata。
- 效果：零置信provider仍存在，但实际预测采用正确alternate；来源和目标metadata保持可区分。
- 观察：预先建立不同目标，比较置信下降、实际选择与两个完整来源字段。
- 保持：未失效来源和其他历史保持，不把重新分配出来的同地址当作原alternate。
- 范围：已分配双来源的零置信回退；不是任意目标目录替换或全部学习策略证明。
- 证据边界：只看selected target会遗漏被alternate掩盖的provider错误，019仍须检查完整provider字段。

### ITTAGE-006：重叠查询按原PC和历史返还目标，而不跟随最新请求

- 事件：多个具有不同目标/历史的查询相邻被接纳并在流水线上重叠。
- 所有权：每份响应属于接纳时的PC、历史及表读取快照，不属于返回当拍线上值。
- 效果：完整目标、来源与metadata逐笔正确，接纳/完成次序符合协议。
- 观察：现有driver/monitor与异步scoreboard按接纳关联每份定义结果。
- 保持：原请求快照、邻居和历史保持，测试层不暴露边沿或靠固定等待完成关联。
- 范围：当前独立UT三周期查询协议及声明输入；背压、取消和目录并发替换另需专门范围。
- 证据边界：延迟是driver协议参数，不是功能名称；同目标返回本身不能证明年龄正确。

### ITTAGE-007：回退后的继续学习仍保留原alternate完整目标

- 事件：原provider置信为零且alternate实际被选择，后续合格反馈继续学习。
- 所有权：原provider、被选择alternate及其目标各自拥有学习义务，不因最终方向相同而混同。
- 效果：按原资格更新置信/目标，正确alternate目标不被无关重写或压缩丢失。
- 观察：比较反馈前后两个完整来源字段及fresh selected target。
- 保持：其他历史和原metadata保持，不只检查公开selected target而漏掉隐藏来源。
- 范围：声明的正确alternate反馈；错误alternate的惩罚/零置信跨区域重写另需证据。
- 证据边界：旧用例只有一次正确继续反馈，不能据此证明全部双来源学习组合。

### ITTAGE-008：分配压力触发保护维护时，间接目标身份仍能被消费

- 事件：真实需要分配但没有候选的反馈累积至保护维护条件。
- 所有权：失败计数属于合格机会，维护改变替换保护，不是清除原provider/目标。
- 效果：维护可推进并降低保护压力，原有效目标及置信按各自学习规则保持。
- 观察：独立失败/维护进程与实际服务及fresh完整目标消费者比较。
- 保持：普通目标写入和useful-only维护不能互相抹掉定义字段，其他身份保持。
- 范围：独立UT无候选压力和目标保留；完整集成维护另有INT-074证据，不能自动移植其来源资格。
- 证据边界：旧260次反馈及末端target断言不单独证明全表扫掠、读/更新阻挡和非零保护清除；已有074范围另行核对，不虚构“没有维护验证”。

### ITTAGE-009：同PC不同历史拥有各自目标，交错和回访不串写

- 事件：相同PC在可区分历史下分别学习不同目标，再重叠/反向查询。
- 所有权：目标来源由原历史派生坐标/tag拥有，PC相同不代表同一条缓存身份。
- 效果：各历史分别返回自身完整目标，回到较早历史仍保有原学习。
- 观察：独立历史坐标与条目参考比较逐笔实际目标、来源及metadata。
- 保持：原快照及非目标历史保持，不以实际调试索引或SRAM播种golden。
- 范围：独立UT代表折叠历史；不是集成PHR生成器、所有历史位或全FTQ证明。
- 证据边界：默认语义程序与旧零/非零历史用例都保留，未给每种历史新增功能ID。

### ITTAGE-010：反馈不在首槽时，仍选中唯一有资格的原间接分支

- 事件：唯一taken非return间接分支出现在非零resolve位置，其他位置为空或无资格。
- 所有权：学习目标属于该原分支及其metadata，不属于slot0默认字段。
- 效果：正确分支目标被学习并由后续原身份查询消费。
- 观察：完整实际反馈与fresh完整目标/来源比较，不能只检查某个训练valid。
- 保持：空/无资格槽保持无效，原metadata和其他历史不被污染。
- 范围：唯一合格间接分支的稀疏反馈；多合格输入在当前API中拒绝，不猜测硬件优先级。
- 证据边界：训练槽是映射边界参数，与013的无资格先行分支有共享语义但不能互相代替所有组合。

### ITTAGE-011：禁用不新学也不使用，重新启用仍保留原目标

- 事件：全局关闭时对原冷/热身份查询和反馈，随后重新开启同份合法反馈。
- 所有权：enable控制新使用/新学习资格，不应重置原历史及区域目标身份。
- 效果：关闭时不能分配或有效命中，开启后先看到保留目标并能正常学习。
- 观察：同份真实反馈的开关对照及重新开启后的完整消费者。
- 保持：关闭期间已学条目、目标目录和原metadata保持。
- 范围：静态禁用与恢复；切换边界的既接纳在途反馈/响应处理尚需单独协议审查。
- 证据边界：旧enable用例不证明动态切换时可以任意取消或承诺完成旧任务。

### ITTAGE-012：只有真实taken且非返回的间接分支才能学习目标

- 事件：反馈分别为inactive、not-taken、条件/直接、return、return-and-call及正常间接分支。
- 所有权：资格属于原分支的有效性、类型和返回属性，而非是否带了target字段。
- 效果：无资格事件既不从冷态分配也不修改热provider；正常间接和间接call可学习。
- 观察：逐类拒绝/正对照后查询完整目标、置信和来源。
- 保持：被拒绝身份、邻居及原metadata保持，RAS pop不能误进入间接目标学习。
- 范围：独立UT一致分支属性；不证明父模块解码或完整FTQ合法性。
- 证据边界：正对照不可省略；非return间接call与带return的组合动作须分开，不混叫call。

### ITTAGE-013：较早无资格分支不能遮挡后续合法间接目标学习

- 事件：一份反馈先出现多个有效但无间接学习资格的分支，后有唯一合法taken间接分支。
- 所有权：资格匹配属于每个原分支，不能遇到第一个valid就固定slot0来源。
- 效果：后续合法目标分配；全无资格向量保持冷态，同份合法向量仍能学习。
- 观察：比较完整向量实际接纳与实际后续完整目标，再检查无资格对照。
- 保持：先行not-taken条件分支和return末项不被当作间接学习目标。
- 范围：唯一候选的向量过滤；多合法间接分支输入仲裁不在此接口契约内。
- 证据边界：013与010共享稀疏选择语义，保留ID而不将每个resolve位置增加为功能。

### ITTAGE-014：相同低偏移的不同目标区域仍属于各自历史

- 事件：同PC在不同原历史下学习同偏移但位于当前/相邻区域的目标。
- 所有权：完整目标由原历史、区域引用和偏移共同拥有，不能只用低20位判断相等。
- 效果：不同区域目标分别完整返回，交错查询不串换区域或metadata。
- 观察：独立字节地址区域模型与重叠完整目标消费者比较。
- 保持：各历史原条目和offset保持，编码/解码不得把1MiB语义变为2MiB。
- 范围：声明的当前/前/后区域边界；不是全部高地址位或目录满的保留保证。
- 证据边界：原区域组是实际硬件证据，但017目前尚未把这类正向闭环关联到自身判定。

### ITTAGE-015：区域目录已满时复用已有区域，不误改相邻目标或其他引用

- 事件：目标区域达到声明容量后，新分支使用已存在区域但不同偏移。
- 所有权：新目标属于自己的表身份和偏移，目录引用属于已有区域而非新的任意受害者。
- 效果：无需第17个不同区域即可建立新目标，旧目标和相邻打包SRAM字段均保持。
- 观察：独立区域/offset期望，每次插入后比较所有声明居民及反向重叠消费者。
- 保持：未被替换区域、旧指针和同字邻居完整目标保持。
- 范围：16区域容量内的已有区域复用，不承诺第17个不同区域后所有旧目标无损。
- 证据边界：容量对象个数是有意义边界，不是遍历bank刷行；全部地址/所有打包lane仍不由该用例自动证明。

### ITTAGE-016：读竞争中的目标补丁保持原身份，服务与再激活不丢字段

- 事件：多个原目标身份在查询读取压力下接纳相邻反馈，之后实际服务并fresh再学习。
- 所有权：置信/目标/保护补丁属于各原历史与表项，旧metadata不自动等于最新待写值。
- 效果：pending补丁合法合并，服务前查询保留其原读取状态，服务后及clean再学习均得到规定目标。
- 观察：实际接纳/重叠时刻、独立patch可见性与全部fresh目标及邻居比较。
- 保持：未选字段、其他身份和原快照保持，useful-only补丁不能抹去完整目标写入。
- 范围：不超过四保留对象、声明两bank/两置信模式及串行对照；不承诺满行新键无损。
- 证据边界：重复旧metadata不是TAGE式最新计数累计；相邻输入数不能当成精确累计步数。

### ITTAGE-017：公开字节地址在学习与目标压缩返回中保持同一完整身份

- 事件：原PC、反馈target和provider/alternate目标metadata穿过公开地址适配并被后续查询消费。
- 所有权：每个完整目标包含架构字节地址单位、区域和偏移，省略位零不改变其逻辑身份。
- 效果：编码/解码不截断有效高位、错移区域或修改原metadata，真实目标学习后仍返回同一字节地址。
- 观察：独立地址算术、实际完整反馈及fresh完整目标消费者构成正向闭环；非法输入另作API原子拒绝检查。
- 保持：未参与目标字段、原metadata和邻居保持；非法后项不能让前项部分驱动，但该API性质不替代硬件验证。
- 范围：对齐字节地址到PrunedAddr适配及实际目标身份；保留原hardware ID，不把纯编码PASS当硬件闭环。
- 证据边界：当前017关联的是codec/整批预校验，虽构造了DUT fixture但没有目标学习正向消费者；014/015/018有相关硬件证据，后续应复用并建立关联而非复制刺激。

### ITTAGE-018：目录满的新区域替换只重新解释受害者引用，不任意污染其他目标

- 事件：目录全满后先合法触碰已有区域，再学习新的非PC区域目标。
- 所有权：区域指针引用的是可替换目录项，原offset与provider置信/保护仍各自拥有。
- 效果：独立树PLRU选出受害区域，只有引用该目录项的目标高位被重新解释，非受害引用保持。
- 观察：驱动前预测受害者，实际两次替换后重叠查询全部原身份的当前完整目标和metadata。
- 保持：未替换区域、原offset与provider身份/置信/保护保持，不从实际受害者播种期望。
- 范围：当前16区域的显式容量替换，允许受害旧引用目标改变；不承诺超容量无损或全FTQ寿命。
- 证据边界：区域引用再解码与019错误丢失新学习目标不同，不能借容量契约豁免无关重写错误。

## 先登记、尚不能继承旧PASS的义务

003的置信两端同向保持与反向恢复，不能由“值都在0到3内”证明。
008的保护维护需分别证明真实失败资格、阻挡后的进展、非零保护被清除以及
目标完整性；不能把260个发送数等同维护完成。集成074已有更强的组件维护
证据，下一阶段先复核复用范围，不为单元/集成机械复制两份大压力程序。
017必须有真实硬件正向目标闭环，API整批拒绝与地址codec继续作为环境证据
保留，但不以测试所在目录或fixture创建判断它已经验证目标硬件。
