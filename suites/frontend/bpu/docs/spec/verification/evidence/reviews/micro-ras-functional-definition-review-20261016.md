# MicroRAS：按年龄合成在途调用/返回，而不是背诵优先级mux

在新增DUT刺激前审查15项旧ID，016的组合return-and-call普通FAIL合同保留。
MicroRAS只知道主RAS当前top与两个在途窗口，不拥有无限主栈。CALL建立已知
返回地址，RETURN抵消最近已知CALL；若返回后低于已知深度，预测必须不可用。
中性操作与“没有接纳事件”不同，修正也可能是取消年轻调用的真实语义事件。

`ras/MicroRas.scala:30–145`描述在途转发与修正，`model/semantic.py`按老到年轻
做抽象push/pop归约，不复制每条优先级控制；它以公开main_top作为输入，不
证明主RAS自身退休和深栈。其API地址是50位guarded半字域，call返回按原块
起点和半字位置推导。无效预测只比较usable，不把未定义target位当作真值。

原生91行已全命中仍有016 FAIL。共享12规则reached/checked组里的advance/retire
只标识控制事件，不能单凭满组断言每一种年龄、停顿与有效call寿命均被检查。
下方合同同时说明旧程序的证据边界，不自动扩大PASS。

### URAS-001：无在途操作时，用当前主RAS地址建立已知返回来源

- 事件：复位后主RAS提供已知当前top，正常接纳一个不改变栈的早级事件。
- 所有权：返回来源属于该次公开main_top，不属于旧call残留或上一请求地址。
- 效果：空在途窗口能够提供可用且正确的当前主返回地址。
- 观察：以可区分main_top输入与独立空窗口归约比较实际usable及有效目标。
- 保持：没有call就不凭空创建在途返回地址，主RAS输入不被微RAS修改。
- 范围：独立UT已知main_top输入，不证明主RAS栈正确或redirect后的未恢复主top可信。
- 证据边界：初始化是来源接纳，不是声称主RAS端口带有不存在的全栈有效性证明。

### URAS-002：早级调用建立可用地址，返回只抵消已有的已知调用

- 事件：正常早级CALL或RETURN被接纳，主top与已有在途窗口已声明。
- 所有权：CALL地址属于原指令，RETURN作用于按年龄排列的最近已知调用。
- 效果：CALL产生正确新top；RETURN有可抵消调用时回到其前驱，深度未知则不可用。
- 观察：独立老到年轻栈归约与实际可用性和有效目标比较。
- 保持：原main_top和未被取消的老窗口保持，不用无效target原始位伪造已知前驱。
- 范围：早级普通call/return；组合动作、修正与阶段释放分别另审。
- 证据边界：只知道一个主top不能证明任意深层LIFO，不能把MicroRAS当完整主栈。

### URAS-003：中级修正替代年轻推测，并在等待推进时保留修正调用

- 事件：原待推进窗口得到真实中级call/return修正，可能暂不前进。
- 所有权：修正地址与操作属于原中级分支，不是同拍新早级请求。
- 效果：按更老窗口与修正操作重新归约，取消竞争的年轻输入；暂停时修正call不能丢地址。
- 观察：区分旧call、新call与main_top，比较修正当次及撤回/推进后的实际有效结果。
- 保持：未取消的更老操作与原修正地址保持，年轻输入不得抢占其身份。
- 范围：独立UT的中级修正/停顿；BPU父连接对修正与推进有额外约束，不自动证明集成可达。
- 证据边界：父级已约束的停顿组合不能要求集成重复造出；独立UT合法范围与父级两个零DA另分。

### URAS-004：较老修正成为当前权威来源，并取消全部年轻在途操作

- 事件：退休窗口对应的较老分支得到call/return修正。
- 所有权：修正属于该原较老分支，优先于所有仍年轻的在途操作。
- 效果：用该权威操作和当前主top确定结果，年轻call/return不再影响后续预测。
- 观察：使修正地址与年轻call可区分，比较当前结果及修正撤回后的不复活。
- 保持：未声明的深层主栈不被臆造，原主top输入及修正metadata保持。
- 范围：独立UT老级修正；不证明父模块为何产生修正或主RAS完整恢复。
- 证据边界：只看一次同拍地址不能证明年轻窗口已清空，后续消费者仍需保留。

### URAS-005：同拍竞争按重定向和修正年龄取权威来源

- 事件：年轻预测、中级修正、较老修正或全局redirect在同一消费边界竞争。
- 所有权：操作按原分支年龄排序，不能按某个地址数值碰巧相等选择来源。
- 效果：redirect先取消预测信任；否则较老修正胜过中级与年轻输入，结果属于唯一权威事件。
- 观察：预先声明不同返回地址，比较实际可用性/有效目标与独立优先年龄归约。
- 保持：被取消年轻操作不能在后续无修正时重现，不能只比较当拍输出。
- 范围：声明的同时事件及阶段年龄接口；不是任意BPU/FTQ修正合法性证明。
- 证据边界：旧专属用例主要检查三输入竞争一次，redirect及长期撤回另有006/015，不借通用满组补齐所有组合。

### URAS-006：重定向取消年轻窗口，并在主来源恢复前保持不可信

- 事件：全局redirect取消当前错误路径，随后有中性或真实call来源到达。
- 所有权：旧在途call属于被取消路径，新主top只有在恢复语义允许时才能提供预测。
- 效果：redirect当前不可用，恢复窗口不凭旧main_top伪造可信结果；合法新call可建立新已知地址。
- 观察：独立信任状态与可区分旧/新地址，比较redirect、恢复及后续消费者。
- 保持：被取消call不复活；无已知深度时不解释无效target位。
- 范围：当前协议一消费边界的主来源恢复；不同级权威修正的特殊恢复范围见015。
- 证据边界：恢复窗口长度属于driver/monitor协议，不以测试层裸等周期代替真实信任事件。

### URAS-007：调用返回地址由原指令位置计算，不串用起点或丢有效地址位

- 事件：合法不同块起点和指令位置的CALL进入早级或修正窗口。
- 所有权：返回地址属于原call指令结束位置，采用该模块公开半字地址单位。
- 效果：对齐、位置偏移与有效高位正确，不能把后续请求起点或字节/半字混用。
- 观察：独立地址算术与实际有效目标比较，原调用地址与main_top刻意不同。
- 保持：未参与老窗口与原输入保持，地址计算不改变调用数量或来源年龄。
- 范围：声明地址/位置边界及50位guarded域；不将所有高位、溢出组合视为已验证。
- 证据边界：旧代表边界不是全地址枚举证明；与主RAS和ITTAGE不同API域需各自适配，不能直接复用数值。

### URAS-008：调用转发随年龄前进并在主RAS接管后释放

- 事件：原早级call从年轻窗口前进到较老窗口，再完成其在途寿命。
- 所有权：同一调用地址随操作年龄移动，而不是复制成两次独立call。
- 效果：等待主RAS接管时持续转发原地址，释放后回到当前主top，不重复push或留下幽灵call。
- 观察：可区分call/main地址、实际推进/释放事件及随后中性查询共同比较。
- 保持：原调用和未受影响老操作保持，不用空窗口advance事件冒充有效call迁移。
- 范围：正常无修正的两窗口流水，独立main_top输入；不是主RAS提交或任意停顿证明。
- 证据边界：共享12规则组含空推进/释放，满组不单独证明此有龄调用链；原专属程序与默认参考必须同读。

### URAS-009：中性中级修正不遮蔽仍存活的较老调用转发

- 事件：较老窗口保有真实call，中级修正明确为中性操作。
- 所有权：中性取消的是年轻分支错误操作，不取消未被它支配的较老call身份。
- 效果：归约仍得到老call返回地址，而不是无条件回到main_top。
- 观察：区分老call、当前main与竞争年轻call，比较中性修正后的实际有效结果。
- 保持：老call及其地址保持，中性不能被误当作没有修正事件。
- 范围：独立UT老call加中性中级修正；与015空老窗口恢复主top的前提不同。
- 证据边界：若不区分是否有老call，两个看似相同“中性恢复”要求会互相矛盾；本合同明确前态。

### URAS-010：中级返回抵消已知老调用；缺少已知前驱时不制造有效地址

- 事件：中级RETURN修正分别遇到有、无较老pending CALL的前态。
- 所有权：返回只消费最近已知call，不拥有未知主栈第二层的地址。
- 效果：有老call时回到已知main前驱，无可抵消call时结果不可用。
- 观察：独立两个前态归约与实际可用性/有效地址对照。
- 保持：无效目标原始位不参与正确性，未取消来源及原地址保持。
- 范围：一老call的已知深度边界；不证明任意多层主RAS返回。
- 证据边界：有效/无效正反对照均需保留，不能只检查一个pop控制被置位。

### URAS-011：较年轻返回的暂存贡献到期后，不永久吞掉仍存活的老调用

- 事件：老call与年轻RETURN依次处于在途窗口，之后年轻贡献前进/消退而老call仍有效。
- 所有权：每份操作只在自己的窗口寿命内参与转发归约，不直接永久修改公开主RAS。
- 效果：RETURN有效期间抵消老call得到主top，贡献移出后结果重新由存活老call提供。
- 观察：可区分老call/main地址、实际窗口事件及随后中性消费者比较。
- 保持：未到期老call和原地址保持，年轻中性事件不得丢失更老来源。
- 范围：独立UT固定main_top的在途转发贡献，不是完整程序中已退休return重新入栈。
- 证据边界：必须按窗口寿命解释，不能把表面地址再次出现误写成真实调用复活。

### URAS-012：未被较年轻call覆盖的老返回使未知深度继续不可用，释放后可恢复

- 事件：较老窗口有RETURN，年轻输入或中级修正为中性，随后老操作释放。
- 所有权：不可用性来自老返回对已知主top的消费，不属于年轻中性操作。
- 效果：老返回仍在时不伪造有效目标，释放后可重新使用当前主top。
- 观察：中性早级/中级两类事件与实际释放后的有效恢复比较。
- 保持：年轻中性不能遮蔽老返回，未知深层目标不被当前残留地址冒充。
- 范围：声明的老RETURN与中性前态，已知主top输入；不代表主RAS栈为空或架构异常。
- 证据边界：usable=0是本模块知识边界，不可从中推断整个RAS没有存活调用。

### URAS-013：新call可在老返回之上建立已知地址，其贡献释放后仍保留老返回影响

- 事件：较老RETURN尚在时，年轻CALL进入并随后释放自身窗口。
- 所有权：新call的已知地址与老return的未知前驱是不同年龄的贡献。
- 效果：新call存在时可用其地址，移出后老return再次使结果不可用，老return释放后主top恢复。
- 观察：比较三个有区分度的窗口阶段，独立归约可用性及有效目标。
- 保持：未释放老操作保持，不能把新call离开误当作同时清除老返回。
- 范围：两窗口普通call/return的年龄合成，不证明任意深栈或组合动作。
- 证据边界：仅检查最高优先输入的当拍值无法证明两个操作的独立寿命。

### URAS-014：年轻操作与待决call/return按同一栈规则合成，不依赖特殊组合分支

- 事件：年轻RETURN或中性事件分别与待决CALL或RETURN组合。
- 所有权：所有操作按原年龄归约；中性不是无接纳，RETURN不拥有未知地址。
- 效果：已知call可被return抵消，未知深度保持不可用；随后结果遵守各窗口寿命。
- 观察：四类可区分前态与下一有效消费者比较，而不只看组合控制值。
- 保持：原main_top、未消费老来源及原地址保持，空/未知数据不当真值。
- 范围：声明的两类年轻操作与两类待决操作；不是所有修正、redirect和FTQ组合。
- 证据边界：四组合是已知深度规则的证据参数，不新增四种硬件信号功能。

### URAS-015：取消年轻调用的中性修正仍是真实事件，并按原恢复资格选择当前主来源

- 事件：空老窗口下中级中性修正或权威老级中性修正取消竞争年轻call，并可与redirect竞争。
- 所有权：修正属于原较老分支，选择当前主top而非旧top或被取消call。
- 效果：中性修正取消年轻效果；redirect优先，中级主来源等待恢复而权威老级可直接提供恢复结果。
- 观察：不同旧/新main地址、实际修正/redirect与撤回后的中性消费者比较。
- 保持：被取消call不得复活，恢复资格不足时不解释无效target。
- 范围：声明的空老窗口或权威老级修正；有存活老call的中级中性修正应遵守009，不强行清除。
- 证据边界：原neutral_override覆盖两级恢复差异，但并非所有主RAS寿命/修正调度都由此证明。

## 本阶段的边界

各点共享同一个年龄归约模型，但覆盖分组不能只按源码mux信号改名。实际
call是否存活、return是否抵消了已知call、中性是否取消了年轻错误路径、以及
释放后谁继续提供地址，才是可读义务。停止更新不等于没有在途来源，预测
无效也不等于全主栈为空。所有旧配方和016普通FAIL保留，不为独立UT与父连接
不同范围添加skip、不伪造输入、不改RTL以提高数字。
