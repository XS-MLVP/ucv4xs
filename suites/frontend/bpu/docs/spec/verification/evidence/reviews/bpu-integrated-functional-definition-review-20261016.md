# BPU集成：原窗口、合格效果与后续消费者

在269合同阶段后审查剩余64项旧集成ID。已有33项集成合同保持；九个UT的
236项合同保持。下列64项先定义，随后才允许针对缺失义务设计新刺激。343个
追踪ID、历史配方和原判定不变；“全部旧点有合同”不等于完整规格已闭合。

## 审查原则与实际边界

事件不是某根信号为1，也不是第几次循环。一次有意义的验证义务应说清：
哪个原窗口/分支有资格改变什么、何时真正完成、谁随后消费、谁必须不变。
输入接纳、状态效果和消费者是不同证据，不以接纳即学习成功或以槽位命中
即最终分支正确。多个历史/坐标只用于区分错源、别名、容量和边界错误。

`model/pipeline.py`独立拥有token、阶段推进、冲刷及路径历史；初始化状态
是声明服务输入，metadata是valid-only而非可背压队列。`main_sources.py`、
`direction_sources.py`、`ahead_sources.py`及`indirect_sources.py`逐个组成
不同已声明预测器profile，不是一份任意全预测器/全FTQ的完成模型。
主栈与MicroRAS、CommonHR与SC、输入观察切点与自主演进也不能互相冒充。
未支持profile目前显式拒绝；不能为了跑通把已学习预测器当永远miss。

### 本轮静态发现

1. `model/selection.py::final_repair`对普通Main目标沿用低20位差异判断，
   复现`Bpu.scala`当前有限比较。013/018要求的完整目标纠正不能据此背书。
   后续须区分正确语义golden与旧实现刻画；保留两项XFAIL及真实前提，不改RTL。
2. 013的旧strict XFAIL未限定异常类型，训练/来源前提的AssertionError也可能
   被记作已知缺陷；018已用专属异常限制豁免。需补足013来源/回绕前提，并把
   仅允许的纠正缺失与准备/关联失败分开，不能让准备失败悄悄变成XFAIL。
3. 007旧配对程序只有冷态fallthrough，不能单独证明训练后异质来源和纠正流
   的原元数据归属；076等较强profile应关联复用，不能把旧固定延迟当所有模式。
4. 023/024旧共享SC投票主要观察方向与使用阈值，不能代替共享signed counter
   在两端先净聚合再饱和的义务。070/071检查的是另一种自适应阈值状态；不混同。
5. 前轮MicroBTB地址API/模型单位、MainBTB旧depth归属问题尚未修复。完整
   BPU组合复用这些模型，来源独立不代表被复用算法当然正确。

旧64点中不少已有高质量自主来源/服务证据，定义不应退回只写行为标签；也
不能把局部切点或一次全绿重放夸大为全系统证明。旧已知失败和未覆盖分母保持。

### INT-001：初始化完成后从复位入口开始新的预测寿命

- 事件：复位启动并完成必要存储初始化，环境允许接收首笔预测。
- 所有权：首个有效窗口属于本次复位入口，旧流水/学习/恢复义务属于已结束寿命。
- 效果：初始化前不消费未就绪表，初始化后能推进并给出正确入口的定义预测。
- 观察：实际初始化完成、独立冷态和首笔接纳PC/完整payload联合比较，不以固定等待证明就绪。
- 保持：复位前已接纳的旧义务不污染新寿命，未定义初始化数据不当有效分支。
- 范围：当前初始化服务与无guard地址profile；非空、在途学习/恢复前态需独立证明。
- 证据边界：旧新实例用例仅检查首PC及有界可达，不独立证明非空复位取消或完整首笔payload。

### INT-002：冷表窗口沿合法顺序路径前进，不伪造taken分支

- 事件：初始化后没有已学分支，连续接纳冷态预测窗口。
- 所有权：每个顺序目标和末端位置属于其原取指起点及页内窗口边界。
- 效果：无有效分支时输出not-taken和正确fallthrough，下一窗口从合法目标继续。
- 观察：独立窗口/页边界算术与逐笔PC、目标、位置和方向比较。
- 保持：冷查询不学习记录、不凭空产生调用/返回或更新已执行历史。
- 范围：当前窗口几何与页末裁剪；guard地址和任意异常取指不在已验证profile内。
- 证据边界：旧程序只断言各笔taken为0，完整地址/位置及页边界需关联076或后续判别证据。

### INT-003：普通预测被背压时保留原窗口，元数据不受伪ready阻挡

- 事件：普通有效预测尚未被接收，prediction ready关闭；另有独立metadata呈现。
- 所有权：被持有的预测属于原窗口，metadata属于正常到达S3的较老窗口。
- 效果：无纠正/redirect替代时预测valid与完整payload稳定；metadata按valid-only规则交付。
- 观察：独立token占用及实际呈现/接纳事件比较，不把两个通道强行同拍握手。
- 保持：普通stall不重复接纳或错误更新历史；较老纠正和外部恢复仍有原优先权。
- 范围：普通背压保持；纠正/redirect可以合法替代呈现，不能用无条件稳定断言阻挡它。
- 证据边界：旧用例比较两次冷态快照，不独立证明中间每拍或纠正竞争；076补强的valid-only语义须复用。

### INT-004：原FTQ结果改变所属预测器，并由新的同源查询消费

- 事件：真实原预测的合法执行结果被接纳，后续同上下文发起新查询。
- 所有权：PC、分支位置、历史、组件metadata属于原公开来源，不由当前线上窗口替换。
- 效果：各启用且合格预测器完成对应学习，后续完整选择/纠正链消费正确新状态。
- 观察：从reset独立组成已声明Micro/Main/TAGE状态和路径历史，比较原接纳、实际效果及fresh消费者。
- 保持：Main-only反馈不改TAGE，未参与居民及所有旧来源快照保持；错误实际值不得反向播种参考。
- 范围：直接学习及已声明Main/TAGE/Micro组合；任意全预测器、调用栈及完整FTQ epoch仍未完成。
- 证据边界：旧直接target断言与后续自主组合证据范围不同，不能用五/六事件组替代全部profile完备性。

### INT-005：外部恢复以原检查点重启正确目标，取消较年轻路径

- 事件：携带真实原检查点的外部redirect被接纳。
- 所有权：恢复的历史属于原检查点，重新执行边界属于纠正指令，年轻预测不拥有继续消费资格。
- 效果：从指定目标重新查询，较年轻路径取消，原检查点历史按纠正结果更新。
- 观察：独立检查点/token/路径历史与恢复后的完整消费者比较，不仅寻找任意同PC。
- 保持：存活较老来源与学习记录保持，取消项不得产生重复metadata或提交作用。
- 范围：已发布来源的外部恢复；完整FTQ存储回绕/epoch所有权另需验证。
- 证据边界：旧测试只检查回到PC，历史与年轻取消需复用076等独立流水证据。

### INT-006：全局禁用抑制已学预测选择，而不删除学习寿命

- 事件：已有taken记录时禁用预测器，等待声明控制传播后查询，再恢复使能。
- 所有权：选择资格属于生效后的控制状态，已学记录仍属于原分支。
- 效果：禁用后按合法fallthrough前进，恢复后可重新消费保留记录。
- 观察：独立控制传播/token参考与关闭/开启的完整目标和方向正反对照。
- 保持：禁用不误清记录；关闭前已接纳的学习与关闭后的新反馈须按各组件协议区分。
- 范围：全局选择门控；各训练门控及动态在途完成不是同一事件。
- 证据边界：旧测试只证明关闭后taken为0，未单独证明恢复保留及所有在途边界。

### INT-007：最终元数据返还原早级预测及其检查点，不拼接其他窗口

- 事件：早级预测被接纳，原token推进至最终metadata呈现。
- 所有权：早级PC/目标/方向/位置/来源回显和最终检查点共同属于原token。
- 效果：metadata按协议与原预测一一关联，纠正流也不把较年轻payload接到较老来源。
- 观察：独立接纳身份、阶段推进及全部定义回显字段比较，时延由driver/monitor管理。
- 保持：旧metadata不可被后续预测覆盖，无效或被取消token不得伪造配对。
- 范围：普通推进及声明纠正profile；metadata为valid-only，不承诺任意ready背压保留。
- 证据边界：旧四笔均为冷态fallthrough，固定延迟相等不能单独证明训练后异质来源关联。

### INT-008：调用形成的返回地址优先于错误静态返回目标

- 事件：真实调用被预测执行，随后同调用寿命中的间接return被消费。
- 所有权：返回目标属于存活调用帧，而非return指令的静态BTB目标或年轻已取消调用。
- 效果：调用去往正确callee，return在最终级选择对应返回地址并纠正错误静态目标。
- 观察：独立调用位置/返回地址算术、原来源及同笔S2/S3目标链比较。
- 保持：返回不消费无关帧，目标纠正不把来源metadata换成年轻窗口。
- 范围：单调用/返回与集成选择；多层、压缩、退休信用和恢复另见033/080/081及已有合同。
- 证据边界：单对目标正确不是完整主栈或所有CALL/RETURN组合的证明。

### INT-009：预测与训练真实重叠，接纳和观测均不漏笔

- 事件：预测连续被接收期间，一份合法原来源训练也实际被接纳。
- 所有权：每笔预测和训练各有原身份，不能把提交时刻当作硬件接纳。
- 效果：声明流量下预测继续推进，训练恰好接纳一次，monitor保留全部真实事件。
- 观察：实际预测/训练接纳窗口及唯一性、完整payload比较，不能只统计启动的任务。
- 保持：训练不覆盖相邻预测来源，预测占用不使合格训练静默丢失。
- 范围：当前无冲突或可服务profile；冲突背压由030/031明确。
- 证据边界：旧测试证明16笔时间窗口与一次训练重叠，未独立证明全部下游学习效果及消费者。

### INT-010：外部恢复可替代被持有的年轻预测，不等待旧ready放行

- 事件：prediction背压持有旧窗口时，真实检查点redirect要求新目标。
- 所有权：旧窗口失去消费资格，新呈现属于恢复目标；检查点属于原存活来源。
- 效果：ready仍低时可替换呈现，重新开启后首笔接纳是恢复路径而非旧窗口。
- 观察：恢复前持有、恢复后呈现和首笔实际接纳与独立token参考比较。
- 保持：旧窗口不能随后重复出现或更新历史，较老合法学习义务不被误取消。
- 范围：外部恢复优先于普通背压；多级同时纠正的年龄优先级需各自证明。
- 证据边界：旧PC断言不完整证明历史恢复和所有年轻metadata取消，076等较强证据须关联。

### INT-011：早级未发现的真实分支由MainBTB在中级纠正

- 事件：早级预测为miss/fallthrough，原窗口MainBTB已有有效taken分支。

- 效果：S2输出正确位置/属性/完整目标并发出必要纠正，年轻路径按原年龄取消。
- 观察：独立居民和原token，比较完整S1到S2纠正及后续消费者。
- 保持：不存在差异时不多发纠正，未参与居民和存活较老窗口保持。
- 范围：早级关闭的Main正向接通场景；目标仅差高位另见012/013/018。
- 证据边界：单个S2命中不能替代完整纠正窗口中的漏发/多发及错龄检查。

### INT-012：MainBTB修正跨局部区域的完整目标，而不只修低偏移

- 事件：早级关闭，原分支目标位于相邻较高或较低区域。
- 所有权：完整目标属于原分支和合法区域进借位，不由当前PC高位拼接替代。
- 效果：Main中级纠正返回完整正确目标，两方向均可被后续取指消费。
- 观察：独立半字/字节单位与区域算术、真实原来源和实际完整纠正比较。
- 保持：原位置/属性和另一方向居民保持，不能用低位相同判目标正确。
- 范围：当前Main局部目标的相邻区域重建；不承诺任意远目标无损编码。
- 证据边界：早级关闭时成功不证明早级已有错误高位目标时仍会触发后级纠正。

### INT-013：MicroBTB局部回绕不能成为最终错误取指目标

- 事件：真实MicroBTB早级来源给出局部回绕目标，而后级保有原分支完整正确目标。
- 所有权：最终目标正确性属于原指令，不能因早级目标低位相同而丢失纠正资格。
- 效果：早级已正确或后级完整纠正后，后续取指不得沿错误高区域继续。
- 观察：分别证明早级来源/回绕和后级正确前提，关联同token完整目标与后续消费者。
- 保持：准备、来源或关联错误必须普通失败，不能被已知纠正缺陷XFAIL吸收。
- 范围：原窗口完整目标语义；当前已知高位比较缺陷不作规格豁免，也不授权RTL修改。
- 证据边界：旧strict XFAIL未限定异常类；final_repair也沿用低20位判断，均需在验证基线中修正，不能视为独立正确oracle。

### INT-014：早级旧间接目标被Main新目标纠正，来源仍是原窗口

### INT-016：禁用一个早级来源不会让另一来源的学习覆盖它

- 事件：Micro已有目标A，禁用Micro期间Main/Ahead合法学习不同目标B，再重新选择Micro。

- 范围：声明顺序切换与保留隔离；任意在途使能竞争不由此自动证明。

### INT-017：同一请求的双有效早级来源按Ahead优先选择

- 事件：同一已读取S1窗口同时有有效Micro和Ahead候选，目标可区分。
- 所有权：两份候选属于同一原请求，不能用分开启用的不同请求伪造竞争前提。
- 效果：Ahead有效候选按其方向选择优先于Micro，公开完整结果和来源回显一致。
- 观察：真实双有效前提、持有窗口下揭示Micro及恢复流水后的相邻来源比较。
- 保持：仲裁不误学习另一来源，改变控制不被当作重新接纳原S0请求。
- 范围：当前双来源仲裁和声明恢复流水；Ahead有效但全not-taken的优先语义也不能简化为只看taken。
- 证据边界：旧不同target竞争已具区分力，尚不能据此声称所有有效/方向/窗口取消组合齐全。

### INT-018：Ahead局部高位回绕须由最终完整目标纠正
