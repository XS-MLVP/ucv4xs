# 保留中的学习与已退休调用：剩余行缺口的功能定义

依据 `production-utage-source-ownership-20261016-v1` 完整失败诊断。
SC 剩336、TAGE剩120、RAS剩16个原生零DA键；分母完整保留。
这是八项既有ID的定义审查，不是新增测试、PASS或行覆盖率。

## 先确定这些缺口是不是新功能

SC 的336行是 `WriteBuffer` 两个生成版本中的复制路径，受同一层
`hit && !hit` 条件排除。TAGE 的120行是同一待写身份更新中被更高优先级
赋值排除的复制路径。RAS 的16行分别受优先级或父模块单一提交动作约束。
精确源码形状、全部原生生产者和放松约束负对照，见最新账本及
`sc/coverage/guard_audit.py`、`tage/coverage/coverage_audit.py`、
`ras/coverage/guard_audit.py`。这些是固定源码、二态条件下的有界证明，
不是整个设计的形式可达性结论，也不豁免TAGE/RAS已有普通FAIL。

因此不能新增336种SC功能、120种TAGE功能或16种返回栈操作，再要求
用例触发互相矛盾的路径。真正需要审查的是保留身份的更新、同拍独立
来源、掩码隔离、存储可见性，以及退休后不依赖推测副本的调用消费者。
以下分别定义这些已有义务，不能仅给几个case换成漂亮标题。

源码职责依据：`WriteBuffer.scala:153–248` 区分待写/已服务身份与新身份，
`WriteBuffer.scala:80–88` 按mask合并；完整identity包含set与tag，端口号不等于
保留owner。`RasStack.scala:333–372` 的提交按调用身份维护重复计数与前驱。
SC无反压的满行miss允许替换脏项；这里的保留要求限定不超出既定容量，
不偷偷把规格扩大为任意满行输入均不得丢失。

## 逐点合同

### SC-016：连续学习两个分支时，后到反馈不抹掉前一个分支的学习

- 事件：同一查询块内两个不同条件分支的合格反馈相邻到达，前一学习尚未写入存储。
- 所有权：每份方向学习属于原分支位置及历史特征选中的权重，不属于当前反馈槽号。
- 效果：两分支均能形成可消费的方向修正，后来的权重补丁不能抹去另一分支的已接纳学习。
- 观察：从冷态声明两个分支的目标方向，经真实反馈及写回后由新查询消费，并保留间隔反馈对照。
- 保持：未选分支及原反馈metadata保持；相邻读取旧存储不等于每拍都获得串行学习的速度。
- 范围：独立SC的两分支连续反馈及其存储可见性；不要求与串行相同的收敛周期，不证明超容量不丢失。
- 证据边界：旧用例主要检查最终方向与收敛；默认ScReference逐查询比较完整定义输出，但没有专属成对覆盖来分别证明全部中间保留状态和实际服务。

### SC-018：只学习被选择的分支，其他等待写回和已学方向仍属于原身份

- 事件：多个历史身份已有等待写回的学习，后续反馈只选择其中部分分支方向。
- 所有权：权重补丁属于原PC、历史特征和分支位置，bias特征与预测槽不能互相替代。
- 效果：选中分支接纳学习；同一身份的不同分支补丁合并，其他身份与未选方向不被覆盖。
- 观察：从预先声明的冷态与已学邻居开始，真实写回和再次学习后用新查询比较全部定义方向及metadata。
- 保持：未参与的已学习邻居、冷态邻居、历史身份和原始反馈快照保持。
- 范围：独立SC不超过保留容量的掩码反馈；不同物理行是隔离参数，不分别新增功能，不宣称满行miss无损。
- 证据边界：现有masked_rows与默认语义模型形成输出检查；旧context/way/bias物理交叉组不是所有掩码语义的独立成对证明。

### TAGE-023：交错更新多个原provider时，计数不串写且单独再学习不改变邻居

- 事件：不同预测身份的真实最高provider接纳交错的相反方向反馈，写回被查询竞争延后。
- 所有权：每个方向计数属于原PC、历史、分支位置及provider身份，不属于最近一次读取的数据。
- 效果：各身份分别累计到自身方向的边界；单独再次学习一个身份时只改变该身份。
- 观察：以预先声明的不同初态和方向区分身份，分别查询饱和后的provider，再单独反向学习并查询所有邻居。
- 保持：其他provider计数、tag、位置和原反馈快照保持，串行对照不能掩盖并发丢失。
- 范围：独立TAGE四个保留身份、最高provider无更长分配；未超过保留容量，不要求任意满行miss均无损。
- 证据边界：现有32份相邻反馈和串行对照检查实际消费者；四身份/四槽是容量边界配方，不等于已证明所有替换冲突与跨owner来源。

### TAGE-024：同拍两个分支的方向与保护学习彼此独立

- 事件：同份合格反馈中两个不同分支同时产生方向学习，且各自可能仍有待写版本。
- 所有权：每份学习属于其原provider、分支位置和历史；两个输入端口不是两个固定逻辑owner。
- 效果：两份学习及各自usefulness正确保留、服务和再激活，不能因另一分支更新而消失或串写。
- 观察：独立预期计数、保护、身份和实际新查询共同检查写回前后，并比较未选中的邻居。
- 保持：未选方向、其他历史及不可变原始metadata保持；不能只检查两路写使能同时出现。
- 范围：独立TAGE允许的不同分支、不同写目标；同键双写、槽碰撞与任意满行替换不能借此宣称已有明确优先级或无损保证。
- 证据边界：现有dual_rows与默认参考保留；须区分actual反馈机会与组件缓冲参考的合法输入前提，旧物理满组不能替代来源资格。

### TAGE-035：请求端口改变时，已保留身份仍由自身最新计数继续学习

- 事件：两份不同身份的同拍学习分别命中或新建保留版本，命中身份可能原来由另一请求端口写入。
- 所有权：身份由完整set/tag及原分支确定；请求端口、保留owner和物理深度不是同一个概念。
- 效果：命中从该身份最新保留计数学习，新建从原来源产生初值；另一份命中或缺失不改变其数据来源。
- 观察：故意使原快照、当前保留值和另一身份计数不同，核对实际写入、服务后的fresh消费者及全邻居。
- 保持：未参与项和原快照保持，交换两个请求方向仍各自归属正确身份。
- 范围：现有同bank共同set、不同键且独立保留槽的双写；参考模型明确拒绝同键、槽碰撞与未建模满行仲裁，不外推这些输入。
- 证据边界：advance_tage_shadow_writes本身是缓冲组件切点，不能单独证明父输入合法；case的真实捕获、默认TageReference与完整消费者检查需同时保留。

### RAS-011：调用已退休且推测副本被复用后，返回仍消费正确的存活前驱

- 事件：多个不同调用按原调用metadata退休，随后临时调用/返回复用原推测存储。
- 所有权：返回地址属于存活调用帧及其前驱，不属于仍碰巧残留的推测槽内容。
- 效果：原调用仍按LIFO被逐个消费，已完成返回只退休一次，最后恢复初始空栈。
- 观察：先证明推测队列确已复用，再由真实返回和提交消费者核对原地址及剩余调用顺序。
- 保持：临时调用/返回不改变未消费的老调用，提交metadata必须来自该调用操作前的真实快照。
- 范围：独立RAS合法有序调用/返回退休；不证明任意FTQ乱序、缺退休或无限深度。
- 证据边界：默认RasReference从语义调用组独立维护身份，现有commit_recovery保留；仅观察指针绕回或重复当前top不足以证明存活前驱。

### RAS-012：重复调用在计数上界拆组，存储复用后仍能逐次返回

- 事件：同一返回地址重复调用并有序退休，重复次数超过单个重复组计数上界。
- 所有权：每一次逻辑调用属于该地址的有序调用组；组计数不是允许丢掉调用的环形编号。
- 效果：到达上界后创建后继组而非回绕，脱离推测副本后仍准确返回每一次调用，再恢复不同地址的老前驱。
- 观察：正常与越界重复组分别经过真实队列复用，再逐次比较返回地址、剩余次数与空栈终点。
- 保持：不同地址的老前驱、未消费重复调用及原退休快照保持。
- 范围：独立RAS正常/饱和重复退休与返回；不宣称任意缺退休或全FTQ容量协议。
- 证据边界：现有repeated_commit及默认语义调用组参考；固定重复次数只是穿越边界，不代表每个计数值是一个新功能。

### RAS-013：提交后的调用组在有界存储复用中保持完整且能被后续返回消费

- 事件：不同地址及重复调用组有序退休，后来的临时调用复用推测存储，再消费原调用。
- 所有权：完整提交状态由有序调用帧、重复计数和存活前驱拥有，不由选定物理槽号定义。
- 效果：每次实际退休恰好更新其调用组，全部提交组与公开返回均符合独立调用序列。
- 观察：连续比较真实接纳、完整提交组状态和公开投影，并在复用后用返回消费全部声明调用。
- 保持：未参与组及未消费前驱保持，不能只比较当前top而遗漏更老帧。
- 范围：现有normal/saturated有界程序，完整提交组检查但非全FTQ；物理槽参数只测副本，不扩充语义分母。
- 证据边界：CommittedStack/advance完整状态参考与默认RasReference作用不同，均保留；旧索引交叉组没有独立reached/checked语义绑定。

## 本阶段不补刺激

先把以上合同登记到原ID，并保留旧配方、判定和证据限制。其他模块的缺口，
