# RAS：调用身份、推测版本、退休与恢复

在新增刺激前审查剩余12项旧ID，保留008/017普通FAIL与011–013已采用的退休合同。
17项要求按调用事件与消费者定义，不把SSP槽、重复计数值或队列指针当作功能。
空栈的物理游标与完整活跃调用语义必须分开，不能把“top保持”写成“所有状态不变”。

`ras/RasStack.scala`实现有界推测版本和提交组；`model/semantic.py`独立拥有
调用帧、重复组、真实检查点及按原操作关联的退休。其语义地址为字节，adapter
负责公开半字地址转换。普通调用/返回、pop-then-push、恢复与退休分别有义务。
`model/model.py`的提交组、`model/retirement.py`的遗漏通知程序有各自更窄前提，
不能从某个指针模型正确推导任意FTQ调度合法。

独立RAS剩16个零DA是已审查的优先级/父动作有界约束，不新增16种栈操作，
也不排除分母或豁免008/017。提交组被容量复用时，要求只保护声明的存活范围，
不是用无限Python栈要求有界硬件永不覆盖所有旧帧。

### RAS-001：复位建立已知空调用状态，不留下旧在途效果

- 事件：模块复位，既有推测/退休/恢复义务需要终止并重新开始。
- 所有权：新执行属于复位后的调用寿命，不能把复位前的旧版本当作当前有效帧。
- 效果：公开空栈、提交组及信用初态符合规定，旧在途操作不在撤销复位后自行复活。
- 观察：独立reset初态与公开结果、完整提交组比较，并需要从非空前态检验恢复。
- 保持：后续正常call/return仍可用；不要求调用者复位后继续发送的陈旧metadata具备合法寿命。
- 范围：当前有界RAS复位与在途清除；不是软件架构异常或任意FTQ旧通知处理规范。
- 证据边界：旧专属用例两次复位之间没有非空学习，仅相等不能单独证明复位有效；其他程序的非空复位证据须分别核对。

### RAS-002：正常调用建立属于该指令的返回地址

- 事件：有容量的真实推测call按公开块起点与指令位置接纳。
- 所有权：返回地址属于原call的指令结束位置，不属于下个请求的PC或当前栈顶。
- 效果：新调用成为可消费栈顶，重复地址按调用组规则处理而不改变返回地址含义。
- 观察：独立按字节/半字单位和块对齐推导地址，与实际公开top及后续return比较。
- 保持：老调用及未参与提交组保持，原输入不被适配层修改。
- 范围：普通call及合法地址/位置；组合return-and-call与容量拒绝另有合同。
- 证据边界：一次正向地址比较不证明所有高位、符号扩展或跨块边界，015另有恢复地址范围。

### RAS-003：返回按原调用的LIFO顺序消费存活前驱

- 事件：已有不同调用帧的程序执行正常return。
- 所有权：被消费的是最近存活调用，而不是物理索引最大的槽或最近写入地址。
- 效果：一次返回移除一份逻辑调用，随后暴露正确老前驱，最终回到声明的底部状态。
- 观察：预先声明不同返回地址序列，逐return比较公开top、重复信息与独立调用程序。
- 保持：未消费老调用及提交组按自身寿命保持，不重复执行同一次返回。
- 范围：声明容量内的普通推测调用链；空栈下溢、退休后回读和任意深度另审。
- 证据边界：top值重复会掩盖漏pop，需要不同地址与调用次数证据，不能只看一次相等。

### RAS-004：重复返回地址压缩不改变每次逻辑调用的数量

- 事件：多个相同返回地址的call及其后续return被正常接纳。
- 所有权：每次call仍是独立逻辑义务，重复组计数只是有界存储表示。
- 效果：重复调用正确增加组内次数，逐return恰好消耗一次，最终露出不同地址前驱。
- 观察：独立调用组模型与每次实际top/重复次数及最终消费者比较。
- 保持：老前驱、其他调用组和提交状态保持，不能因地址相同掩盖丢call或多pop。
- 范围：声明的重复推测链；上界拆组及退休持久性分别由014/012补充，不自动继承。
- 证据边界：稳定同地址top不是调用数正确的证明，重复计数和完整unwind都需保留。

### RAS-005：初始空栈返回不制造地址，但不要求物理游标完全不变

- 事件：reset后没有活跃调用的初始状态接纳一次普通return。
- 所有权：没有被声明的存活call可消费；底部内容与有界存储游标是不同状态。
- 效果：不凭空产生非零调用返回地址，公开top保持已知初始底部内容。
- 观察：独立空态期望与实际top比较；后续正常call/return能否工作需要额外消费者证据。
- 保持：已知初始化内容与提交数据不被伪造；不把SSP等合法游标移动误判为调用丢失。
- 范围：仅初始空态一次返回，不把它外推为任意历史下溢必须保留所有位。
- 证据边界：旧用例只比较top；默认语义允许底部游标变化，反复空返回或非空历史后的下溢尚无该专属用例证据。

纯语义重放可直接区分两种说法：初态top为0、group为0；一次空返回后top仍0，
group合法成为7。随后call到0x1234再return能回到原底部，调用版本计数仍记录
这份真实call。该结果不是DUT测量，但说明“整个状态不动”会误杀合法行为。

### RAS-006：版本容量保护拒绝新增推测效果，而不误当作成功执行调用

- 事件：未退休调用持续占用有界推测版本，达到保护阈值后继续提供操作。
- 所有权：存活调用及其版本信用决定保护，不由driver任务是否完成决定调用是否生效。
- 效果：容量保护抑制非法新增推测效果，已存活调用不被满队列输入覆盖。
- 观察：独立占用前态、不同调用地址及实际公开结果区分有效call与被保护输入。
- 保持：被抑制操作不修改有效top、检查点或提交组；公共输入接纳不等于承诺push已生效。
- 范围：近满保护的声明程序；保护后恢复可用性另由010，任意满队列FTQ调度不外推。
- 证据边界：旧用例用top区分第一份拒绝，不能单独证明全部metadata保留或所有恢复边界。

### RAS-007：真实检查点恢复原调用前缀并取消年轻错误路径

- 事件：正常调用程序保存真实metadata，后续redirect引用该原来源。
- 所有权：恢复身份属于原调用前缀及重复次数，不属于当前同数值指针的任意新寿命。
- 效果：恢复原top/调用状态，年轻调用不再参与后续return。
- 观察：独立保存的语义检查点与实际恢复结果及fresh返回消费者比较。
- 保持：更老存活调用和原metadata保持，不从实际DUT栈复制恢复期望。
- 范围：合法有界原来源恢复；不承诺任意过期FTQ通知或全部队列代际可区分。
- 证据边界：浅恢复不证明老前驱整链和容量释放，分别见009/010/015。

### RAS-009：恢复中间调用后，较老返回链仍按原身份消费

- 事件：多层不同调用后回滚到较老中间检查点，并连续返回。
- 所有权：检查点拥有原前缀，保留前驱不能被错误路径或当前top替代。
- 效果：年轻后缀取消，连续return依次恢复全部声明老地址和底部。
- 观察：至少三个可区分地址的独立调用序列、实际恢复与完整后续unwind联合比较。
- 保持：老前驱、重复信息及原来源快照保持，不用相同top掩盖链断裂。
- 范围：声明的嵌套有界前缀；退休后存储及近满保护各有独立要求。
- 证据边界：恢复当前top正确不等于前驱链正确，原nested消费者不可删减。

### RAS-010：保护拒绝输入后，合法老检查点释放容量并恢复正常调用

- 事件：近满保护抑制新call/return后，真实更老检查点回滚取消年轻后缀。
- 所有权：被回收信用属于已取消版本，保留老帧仍拥有自己的返回地址。
- 效果：保护期间top与恢复metadata保持，回滚释放容量，fresh call/return能再工作。
- 观察：独立老检查点、实际保护拒绝、回滚后新调用及返回消费者闭环。
- 保持：原老帧和提交组不被回收误伤，同一当前检查点不能被当作释放了年轻容量。
- 范围：guard到合法回滚恢复的有界程序；不是所有代际别名或完整FTQ寿命验证。
- 证据边界：旧006的top拒绝与浅007不能替代此恢复链，保留全部metadata检查。

### RAS-014：相邻调用/返回按年龄合成，不因无空拍丢失旁路或重复次数

- 事件：不同/相同地址的call/return以相邻实际接纳节奏执行，包含转向与重复计数边界。
- 所有权：每份操作属于原调用程序次序，不属于当前单个push/pop控制值。
- 效果：旁路和重复组演进等价于有界语义序列，每个API结果对应自己的操作。
- 观察：完整实际接纳、独立压缩调用模型及全部有序结果/提交组保持比较。
- 保持：未消费前驱与提交状态保持，重叠发送不能漏操作或重复采样。
- 范围：声明深度和重复上界内的推测序列；不包括队列满恢复、动作三或集成FTQ。
- 证据边界：27个命名场景是证据分解，不是27种物理信号功能；时间由driver/monitor封装。

### RAS-015：恢复真实检查点后重做原操作，返回地址和完整存活链仍正确

- 事件：引用推测或已退休真实检查点，取消错误路径后重做call或return。
- 所有权：redo属于恢复后的原调用前缀、重复次数及指令地址，不属于当前错误路径。
- 效果：只重做一次声明操作，同/异地址call及return均能得到正确top与后续unwind。
- 观察：独立前缀/redo地址算术、实际完整恢复输入、提交组与全部返回消费者比较。
- 保持：未消费老调用及原metadata保持，地址有效高位和符号扩展不丢失。
- 范围：声明普通call/return及0/3/7重复边界，推测/提交来源；不以此豁免008/017组合动作和陈旧来源FAIL。
- 证据边界：正负地址指的是地址符号区域而非允许负Python整数；24组场景不等于全部FTQ恢复合法性。

### RAS-016：遗漏退休通知后，信用回收与调用栈操作仍各按原语义

- 事件：有意省略部分call退休通知后，真实call/return或中性通知带声明范围的版本信息到达。
- 所有权：回收属于允许释放的版本信用；只有实际声明的call/return拥有相应提交栈操作。
- 效果：满足阈值时回收信用，真实栈动作只执行一次，中性通知不伪造调用、返回或地址。
- 观察：独立故障程序、实际回收及完整提交状态，再用真实返回消费保留调用；分别检查中性与真实动作。
- 保持：未允许释放的版本与不属本动作的老调用保持；中性通知保持整个提交组，合法return可正常消耗自己的帧。
- 范围：故意不完整通知的容错端口契约，各程序的distinct call/零重复和允许动作分别声明；不是正常FTQ调度证明。
- 证据边界：独立UT的Retirement窄模型只证明正常call/return通知，拒绝中性action；BPU中性程序需自己的完整故障参考，不能把两者当同一种空操作或互相替代。

## 先登记的证据限制

001需要非空/有在途前态后的复位，而不只是两次初始快照相等。005需区分初始
下溢、反复下溢与合法新call恢复，不要求RTL没有声明的无限栈或隐藏游标不变。
016必须分别保留故障输入资格与真实消费者，不能为了“更合法”删除遗漏通知
而把它退化成普通提交测试。以上不扩大旧PASS，也不改普通FAIL的golden。
