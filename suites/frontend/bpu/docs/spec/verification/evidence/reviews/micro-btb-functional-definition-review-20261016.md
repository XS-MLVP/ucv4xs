# MicroBTB：单分支可靠性、完整payload与地址身份

新增DUT刺激前审查16项旧ID，保留011连续not-taken错误复活的普通FAIL合同。
MicroBTB命中即给taken候选，可靠性计数同时决定条目是否存活；它不是TAGE
方向计数，也不是MicroTAGE独立于条目有效性的全局替换保护。

`ubtb/MicroBtb.scala`的条目学习先衰减错误来源，失效后才建立新payload。
`MicroBtbReplacer.scala`优先无效项再PLRU。`model/semantic.py`从reset独立维护
逻辑条目、recency、在途学习与查询，不从实际计数或受害者播种期望。
但“独立维护状态”不保证适配层地址语义正确，下述已确认问题必须修复。

## 当前地址单位问题：不是RTL错误结论

现有公开注释和模型宣称使用字节地址，driver却把request.pc/target直接写入
`*_addr`，monitor也直接读回。绑定与`dut/ubtb/UbtbDut_top.sv`均未做移位。
`PrunedAddr.scala:25–63`表明addr省略位零；编译的`MicroBtb.sv`以端口低22位
匹配tag，以查询地址高位拼接22位目标域。模型却以`pc >> 1`匹配，并把22位
target_mask当作字节域，这两种解释不能同时成立。

例如当前绑定送入0x80001000和0x80401000，编译RTL的tag同为0x1000，模型
key分别0x800与0x200800。旧alias测试使用更大间隔，恰好不能区分这一错误。
22位目标域在半字端口应对应8MiB字节区域，不是注释中的4MiB。若保留公开
字节API，需同时修正驱动、监视与模型边界；不能只改模型tag迎合原始端口。
BPU的MicroSources已显式乘二/除二，后续须一并审查复用，防止重复转换。
这是静态绑定/源码/算术证据，不是新DUT测量。本阶段只登记义务，暂不改算法。

### UBTB-001：复位后能够接纳预测与训练，不让旧学习自行复活

- 事件：MicroBTB复位完成，开始新的预测/学习执行。
- 所有权：新请求属于复位后的寿命，旧条目与在途反馈不得成为新有效来源。
- 效果：预测/训练就绪，首个真实冷查询无旧命中，后续正常taken学习可工作。
- 观察：实际就绪状态、独立冷态与新请求/学习消费者比较，不把reset中闲置输出当响应。
- 保持：未发送新请求时不强求未声明的lookup锁存器值，不能据此制造假失败。
- 范围：当前寄存式MicroBTB复位；非空及在途前态复位需独立证明。
- 证据边界：旧专属用例只检查两个ready位，单独不能证明清条目或清在途；后者须与其他冷/热程序分别审查。

### UBTB-002：无有效来源时miss，禁用时不提供有效taken候选

- 事件：原查询身份未学习或预测器使用资格关闭。
- 所有权：有效候选属于原PC的存活部分tag身份，不是任意残留payload。
- 效果：冷态或disabled不输出有效预测，不能用无效target/类型位判断命中。
- 观察：独立冷态与enable资格、实际valid及重新查询结果比较。
- 保持：单纯查询/禁用不创建条目或清除原有学习。
- 范围：冷miss与静态使用门控；训练门控和在途切换边界另由014约束。
- 证据边界：无效payload不属于本合同，地址适配问题也不能以valid低暂时忽略。

### UBTB-003：真实taken学习建立单分支完整候选

- 事件：有资格taken条件/直接/间接分支反馈命中可建立的新身份。
- 所有权：目标、位置、类型及RAS动作属于同一原分支，不能各取自不同反馈。
- 效果：建立存活可靠性初态，fresh查询给出该单分支完整taken候选。
- 观察：独立原payload、实际接纳及有效完整消费者比较。
- 保持：非受害者与原输入保持，不能只看到valid就认定目标/属性正确。
- 范围：当前one-taken配置和声明地址域；不扩为多taken预测或无限tag独立性。
- 证据边界：地址codec不一致尚未解决，现有数值payload回读不能自动证明架构字节地址正确。

### UBTB-004：冷身份的not-taken反馈不凭空建立taken预测

- 事件：无存活匹配条目的原分支接纳not-taken结果。
- 所有权：没有可奖励的taken来源，反馈不能借用上一份已失效条目资格。
- 效果：保持miss，不分配或复活taken条目；后续合法taken仍可建立新候选。
- 观察：冷态反馈前后与正向taken学习对照的fresh有效性比较。
- 保持：其他存活条目与原payload保持，不把无效原始位当作新分配证据。
- 范围：冷miss的not-taken资格；连续耗尽后的旧旁路资格属于011。
- 证据边界：静态cold拒绝不能替代已耗尽条目在紧邻反馈中不复活的并发义务。

### UBTB-005：错误payload先削弱旧候选，失效后新taken才重新建立完整身份

- 事件：同一部分tag身份持续收到与旧目标/位置/类型不符的taken反馈。
- 所有权：旧候选可靠性与后来新payload是两个有序版本，不可立即混合字段。
- 效果：旧存活候选先按错误程度衰减，耗尽后新taken重建完整payload和初始可靠性。
- 观察：首次仍见旧完整payload，之后可区分失效/重建并由fresh查询消费新版本。
- 保持：未失效前不部分覆盖旧目标或属性，其他条目与原输入保持。
- 范围：真实反馈逐次推进的payload收敛；不是命中后立即覆盖，也不自动证明相邻转发全部组合。
- 证据边界：旧标题“Existing entry update”易误导为直接写目标，实际用例允许多次反馈；需保留每阶段语义。

### UBTB-006：有界容量替换只移除合法受害者，并保留其他分支

- 事件：所有条目存活时学习新身份，或存在已失效条目可优先复用。
- 所有权：逻辑tag身份拥有payload，替换年龄由合法预测消费与训练触碰维护。
- 效果：先复用无效容量，否则按PLRU选受害者，新候选与全部幸存者正确。
- 观察：独立recency历史在驱动前选受害者，实际新分配后查询所有声明身份。
- 保持：非受害者完整payload与可靠性保持，不从实际miss反推期望受害者。
- 范围：32条目的既定容量/策略；同拍触碰仲裁与所有边界不是由填满程序自动证明。
- 证据边界：容量对象数量有意义，但每个物理slot不新增功能；独立策略模型仍依赖正确地址身份。

### UBTB-007：相邻查询的响应属于各自原请求

- 事件：多个查询连续接纳，读取与上一请求响应重叠。
- 所有权：valid及完整分支payload属于原PC/读取身份，不属于最新线上PC。
- 效果：逐笔按协议返回结果，不重排、不漏响应或重复消费同一结果。
- 观察：driver接纳与monitor观察的异步scoreboard比较完整定义输出。
- 保持：原请求不可变，查询不改变学习身份，miss不比较无效payload。
- 范围：当前一周期关联协议；不把固定周期数当作功能名称。
- 证据边界：重复同PC的旧流水测试不能单独证明不同payload归属，013提供可区分对照。

### UBTB-008：部分tag别名与目标重建遵守统一地址单位，而不截断有效位

- 事件：合法对齐地址经过公开适配，查询部分tag相同或不同的原身份及目标区域边界。
- 所有权：公开PC/目标的架构字节身份与PrunedAddr端口域须明确转换，部分tag允许的别名不等于全PC独立存储。
- 效果：按配置正确别名或拒绝，目标高区域与低偏移完整重建，字节bit1不能因误当对齐位而丢失。
- 观察：独立字节/半字算术、实际驱动域和fresh完整目标联合核对，选择能区分两种解释的前态。
- 保持：其他payload、位置和属性保持，不能用两种解释恰好相同的样例宣称地址协议正确。
- 范围：当前22位tag/22位半字目标、无carry修复配置；不要求别名PC永不命中或跨任意远区域目标无损。
- 证据边界：已确认当前driver/monitor不转换但模型按字节匹配，且目标区域单位错误；旧边界PASS没有消除此验证实现缺陷，需成套修正再复验。

### UBTB-009：not-taken反馈耗尽旧候选后保持miss，只有taken能重新建立

- 事件：存活旧候选连续收到真实not-taken结果，可靠性达到零后仍有反馈。
- 所有权：可靠性属于原候选的存活寿命，零状态不能继续借用旧hit作为可学习taken资格。
- 效果：先保留旧预测再失效，额外not-taken不重新分配，新taken可建立新payload。
- 观察：逐前态的fresh完整预测、失效后拒绝与合法重建消费者比较。
- 保持：衰减期间原payload保持，邻居及原输入不被更新污染。
- 范围：串行耗尽/重建链；011紧邻not-taken错误复活仍普通FAIL，不由本点PASS豁免。
- 证据边界：三次是当前2位初始可靠性的边界参数，不是三个不同功能点。

### UBTB-010：精确taken确认恢复可靠性并在上界保持，不回绕失效

- 事件：原候选曾被not-taken削弱，随后完整匹配的taken结果继续确认。
- 所有权：奖励属于同一目标/位置/属性的原候选，不能只因taken就奖励错误payload。
- 效果：可靠性恢复并在上界保持，后续预测仍为该完整分支。
- 观察：独立可靠性与可区分错误/精确确认，比较有效完整消费者及持续确认。
- 保持：目标、属性、位置和其他条目保持，不让正饱和回绕成无效。
- 范围：恢复和上界、串行与既有连续确认；不代表所有错误属性/地址位均已覆盖。
- 证据边界：方向稳定是外部效果，准确恢复步数需独立前态或额外反向探测，不从valid独立推断所有计数。

### UBTB-012：连续耗尽后紧邻新taken，旧失效身份不能压住新版本

- 事件：连续反馈耗尽可靠性，紧接不同完整payload的taken反馈。
- 所有权：耗尽终止旧候选寿命，下一份taken拥有新payload及规定初始可靠性。
- 效果：真实转发边界能重建新版本，之后not-taken按新初态逐步失效。
- 观察：实际连续接纳、fresh新payload与后续完整衰减链共同核对。
- 保持：邻居和原输入保持，不能从旧零可靠性继承少量生命或错误属性。
- 范围：耗尽后changed-taken重建；与011耗尽后not-taken拒绝是不同义务。
- 证据边界：正向重建PASS不能代替错误not-taken复活的负对照，两点均保留。

### UBTB-013：不同分支类型的交错查询保留原完整payload

- 事件：已学习的条件/直接/间接分支PC以不同次序连续查询。
- 所有权：target、位置、类型、RAS动作和有效性共同属于该原请求身份。
- 效果：每份响应完整匹配原分支，不借邻居的相同taken值掩盖错龄。
- 观察：在提交前声明不同payload，重叠driver/monitor按接纳完成逐笔比较。
- 保持：原请求与学习条目不被后来查询改写，反向回访仍保留旧身份。
- 范围：代表混合类型与一周期流水；不证明所有地址位或任意取消/背压协议。
- 证据边界：独立参考在这些有限地址上通过不消除008地址单位不一致，必须用区分性地址复验。

### UBTB-014：禁用阻止新学习和使用，原已学候选仍能在恢复后消费

- 事件：关闭期间尝试fastTrain/resolve及查询，随后开启并重复合法反馈。
- 所有权：enable限制新接纳/使用，不改变原已接纳学习的来源身份。
- 效果：关闭时不新分配或改payload、命中隐藏，开启后原版本保留且新学习可生效。
- 观察：相同真实反馈的开关正反对照、重新开启后的完整消费者比较。
- 保持：原条目和原metadata保持；此前已经接纳的反馈按协议完成，不混同关闭后新反馈。
- 范围：静态门控及模型声明的已接纳完成语义；实际切换边界仍需有龄反馈的专属DUT证据。
- 证据边界：旧disabled程序排定后再送反馈，不能单独证明一拍在途切换；这不同于重置取消全部义务。

### UBTB-015：替换写与查询碰撞只抑制受害者响应，不误伤幸存者

- 事件：新分支实际替换同一周期，查询分别命中被替换身份和无关存活身份。
- 所有权：旧读取身份不等于被复用槽的新payload，幸存者仍拥有合法响应。
- 效果：受害者冲突不得返回旧/新混合payload，无关查询正常命中，随后新版本可见。
- 观察：独立策略预选受害者，重放相同历史的受害者/幸存者对照及后续全居民检查。
- 保持：所有非受害者、原请求及原payload保持，不允许全局抑制查询冒充正确冲突处理。
- 范围：真实容量替换写碰撞；可靠性同拍降零与普通命中字段更新的可见性不能直接等同替换。
- 证据边界：校准来源是独立模型而非实际miss，保留这个独立性，不为每槽重复功能ID。

### UBTB-016：稀疏resolve位置选中原唯一误预测，完整属性与老化结果正确

- 事件：唯一合法误预测出现在任一允许resolve槽，之前可有正确not-taken分支。
- 所有权：被选反馈的PC、完整target、位置、类型及RAS动作属于原分支，而非slot0默认数据。
- 效果：所选taken建立正确候选，条件not-taken按原可靠性衰减，其他分支不被误选。
- 观察：完整实际反馈选择与fresh payload、精确衰减链及全部居民比较。
- 保持：无效槽、正确先行分支和邻居保持，不把每个slot当成不同学习算法。
- 范围：当前八槽且至多一个valid mispredict的独立端口契约；不是完整FTQ调度证明。
- 证据边界：驱动同时接受两份有效误预测被API拒绝，不能据此推断其硬件仲裁优先级。

### UBTB-017：真实resolve优先于同拍快速指导，无资格resolve不能抢占学习

- 事件：同拍fastTrain与resolve竞争，resolve分别有资格、无误预测、无效或未推进。
- 所有权：选择的是一份完整原分支反馈，不能PC取resolve而payload取fastTrain。
- 效果：有资格resolve获胜，否则快速指导仍可生效；禁用时两种新来源均不学习。
- 观察：同/异PC和冲突payload的实际双源接纳与后续完整消费者比较。
- 保持：未选来源的其他身份与原快照保持，无资格resolve不得污染已有候选。
- 范围：声明的双源优先与静态enable；fastTrain是上游指导，不自动等同后端执行真值。
- 证据边界：同driver tick只是并发计划，须保留实际观察两源同边界的证明；地址适配修正后两源均需复验。

## 待处理而不提前授予PASS

008的地址转换是验证实现缺陷，优先成套修复并复验所有复用UbtbReference的
独立/集成程序，保留公开字节API或明确迁移，不能静默让模型接受错误raw域。
001需要非空/在途复位证据，006需区分消费触碰与训练同拍策略，014需已接纳
反馈跨enable边界的实际消费者。先登记这些义务，定义完成后再实现最小用例。
