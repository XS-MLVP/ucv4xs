# UTAGE 请求身份与保存快照：定义后再设计场景

## 不新增功能 ID

18项旧定义正式采用后，补强既有006、008、009。定义阶段保留旧判定和证据
缺口，不用旧PASS证明异质关联或快照年龄选择。当前计划47合同、286待审查。
本场景不扩展“多错误竞争”的输入许可；FastTrain仍只作为UT公开指导反馈，
不把它当成后端提交真值，不声称全FTQ来源合法性。

006：分别让PC、历史、以及二者组合成为请求间差异，正常学习三个有不同
方向计数的身份并保留一个冷对照。交错顺序包含重复、反向和冷/热切换，
driver实际接纳彼此重叠，monitor逐份输出必须与各自请求的完整身份匹配。
请求的基础方向也变化，不能把“最新线上base”当成旧请求的来源。

008/009：正常学习三个短表身份，原计数分别为5、2、4（旧、年轻、当前读入）。
全部共享相同分支位置，避免把位置变化混入年龄义务。两种纠正各有匹配/重新
解释为不同tag两个分支，另分别有无并发学习；共8个独立场景，不枚举bank/set。

| 输入程序职责 | 在纠正时的职责 | 检查依据 |
| --- | --- | --- |
| 旧身份 X | 较老保存快照 | 预先声明计数5，实际普通响应必须先证明它 |
| 年轻身份 Y | 年轻保存快照 | 预先声明计数2，与X的方向和计数都不同 |

并发学习分支使用事先正常捕获的目标来源，仅送一次合法正确指导反馈，使
X的当前内容变为6或Y变为1。保存快照仍须返回原5/2。纠正当拍只读SDK shadow
最新入队记录，证明新值已可见；结束后fresh查询再次消费新值。否则，仅在
结束后看到新值不足以排除“学习尚未生效，所以偶然读到旧值”的假通过。

## 组件与完成语义

普通查询使用既有异步prediction scoreboard。纠正程序则是一个复合协议：
填充快照的输入不承诺在被纠正取代后仍正常返回，不能给它们挂上假的正常
completion，也不能取消已经接纳的XTransfer。

已核实xreactor的`AsyncDriver.send`会立即入队，handle在输入接纳时完成，不
需要伪造响应消费者。复合driver复用agent已有的两个单周期driver，以input-only
方式提交程序；常驻独立语义monitor/checker继续检查每一个硬件边界。上游
基础结果覆盖完整下游metadata寿命，收尾属于驱动协议，不在case里等待边沿。

新monitor用静态Bundle和`@on`采样。其输入来源复用现有语义monitor从公开
端口解析的Events（不是模型期望状态），实际输出和shadow来自只读SDK。
纠正响应按实际输入的override事件关联，不按附近相同数据或猜测等待周期选择。
纠正前连续三个实际输入必须正好是X/Y/Z，旧/年轻的普通响应必须先可区分。

reached只授予已证明真实输入、重叠或纠正来源的义务；checked还需要完整
独立比较、恢复上下文、fresh目标/邻居、来源metadata不变，以及并发分支中
纠正当拍确实已可见的新内容。无并发分支不采样“新内容已可见”的义务。

006每种差异5项义务，成对组各15bin；S2/S3分别有22bin：四种分支各五项，
其中两个并发学习分支另加当拍新内容证据。任何不符正常抛异常，不改RTL、
不豁免旧失败、不以新增组的满覆盖替代全局行覆盖或功能点通过率。
