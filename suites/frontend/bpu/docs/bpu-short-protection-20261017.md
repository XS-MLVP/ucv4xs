# 长历史不匹配时的短表保护与分配竞争

INT-066需要分别证明较短provider的保护边界，不能用长表通过替代。较早历史
不同、较近历史相同时，较长表可以不匹配，而短表仍是同一逻辑记录。该原
记录的正确纠正、错误指导、上下界保持和反向恢复，应由真实拥有的来源判断。
FastTrain的对错以独立S3指导为准，不把它当成后端提交真值。

短表错误还有一项并发义务：若共同前态允许分配更长表，原短记录更新与新
长记录分配必须分别正确。随后长provider合法获胜不能冒充原短记录的消费者，
其他年轻学习合法替换了已无保护的短记录，也不能直接归因为边界RTL错误。
这都是既有066的语义子要求，不按bank、索引或槽位创建功能点。

## 正常来源程序

已有正常学习程序自然留下NT短记录，计数1、保护1。用独立拥有的新检查点
构成不同较早方向序列，再形成相同短NT后缀。长历史尚未匹配、短历史已经
重复的窗口，真实短provider可被选择。所有恢复来自已接纳来源，不设置历史、
表项、保护或方向计数。

先用合格一致指导得到计数0、保护1，再声明原短记录。上界程序通过另一
短历史学习相反base，返回原短记录并要求奖励1→2→3→3；上界反向要求随后
真实惩罚3→2。下界程序要求惩罚1→0→0，再由正确纠正恢复0→1。每次都必须
是原短provider，较长provider不存在有效匹配，不是关闭时的裸hit位。

错误指导可能为当前较长上下文分配新T记录；下一份原短查询需要可区分的
较早历史，而不是继续查询已由该新长记录赢得的相同完整上下文。方向次序
是为区分两层预测寿命的前态，不是枚举物理坐标。

长表已有保护时，短表错误仍应削弱原短记录，但不能强制分配。长表没有
保护时，同一份原指导应同时更新短表并分配长表。独立账本在学习读取时保存
共同前态，分别比较实际允许／阻止分配、两表写命令以及下一边界的完整保护
状态。新长记录还要由新查询证明其身份和初始T强度，不能只凭保护初始化判定
分配正确。随后再次查询原短记录，证明新长消费者没有被拿来替代它。

## 用实际接纳事件关闭窗口

连续开放预测流的纯推演确实出现过合法替换：原短记录保护从1降到0后，
年轻学习把同一物理行装成另一tag。不能把该流量继续称为“原记录仍存活”。

新协议由现有独占控制driver开放预测，monitor确认预先声明的原短S1身份
实际接纳后关闭窗口；不是等固定若干周期。先排空旧S2／S3，再联合发ready
与恢复。初始读流水可以推进，但目标之后不能另有合格年轻接纳偷改原记录。
目标自己的S2／S3和注册学习仍必须排空并完成比较，不能通过丢在途工作凑前态。

XReactor后端条件判断早于`@on`捕获，因此轮询捕获结果会多开放一个接纳边界。
控制driver改为等待原生`TaskComplete`：monitor完成本边界的完整比较后，将
真正的S1接纳`XEvent`交给driver关窗。driver返回该原生事件，不用外部完成事件
的`tick=-1`冒充硬件时刻。超时仅作为失败预算，失败与超时都关闭ready，不吞
掉原比较异常。阶段细节和并行任务汇合留在driver内，case只调用语义操作。

静态Bundle和现有@on观察负责实际输入、输出、维护／分配控制及全部1024
保护单元。独立语义账本从原来源计算资格、强度与共同前态分配；不从实际
控制位决定期望。原短消费者、新长记录消费者及原metadata不可变性共同闭合。

以下保留构成程序时的纯推演问题，不再代表当前T短表状态；T长表边界仍未闭合。

属于瞬态历史、短表计数4／保护1；改为稳定T路径后，Ahead已可直接预测T，
