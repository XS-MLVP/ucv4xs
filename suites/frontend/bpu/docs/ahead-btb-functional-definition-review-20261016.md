# AheadBTB：窗口归属、分支学习和待服务版本

在新增刺激前审查50项旧ID：001–049及052。050/051/053已有合同原样保留。
53个追踪ID不是53种独立语义，更不是每个bank/set/way都定义一种功能。
历史坐标和遍历配方继续保留作物理实现证据；下文把要求写成可理解的事件，
以后按最小可区分前态选代表坐标，不默认扩展物理矩阵。

## 已核对的语义与证据边界

- `AheadBtb.scala`、`AheadBtbBank.scala`及`model/semantic.py`区分原窗口读取、
  保存的S2/S3快照、合格反馈、方向效果、记录待写和实际服务。查询不是替换
  年龄访问；训练命中访问和分配写回才是两类年龄事件，050已有冲突合同。
- 公开UT接口沿用半字PC/target，直接绑定`PrunedAddr.addr`；22位局部目标
  对应8MiB字节区域。032旧“4 MiB”把数值跨度当字节，示例算术本身是在半字
  域截断。修正文案不等于修复MicroBTB已发现的字节API适配缺陷，两者不同。
- 016/017旧程序同PC预热、保存和恢复，能够检查override重匹配，但不能区分
  恢复了正确旧快照、错误当前快照或另一个相同payload。需要S2、S3、当前
  正常候选各异的前态，还要检查redirect/已消费后的恢复资格；不新增同义ID。
- 007旧同PC静态程序让S1快速位置与S2结果相同；040异质profile程序区分S2
  的方向/强度归属，但没有按前后两笔分别关联S1 fastPositions。两个阶段
  不应被硬性要求在同周期属于同一请求。完整语义checker目前也未比较该S1字段。
- 009实际观察DUT训练输入，证明驱动有效位/payload一致及单次脉冲；不是单独
  的状态效果证明。049逐拍比较全部计数，但方向参考的初始化消费经计划校验
  的实际SRAM服务响应，是声明切点参考，不独立预测全部记录服务时序。
- 052旧有界参考按当前WriteBuffer shadow key及slot规则复现容量生命周期，
  不可拿它给053“同row/tag不同目的分支不能互相吞掉”要求作相反golden。
  053仍普通FAIL；满dirty溢出无背压，不擅自要求无限容量、无条件无损。

## 语义族与旧物理变体

| 语义族 | 旧ID | 要求与物理参数的区别 |
| --- | --- | --- |
| 窗口归属/恢复 | 006/016/017/022/023 | 请求年龄、保存源和取消资格是功能，PC/流水笔数是刺激参数 |
| 方向与位置资格 | 010/011/013/020/024/027/033/036/037/039/041/043/046/047/049 | 同分支奖励、前序惩罚、后序保持、饱和及邻居隔离是功能，坐标不是新功能 |
| 替换与新身份 | 005/014/015/019/021/026/030/034/035/038/042/044/045/048/050/051 | 合法受害者、新身份初始化、幸存者保持和并发优先级是功能 |
| 历史上下文 | 012/018/025/039/041/046 | 同PC的不同上下文须独立；具体hash值仅用于构造上下文 |
| 学习与服务 | 002/003/004/028/029/031/052/053 | 新建/修正/清理/禁用/版本服务是不同义务，不以看到write即判全部正确 |

保留原ID及配方用于回溯，不把上述重复坐标变体汇总成“独立功能种类增长”。
本轮只稳定定义；现有原生行覆盖已经满也不能替代这些尚未证明的语义义务。

### ABTB-001：复位结束后旧分支失效，新查询和学习可以重新开始

- 事件：存储初始化复位完成后接纳新的窗口查询及合法训练。
- 所有权：查询和分支记录属于新的复位寿命，旧查询、保存快照和待写不自动复活。
- 效果：就绪后冷查询无有效旧分支，metadata属于当前查询，新训练仍可建立可消费记录。
- 观察：实际初始化完成、独立冷态和后续新学习消费者联合比较，不用固定等待本身证明就绪。
- 保持：复位中未定义payload不当有效结果，复位前已接纳的旧反馈和旧待服务版本不得污染新寿命。
- 范围：当前存储初始化和冷态；非空及在途前态复位需要独立证据。
- 证据边界：旧新实例冷查询不能证明所有旧在途义务被取消，后续需非空/待写/保存恢复前态。

### ABTB-002：合法taken分支按原身份建立完整可消费记录

- 事件：合格来源显示原条件、直接或间接分支尚未命中，最终结果为taken。
- 所有权：记录属于原窗口tag、分支位置及类型/RAS动作，物理位置由原metadata上下文确定。
- 效果：在合法容量内建立记录和规定初始方向，完整位置/属性/目标在fresh查询可见。
- 观察：独立原训练payload、上下文算术和完整预测向量比较，不只检查任意valid或任意write。
- 保持：未选上下文和幸存分支保持，不能用当前查询PC代替原反馈PC。
- 范围：三类声明分支的新建；同位置改类型、陈旧来源与重复清理不是本项自动证明。
- 证据边界：三类代表新建不证明所有RAS动作、边界地址和并发版本服务。

### ABTB-003：未命中分支的not-taken结果不凭空新建记录

- 事件：真实未命中的合格原来源收到not-taken反馈，随后重新查询。
- 所有权：分配资格属于最终taken分支，未命中not-taken不拥有新记录。
- 效果：没有该分支的新分配，fresh查询仍不命中该身份。
- 观察：原冷metadata、实际接纳反馈和fresh完整结果及独立模型比较。
- 保持：已有条件分支若在原向量中命中，仍可按各自方向资格被惩罚；不把不分配误解为所有状态冻结。
- 范围：未命中not-taken的分配资格；已有命中方向效果由010/013/036验证。
- 证据边界：全冷场景不能单独证明带其他有效居民的not-taken反馈仅改合法计数。

### ABTB-004：间接目标纠正仍属于原分支，不制造第二条记录

- 事件：真实命中的间接分支携带不同局部目标的合格纠正。
- 所有权：新目标属于原tag、位置、属性及原命中way，不属于新的候选受害者。
- 效果：原记录更新为正确目标且身份唯一，fresh消费者可见完整重建目标。
- 观察：原完整来源、纠正前后记录身份与实际目标比较，不能从DUT读值反推golden。
- 保持：原位置、类型/RAS动作、方向及其他分支保持；目标修正不是新身份初始化。
- 范围：命中间接目标修正及当前局部编码；不同目标区域见032，并发目的地见053。
- 证据边界：单次纠正回读不能证明读压力下两个不同目的地都能完成服务。

### ABTB-005：冲突替换只淘汰合法受害者，独立上下文保留

- 事件：相同容量上下文的不同分支发生冲突，同时存在独立上下文的居民。
- 所有权：替换年龄和受害者属于原bank/set策略，分支身份不能由实际被淘汰者倒推。
- 效果：新记录替换独立策略选中的居民，其他幸存记录仍可完整消费。
- 观察：从已知前态推进独立年龄参考，比较受害者及新旧居民的完整查询结果。
- 保持：独立bank/set居民、幸存者目标和方向保持。
- 范围：有限冲突与容量策略；查询不被误算作训练访问，并发touch优先级由050定义。
- 证据边界：坐标枚举只增加实现副本证据，不增加替换语义种类。

### ABTB-006：重叠查询逐笔返还原请求的结果，不错龄或漏笔

- 事件：前一查询尚未完成时继续接纳后续查询。
- 所有权：结果及metadata属于原接纳请求，不属于当前线上PC或最后一次提交。
- 效果：按声明流水协议逐笔完成，次序和完成关联正确，无漏笔或重复。
- 观察：异步driver接纳事件、monitor完成事件及scoreboard完整比较，时延约束封装在agent协议。
- 保持：原请求不被后续提交覆盖，查询本身不学习或修改替换年龄。
- 范围：当前无任意背压的连续查询协议；异质payload进一步由022/023区分。
- 证据边界：固定完成时延和完成数量不是所有stall、redirect或取消组合的证明。

### ABTB-007：预测、训练来源与MicroTAGE结果一致，但快速位置归前一级

- 事件：一个已学习窗口从读取进入有效预测级，并向训练和MicroTAGE提供来源。
- 所有权：S2完整结果与S2 metadata属于同一窗口；S1 fastPositions属于前一级候选，可能是下一请求。
- 效果：同一有效S2分支的命中、位置、属性和方向一致，快速位置按自己阶段归属输出。
- 观察：独立原分支及分阶段请求关联比较，不强迫不同级同周期payload相同。
- 保持：无效分支的未定义payload不成为参考，下一查询不能覆盖上一有效来源身份。
- 范围：公共sideband一致性；异质窗口的S1/S2错龄须与040的强度profile分开证明。
- 证据边界：旧单PC稳态让两阶段恰好相同；完整checker也未比较S1 fastPositions，不能宣称其错龄已被检测。

### ABTB-008：不同冷上下文只返回各自查询身份，不伪造分支命中

- 事件：初始化后对不同PC/历史上下文进行冷查询。
- 所有权：结果metadata中的上下文属于原请求，分支有效性属于对应记录的寿命。
- 效果：各查询均无有效居民，metadata准确标识各自上下文。
- 观察：独立地址/历史映射与冷态完整valid向量比较，不只看某个物理索引变化。
- 保持：冷查询不创建记录或训练，其他冷上下文仍为空。
- 范围：冷态路由；学习后上下文隔离分别由012/018/025定义。
- 证据边界：索引算术正确不独立证明SRAM已清空全部旧居民或历史别名语义。

### ABTB-009：一次训练接纳必须携带同一笔有效完整反馈

- 事件：训练driver提交一次有效反馈，由DUT输入边界实际接纳。
- 所有权：valid、原PC、最终分支和原metadata是同一训练事务，不可跨提交拼接。
- 效果：有效输入恰好一笔，所携字段与提交意图一致，不晚一拍或重复。
- 观察：输入monitor读取实际接纳边界并与独立意图比较；agent负责边沿/写入模式而非用例。
- 保持：原metadata快照不可被后续查询或调用修改，无效间隔不被算作重复反馈。
- 范围：驱动到DUT输入的接纳切点；学习效果必须另由完整模型和fresh消费者证明。
- 证据边界：旧检查读取了主要输入字段，不等于覆盖全部训练字段或独立证明下游状态正确。

### ABTB-010：条件方向双向学习、边界保持且反向可恢复

- 事件：已命中的条件分支接纳taken/not-taken反馈，经过两方向分界和两端边界。
- 所有权：方向属于原命中条件分支和上下文，不从当前其他请求的way取值。
- 效果：计数按资格增减，两端同向保持而不回绕，反向仍能离开饱和并改变方向。
- 观察：独立逐步计数及fresh方向、强弱和完整身份比较。
- 保持：目标、位置、类型/RAS动作以及无资格邻居保持。
- 范围：2位方向计数；非条件记录的方向初态和多位置资格不能套用单分支规则。
- 证据边界：若只查最终taken不能证明精确饱和与强弱边界，049保留精确状态切点证据。

### ABTB-011：同容量的不同分支各自学习方向，不串扰同组居民

- 事件：同一上下文内多个不同身份的条件分支分别学习正反结果。
- 所有权：每个计数属于自己的记录身份，物理way只是承载位置。
- 效果：本次匹配来源的方向按规则变化，回访其他居民仍为各自预期。
- 观察：独立居民列表、来源资格及全部fresh目标/方向/位置比较。
- 保持：其他tag的计数和完整记录不因共享bank/set改变。
- 范围：容量内不同PC居民；同PC多位置的前后序资格由013/036定义。
- 证据边界：覆盖四way不是四个功能，需保留可区分的邻居前态而非全部相同方向。

### ABTB-012：同PC在不同历史上下文中可以独立保留分支预测

- 事件：同一PC在可区分历史上下文分别学习不同目标，随后交错查询。
- 所有权：上下文选择属于原查询历史，不由同PC或当前历史把不同来源合并。
- 效果：每个上下文返回自己的完整分支与目标，metadata准确标识原上下文。
- 观察：独立历史映射、提交前冻结的不同payload和fresh完整结果比较。
- 保持：改变一个上下文不破坏其他上下文居民及计数。
- 范围：当前折叠历史可区分的bank上下文，不要求哈希碰撞的任意历史永不别名。
- 证据边界：遍历四个bank是实现证据，真正区分力来自同PC的不同预期。

### ABTB-013：较晚taken惩罚前序条件，较早taken不惩罚后序分支

- 事件：同窗口有多个条件分支，最终taken位置在它们之前、相同或之后。
- 所有权：反馈资格来自原来源的命中/条件属性与指令先后，不能按way顺序判断。
- 效果：较早条件被惩罚，同位置条件被奖励，较晚条件保持；反向训练只恢复合格分支。
- 观察：独立位置顺序、逐分支计数和全部fresh消费者比较。
- 保持：非合格方向、目标和原分支身份保持，不把最终taken广播奖励所有分支。
- 范围：声明多位置来源；not-taken全条件惩罚由036补足。
- 证据边界：两分支例子不自动证明四分支混合类型和受害者重分配组合。

### ABTB-014：新分支不能继承被替换居民的强方向

- 事件：独立年龄参考选中的老居民已被训练到可区分的非初始方向，新分支替入。
- 所有权：被替换的旧方向寿命终止，初始方向属于新记录身份。
- 效果：新记录取得规定弱正方向，而非沿用旧强正/负值，后续学习正常。
- 观察：独立旧计数、受害者、实际分配及新身份方向/强弱/完整payload比较。
- 保持：幸存居民方向和目标保持，初始化不能按请求way误伤另一记录。
- 范围：新身份初始化；同拍方向冲突优先级由051定义。
- 证据边界：旧值恰为弱正时不可区分真正初始化，必须保留非初值前态。

### ABTB-015：持续冲突按独立年龄策略更新有限居民集合

- 事件：超过同一上下文容量的不同分支依次被学习，并反复触发合法替换。
- 所有权：每次受害者由此前合格训练/服务事件维护的策略状态决定。
- 效果：有限容量内保留策略指定居民，新旧命中集合与完整payload均正确。
- 观察：逐次独立年龄/居民参考和实际新旧查询比较，不从实际受害者播种下一期望。
- 保持：未选受害者和独立上下文保持，任意预测访问不偷改年龄。
- 范围：声明冲突程序；不要求无穷历史全部保留，也不把最后四项当任意程序的通用策略。
- 证据边界：特定序列恰好保留最近四项不等于精确LRU或所有并发touch已被证明。

### ABTB-016：S2纠正重新匹配原S2快照，而不是重新读取当前候选

- 事件：有效S2窗口被纠正起点，正常读取候选与被恢复窗口可以不同。
- 所有权：被重匹配的居民、计数与上下文属于原S2快照，匹配PC属于本次纠正。
- 效果：沿用原读取数据重新判定命中和目标高区域，metadata保持原上下文及合法有效性。
- 观察：原S2、S3保存和正常候选采用不同完整payload，独立快照参考比较恢复结果。
- 保持：恢复不分配新记录、不回填当前SRAM数据，不意外复活无资格窗口。
- 范围：S2快照重匹配及正常流竞争；redirect/无效前态的取消资格需独立证据。
- 证据边界：旧程序同PC训练/保存/恢复只能证明重匹配，不能区分快照年龄；需异质前态和取消对照。

### ABTB-017：S3纠正恢复原先保存的较老窗口，并遵守其有效寿命

- 事件：已保存的S3窗口发生纠正，同时当前S2及正常候选可为不同窗口。
- 所有权：恢复源属于原S3保存快照，而非当前S2；纠正PC只重新解释该源的匹配。
- 效果：选中正确旧数据/计数/上下文并重新匹配，失效或已取消的保存源不产出有效旧分支。
- 观察：S3、S2、正常候选各异的预置快照、实际恢复与后续有效性联合比较。
- 保持：恢复消费/redirect后的旧资格不复活，其他居民和未参与训练状态保持。
- 范围：S3保存/恢复及有效寿命；不能仅从S3控制位拉高推断保存源正确。
- 证据边界：旧同PC程序未区分S2与S3来源，也未独立证明redirect和已消费源的恢复资格。

### ABTB-018：索引边界上下文仍能独立学习与消费分支

- 事件：位于地址映射边界的可区分上下文分别学习不同分支并回访。
- 所有权：每笔学习和查询仍归原上下文，不因最高索引截断或进位串到邻居。
