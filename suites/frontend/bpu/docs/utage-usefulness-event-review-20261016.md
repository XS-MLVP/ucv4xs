# UTAGE 替换保护：从行缺口到独立事件检查

## 先确定要求，后实现用例

依据 `production-main-latest-age-20261016-v2` 的完整测量：UTAGE 未命中
4,066 个原生 DA 键，全部关联新项保护初始化、有效反馈增减和饱和保持。
这不是 4,066 种独立功能，也不能把 shadow 模块名当作缺少持久性的证据。
本轮复核 UTAGE-020/021 既有合同，**不新建同义 ID**，不改变旧 FAIL/XFAIL。

当前问题是证据组织：地址矩阵将很多义务串在同一用例里；分配矩阵在第 8
个后续 PC 查询已被独立方向模型检出不匹配，尚未走完剩余学习；更新矩阵
同样有提前失败。旧边界 024、分离祖先 023 证明了特定上下文的部分义务，
不能代替短/长表的独立完整事件覆盖，更不能据此宣布所有物理复制等价。

本轮先登记以下子要求，合同见计划 metadata.semantic_subrequirements；
旧物理覆盖组及其分母保留，新覆盖不得替代旧缺口或解除失败。

| 归属 | 人类可读的要求 | 有区分度的检查 |
| --- | --- | --- |
| 020 | 新学习身份建立自己的初始保护程度 | 短表为 1，长表为 2；正常误预测学习后 fresh 查询身份/方向正确，其他身份保持 |
| 021 | provider 正确纠正基础预测时得到奖励 | 从未饱和前态连续两份合格反馈，保护累计增加，不回放旧值 |
| 021 | provider 自身预测错误时失去保护 | 从非零前态连续两份真实反馈累计削弱；无关预测身份不受影响 |
| 021 | 已达最强保护，继续奖励不会绕回 | 独立准备到 3，再接受两份正向反馈，仍为 3 |
| 021 | 已无保护，继续惩罚不会下溢 | 独立准备到 0，再接受两份负向反馈，仍为 0 |
| 021 | 最强保护仍可被后续错误削弱 | 独立准备到 3，两份反向合格反馈后为 1，不能卡在饱和态 |
| 021 | 已失去保护的身份可重新获得奖励 | 独立准备到 0，重新取得真实来源后，两份有效纠正使保护恢复到 2 |
| 021 | 与基础预测一致且正确，不取得保护更新资格 | 分别从中间、上界、下界前态提交真实一致反馈；保护不动，方向学习仍须正确 |

每项分别检查短/长 provider；它们的初始等级和来源建立不同，不是物理 bank
枚举。021 每项的两份真实反馈分别以串行与相邻方式发送：两种方式都重放
原始、不可变的正常预测来源，验证当前保护状态按接纳顺序累计。相邻必须有
实际输入 monitor 收据，不能只把场景参数命名为 adjacent 就算覆盖。

## 定义完成后的场景设计

020 两个独立初始化场景；021 九项事件 × 两类 provider × 两种节拍，共 36
个独立 reset 场景。饱和、恢复和一致性前态分别准备，某个事件失败不阻断
其他事件。**没有 bank/set 循环，也没有从未命中行挑选地址。**

使用同一程序 PC 和一个正常非零最近路径历史 `0xA6B`，训练另一个独立历史
`history ^ 0x15` 作为有内容的邻居。短表消费者使用 `history ^ 0x40`：该位
在短历史范围外、长历史范围内，因而能在原历史升入长表后，继续实际消费
未被替换的短 provider。所有十九种折叠历史均从原始最近历史生成，不拼造
metadata，不分离祖先来规避本场景的身份义务。

期望模型在驱动前声明保护/方向前态、准备步骤、两份反馈的实际结果和逐份
最终状态。不能用 DUT counter/useful 来决定期望增减或选择 provider。
常规语义参考模型同时检查整条预测/学习流程；另一套公开反馈参考与只读
memory-direct monitor 比较全部 1,024 个 useful 单元和学习资格。

reached 仅在来源和前态已验证、两份实际输入完整接纳且节拍满足时采样；
checked 还要求完整状态比较、目标与已学习邻居的 fresh 消费者正确、所有
原始 metadata 未被修改。异常正常抛给 pytest，显示语义程序和 expected/actual。
旧物理矩阵继续存在且失败不会被新增的 PASS 覆盖。

这是 UTAGE-020/021 的事件证据补强，不声称整颗 BPU 的 FTQ 来源合法性，
也不把新事件组满覆盖解释为 4,066 行全部可达或全部已覆盖。
