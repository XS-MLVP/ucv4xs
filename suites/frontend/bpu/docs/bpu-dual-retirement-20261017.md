# 两条迁移分支的连续学习跨越同拍退休

两条分支的旧反馈都到达时，前一版本的实际写回不能清除任一分支刚形成的
后继学习。每个版本仍属于当前逻辑分支，而不是原预测保存的物理位置或
另一条分支的服务结果。这细化已有 INT-090，不新增槽位型功能点。

## 尚未由旧用例证明的组合

已有单分支连续反馈证明一条迁移分支的多版本学习；已有双迁移程序证明
读阻挡后合并与干净再激活。二者不能推出两条迁移分支在相邻反馈与前版
退休同时发生时，各自的后继版本都能保留。剩余集成写缓冲路径的守卫还
涉及这种并发保留前态；是否产生新行命中必须以实际测量为准。

直接插入其他逻辑分支并不自动构成有用的邻居压力：它可能淘汰当前干净
保留版本，使从最新保留计数前转的前提消失。邻居共存仍需独立建立保留
资格，不能靠读内部槽位选择期望，也不包含在本程序的通过范围内。

## 预先声明的语义程序

正常预测、反馈与分配建立和保存四份不同原预测，原 A=2、B=5；随后两条
分支都被正常替换并重新分配，当前 A=1、B=4，两个 provider 位置互换。
准备程序与既有双迁移程序相同，只增加一份真实原查询，不复制旧 receipt。

连续提交四份原反馈，A均不跳转、B均跳转，不为每份反馈等待效果完成。
每份原提案仍为 A=1、B=6，但实际完整服务必须如下：

| 旧反馈序号 | 当前 A 的服务 | 当前 B 的服务 | 必须验证的区别 |
| --- | --- | --- | --- |
| 第一份 | owner 1，计数 0 | owner 0，计数 5 | 都从当前 1/4 继续，不重放旧 1/6 |
| 第二份 | owner 1，计数 0 | owner 0，计数 6 | 前版退休同时形成后继，两个后继都保留 |
| 第三份 | owner 1，计数 0 | owner 0，计数 7 | A保持下界，B达到上界，不能串改方向 |
| 第四份 | owner 1，计数 0 | owner 0，计数 7 | 净不变饱和仍有独立服务，不能被第三份退休清除 |

实际输入和提案各自相邻。后面三份提案必须与前份两个 owner 的 SDK 完整
服务同周期，不能以最后的 0/7 推断中间版本都曾正确服务。最终两个新查询
分别验证原历史 0/7 和被置换历史双 miss，MainBTB 完整身份与全部四份原
metadata 保持。八次实际服务缺一不可，全部义务完成后才授予 checked。

## 实现和证据边界

独立 MainBTB、TAGE、历史与保留版本模型从复位推进；不由实际 proposal、
dirty 或 SRAM 状态初始化 golden。Driver 负责并行提交，已有 monitor 用
memory-direct 只读观察和 SDK 转移确认前态、同拍关系和完整服务。测试入口
不写引脚、边沿、固定等待或 asyncio task/gather。

现有服务状态快照在 RisingStable 读取子模块组合端口，表示下一次接纳前的
候选；SDK ReadyValidMonitor 则在 DriveStable 捕获，以下一上升沿标记实际
接纳。因此提案的观察时间、写缓冲接纳时间、SRAM服务时间分别记录，不能
把观察时间当成已接纳时间。一个完整时钟为两个half tick，由固定相位规则
推导而非对照实际结果拟合偏移。同拍证明比较后继写缓冲接纳与前版SDK
服务，同时核对该快照中的完整待服务payload与SDK结果。

Useful 均为 0，不关闭已知 useful 归属失败。此程序不是完整 FTQ 调度、
全部预测器组合或任意容量压力保证。旧单分支原合同和用例保留，新增义务
不继承它们的 PASS。失败直接抛出并由 pytest 判普通 FAIL，不扩大 XFAIL。

## 专项实际事件

66项新增纯模型／故障注入检查和原43项双迁移检查共109项PASS；相关兼容
322项PASS，原255项判定保持。真实DUT专项完成8项reached与checked：SDK
确认两个owner各四次完整服务，序列分别为5/6/7/7及0/0/0/0；三次后继
接纳与前版两路实际服务严格同拍。最终原历史0/7、被置换历史双miss，
四份原metadata保持。见[精简实际事件](../results/bpu-dual-retirement-evidence-20261017-v2/event-qualification.json)。

首轮因新检查器混淆观察相位与实际接纳而普通FAIL，原因及日志保留；修正
后仍严格比较完整payload、接纳顺序、八次服务、三次同拍关系及消费者，
不是允许任意时间偏移。见[首错分析](../results/bpu-dual-retirement-evidence-20261017-v1/failure-analysis.json)。

专项没有新增原生DA键，不将这次组合补证说成行覆盖率上涨，也不据此关闭
仍待归因的179个集成写缓冲键。邻居共存另有正常事件的模型可行性推演，
但不是本专项的硬件通过证据。
