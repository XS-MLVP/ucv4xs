# MicroBTB地址域：修复要求与判别设计

依据UBTB-008既有合同及[全部定义完成后的设计顺序](semantic-gap-test-design-20261016.md)，
本阶段成套修复适配/参考，不修改RTL、DUT或SDK。不是仅让golden迁就raw输入。

## 明确接口语义

公开Standalone PC/target使用**字节地址**；49位反馈`PrunedAddr.addr`存半字，
所以合法无guard字节地址为50位且bit0=0。查询口有额外guard位，本阶段不扩展
guarded语义。不能把49位半字上限错当49位字节上限；新50位范围须有独立
编码/model检查，并通过最高无guard区域的真实DUT消费者验证，而非仅凭端口宽度。

22位部分tag与22位局部目标都在半字域，字节区域跨度为2^23，即8MiB。
tag相同允许别名，局部目标无carry修复允许跨区回绕；二者不是地址单位错误
的豁免。BPU本身的API仍是半字，MicroSources已有乘二/除二复用，不能再移位一次。

## 先固定判别，再改实现

| 语义义务 | 最小可区分前态 | 成功消费者 |
| --- | --- | --- |
| 指令byte bit1不能丢 | 两个PC只差2字节，学习不同位置/属性/目标 | 两记录各自命中，邻居保持 |
| byte bit22仍区分部分tag | PC=0x80001000与0x80401000；旧raw绑定让两者同tag | 未学习邻居先miss，分别学习后共存 |
| byte target bit22是存储偏移 | 同PC目标为0x80402340 | 完整目标保留bit22，而非误截成0x80002340 |
| 前后区域局部回绕 | 0x807fffe0→0x80800100、0x80800000→0x807fff00 | 按8MiB字节区域重建0x80000100、0x80ffff00 |
| 合法无guard最高区域可表达 | PC=(1<<50)-0x1000、target=(1<<50)-2 | 编码最高49位半字字段，DUT完整返回最后一个对齐字节地址 |

前五种先通过旧实现复现：10项纯检查均FAIL，五DUT场景中4FAIL/1PASS，
合计14FAIL/1PASS；日志与原生证据保留于
[修复前诊断](../results/ubtb-address-before-fix-20261016-v1/exit.json)。
最高区域的DUT场景在这里明确后再加入；该纯模型范围判别已先复现旧49位误限。
这些是语义类别，不是遍历bank/set或枚举所有地址位。

## 实现与证据边界

驱动用公共PrunedAddr编码，输入/输出monitor解码回字节。参考独立拥有
部分tag、8MiB目标区域及可靠性状态，不读DUT表播种。纯检查用字面量半字
0x40000801/0x402011a1与字节0x80001002/0x80402342分别验证编码和解码，
不只做可能互相抵消错误的roundtrip。非法/未对齐地址拒绝于驱动之前。
并发resolve/fastTrain及连续burst先验证全部输入，再发任何一份，避免部分接纳。

BPU复用另检raw bit21应保留、raw bit22跨区和最高合法原地址，乘二/除二各
只做一次。原半字模块、GuardedPc、MainBTB等不被盲目改单位。

现有UBTB-011连续not-taken使死项复活的普通FAIL必须保留；不是本次地址修复
要豁免的行为。功能事件用独立reached/checked组记录：实际查询后才计reached，
独立完整消费者及邻居保持均成功后才计checked。默认不写逐case/逐周期JSON，
托管runner负责并行合并/清理。原生MicroBTB已有满行，本阶段不承诺行增量。
