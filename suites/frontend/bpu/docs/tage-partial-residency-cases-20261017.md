# 旧分支失去驻留后的学习与相邻身份保持

既有迁移要求验证“原身份仍驻留但 owner 已改变”。这里补 BPU-INT-098：
原身份已经被替换后，迟到结果不得命中占据原位置的另一分支；应从自己
保存的原计数重新建立完整记录，并明确终止被该记录替换的旧版本义务。
这不是给每个物理槽增加功能点，也不等同于满容量新历史替换的 INT-088。

## 从行缺口到事件要求

现有完整基线中，集成 TAGE 写缓冲仍有 149 个原生零 DA 键未完成输入、身份、
效果和消费者的因果闭合。其同目的地更新候选不能仅按代码行命名成新功能。
本批先区分“身份命中”与“旧身份已不存在时重新学习”，再分别验证替换前
后的存储可见性、实际服务和不受影响的邻居。

已有两条同拍学习争用一个保留位置的模型边界继续开放；本批不规定其优先
关系，不复制 RTL 端口赋值顺序，不跳过主模型。各请求独占一个明确目的地，
或在不同接纳周期先后替换，因而具有独立可判定的结果。

## 四个实际场景的合同

| 场景 | 有区分力的原状态与事件 | 应有结果 |
| --- | --- | --- |
| 仍驻留分支独自接收旧结果 | 原 A=2，当前迁移 A=2；原 B 已不存在。两份不同原来源只反馈 A 不跳，再以第三份旧来源重新激活已服务 A | 当前 A 累计到 0，实际服务走当前 owner；原 B 不得凭未提供的反馈复活，邻居保持 |
| 已被替换的后分支重新学习 | 真实原来源为 A=0、B=5，当前 A=0 且 B 不存在。两份 A 状态均饱和，A 不产生写；B 跳产生自己的 6 | 新 B 替换同目的地的干净 A，不从 A 的 0 得到错误的 1；无关邻居保持 |
| 新身份替换尚未服务的旧版本 | 先用另一份原 A=2 来源把当前 A=0 重新置为待写，再接纳前述 B=5 来源 | 仅完整新 B=6 实际服务；被替换 A 的待写义务明确终止，不额外服务或混合标签与计数 |
| 两个旧身份先后重新建立 | B=6 已重新建立并服务，另一份原 A=2 来源随后独自反馈 A 不跳 | A 从自己的原状态得到 1 并回原 owner，B=6 保持；原 owner 的另一历史被完整替换，两条身份均有 fresh 消费者 |

“只反馈 A”明确是公开训练接口中仅该分支槽有效的有界输入切点，不声称
整块 FTQ 已完成，也不把未提供的 B 当作 not-taken。准备中的两次 A 单独
学习同样使用真实捕获来源和独立资格，不能通过修改旧 metadata 让 A 饱和。

## 独立期望和观察

正常准备的前 23 步使 A 迁到另一 owner、B 失去驻留，另一历史保留一个
不同 tag 的邻居。后三场景再用四次真实 A 学习，分别在保存来源前和当前
版本上达到 0；不设置 DUT 或模型表项、dirty、计数或指针。

先手推 23／27 步的完整 Main 与 TAGE profile，再由自主 Micro/Main/历史/
TAGE 模型从复位执行。每个实际输入有不同原检查点；计数、tag、row 和
owner 期望由原逻辑身份推导，不从实际 proposal 或 dirty 位播种。

每阶段分别要求实际接纳、完整 proposal、被阻挡的旧存储消费者、精确 SDK
服务和新消费者。源 Main 的 B=3 同样保留：迟到 B 学习不能被当前 Main=0
错误重算成 1。所有原快照和另一历史都必须比较，完整闭合后才记 checked。

四个 DUT 场景及下述异序服务场景已合并完成 399 PASS 的影响范围验证；其中
314 个旧节点判定保持，新增 80 项纯检查、5 个真实 DUT 场景全部通过。
独立纯检查及分域检查为 116 PASS，无 DUT 原生或功能覆盖贡献。
整批已执行一次 64 进程全量诊断：19987 项，19950 PASS／34 FAIL／3 XFAIL。
其中原有 32 个普通失败保持，另两处旧纯检查的全仓总数硬编码已在随后
291 PASS 专项中修复；没有为纯检查及要求字段归一化单独再跑一次全量。
该专项不改写前一完整轮的冻结源码和失败数。
不宣称完整 FTQ 存活资格，不扩展 XFAIL 或 skip。

## 同批完成的两路异序服务

进一步从未闭合路径发现，已有目标和邻居程序主要让两路按相同逻辑顺序
服务。新的正常事件推演先只使迁移 A 待写，再接纳邻居两项和 fresh B，
形成 owner0 的“邻居 A、目标 B”和 owner1 的“目标 A、邻居 B”。两份不同
旧来源再同时学习目标 A、B，仍分别累计当前值，不能因同拍服务而错误
关联成同一个来源。

手推期望为目标 0/7、邻居 1/6，两路各服务两项，六个前后历史消费者和
五份不可变原来源均需比较。五份来源不同，未复用一份 token；两条同拍
学习落到不同目的地，不依赖尚未定义的目的地竞争优先级。不同启动历史
下的独立模型推演已证实可行。真实 driver/monitor 场景已通过：接纳时刻为
5132／5134／5136 和 5148／5150，服务时刻为 5212／5214；同一时刻两路
分别属于不同历史。两笔迟到 proposal 确实命中相反当前 owner 的不同驻留
位置，实际四个服务的完整计数顺序分别为 1／7 与 0／6；六个消费者和全部
原快照比较成功。这里细化 INT-086 的独立身份服务关联要求，不为物理 rank
新增功能点。见[五场景专项证据](../results/residency-batch-compatible-20261017-v1/README.md)。

## 本批完整测量与版本边界

33814/46541，其他九 DUT 命中集合保持，十 DUT 无旧命中丢失；总零键
17295，集成写缓冲开放键 144，49 职责组继续保留。415 组／377 满，新增
