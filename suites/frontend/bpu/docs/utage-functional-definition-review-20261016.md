## 先分清反馈是谁给的

`Bpu.scala:169–174` 将 `s3_prediction` 经 `BranchInfo.fromPrediction` 转成
FastTrain，携带同一 S3 来源的 AheadBTB/MicroTAGE metadata。`Bundles.scala:304`
也明确称其用途是“用 S3 预测训练 S1 预测器”。这不是后端已提交执行真值。
下面独立 UT 的“实际方向/到达”指该公开反馈携带的教导结果；若声称集成来源
合法，必须另外证明对应 S3 预测的独立来源、年龄与消费者，不能仅有可编码输入。

`BpuTrain.mispredictBranch` 的 FTQ at-most-one-hot 注释约束另一条 resolve 总线，
不能搬来证明 FastTrain 只有一个相对早级预测的错误。MicroTAGE 内部的单错误
假设目前只有局部注释；它是否由上游选路保证，仍需完整来源见证或约束证明。

## 冷态与方向学习

### UTAGE-001：尚未学习的分支不会凭空产生方向纠正

- 事件：reset 后正常接纳一个具有合法基础分支位置的冷查询。
- 所有权：该请求的 PC、历史及基础分支位置，不是当前线上最后一个查询。
- 效果：没有已学习 provider，不向基础预测提供有效方向纠正；仍保留后续
  学习所需的原始请求身份。
- 观察：实际 miss 与来源 metadata；独立模型核对输入推导的查询上下文。
- 保持：冷查询不分配、不学习其他分支。
- 证据：`test_cold_and_allocation.py::test_cold_miss_contains_allocation_metadata`，
  加常驻 `UtageSemanticChecker`。无专属 reached/checked；零值预测不是完整
  metadata 编码空间的证明。

### UTAGE-002：真实误预测学习后，原分支可以消费自己的新预测项

- 事件：合法冷来源反馈与基础预测相反的真实条件方向。
- 所有权：原 PC/历史/位置指明的逻辑分支。
- 效果：在合格预测表建立新身份及规定的弱方向初态。
- 观察：fresh 查询命中原分支、返回正确方向和 provider，而不只观察分配使能。
- 保持：其他身份不被无关学习修改。
- 证据：同文件 `test_first_training_allocates_a_hit`、`checker/assertions.py::allocate`，
  常驻独立模型；新保护初始化020可补充保护证据，不能把两项算成同一检查。

### UTAGE-003：连续真实跳转增强方向置信度，到上界后不绕回

- 事件：已学习 provider 接纳实际 taken 的合格反馈。
- 所有权：原始来源选定的 provider 身份，不能从当前观测结果改选 golden。
- 效果：方向计数按反馈顺序增加，上界继续 taken 保持；预测与计数一致。
- 观察：更新过程及 fresh 消费者的完整计数/方向，而非只检查最后一次 taken。
- 保持：其他分支、位置和历史身份保持。
- 证据：`test_counters.py::test_taken_counter_saturates_without_wrap` 及常驻模型。
  自身用例主要检查一个短 provider；全表/邻居义务不能只靠该尾部饱和值证明。

### UTAGE-004：连续真实不跳转削弱方向置信度，到下界后不下溢

- 事件：真实 not-taken 反馈纠正原来源的方向预测。
- 所有权：各反馈携带的原 provider；若错误触发升入长表，要区分两表身份。
- 效果：已选来源的方向计数递减并在零保持，不因下溢变成强 taken。
- 观察：fresh provider、完整计数及方向，常驻模型独立检查升表和更新。
- 保持：没有被该反馈选中的身份保持。
- 证据：同文件 `test_not_taken_counter_saturates_without_wrap`。从正向短 provider
  开始的错误会分配长 provider；不能把最终长表零值说成“短表也已验证到零”。

### UTAGE-005：没有有效纠正时，后续学习仍使用原基础方向

- 事件：基础方向分别 taken/not-taken，但 MicroTAGE 没有匹配的 provider。
- 所有权：每份来源自己的基础方向和分支位置。
- 效果：不产生有效纠正，同时保留正确 base 来源以判断之后是否需要学习。
- 观察：hit 资格与 base metadata，不把 miss 时无效的原始 direction payload
  解释为一个真实方向预测。
- 保持：仅查询不改变学习状态。
- 证据：`test_base_fallback.py` 和模型对 miss 未定义 payload 的负对照。旧用例
  还断言 miss 原始 taken 为零；这是更强的实现假设，不应成为核心功能要求。

## 并行来源与纠正来源

### UTAGE-006：流水线重叠也不能把另一请求的预测交给当前请求

- 事件：不同 PC/历史/基础方向的请求在前一请求尚未完成时继续接纳。
- 所有权：每个实际接纳事件建立独立、不可变的查询身份。
- 效果：结果和训练来源一一对应，不能丢、重、错序或串到最新线上请求。
- 观察：driver 接纳与 monitor 返回对齐，再比较可区分的完整预测和来源。
- 保持：后来的请求不修改前一请求的来源快照。
- 证据缺口：`scoreboard/test_pipeline_contract.py` 当前四个请求完全相同，主要
  证明节拍和完成数。010/014/018确有异质 DUT 查询检查，**不能说仓库没有**；
  但006的专属关联证据仍需加强或明确共享归属，不能以相同数据的四次成功替代。

### UTAGE-008：中级纠正使用对应的已保存预测，而不是另一个年龄的快照

- 事件：请求发生中级预测纠正，指定重新解释的目标 PC/历史。
- 所有权：该纠正对应的仍存活年轻预测快照，而不是最新 SRAM 内容。
- 效果：复用指定快照的数据并按恢复上下文重新判断身份匹配。
- 观察：年轻/较老快照应有不同方向或计数；同上下文消费与不同 tag 的拒绝
  都要比较，不能只看 override 信号曾有效。
- 保持：纠正查询不产生学习；无关表项保持。
- 证据缺口：`test_override.py::_check_override` 证明热查询与改 PC 拒绝；已有
  S2/S3 数据可能相同，不能充分区分选错年龄，也未独立证明不会重读最新表项。

### UTAGE-009：晚级纠正使用原较老预测快照，不被年轻预测覆盖

- 事件：晚级纠正与新的预测流水同时存在。
- 所有权：较老来源持有自己的数据、位置和历史快照。
- 效果：从对应较老来源恢复，不错误借用年轻快照；恢复 tag 不同应拒绝匹配。
- 观察：让两种来源有可区分的结果，比较真实纠正结果及原快照保持。
- 保持：年轻来源不能改写较老保存数据，查询不学习。
- 证据缺口：与008共享 helper；分别切换 stage 并不等于已证明两种来源年龄。
  `MicroTage.scala:141` 及语义模型明确区分来源，下一场景需具备有区分度前态。

## 上下文、资格与保护老化

### UTAGE-010：相同分支的不同路径历史保有各自的学习结果

- 事件：同 PC/位置在不同有效历史下分别学习，之后只训练其中一侧。
- 所有权：逻辑历史参与预测身份，不能仅以 PC 相等合并。
- 效果：被训练上下文按真实结果更新，另一上下文仍可消费自身学习。
- 观察：不同方向的 fresh 查询和交错流水查询，核对完整身份与返回。
- 保持：未训练上下文和原始快照保持。
- 证据：`test_history.py` 已有两上下文及异质重叠返回；无专属成对事件覆盖。
  不外推所有哈希碰撞（019）或短/长共享结构（018）。

### UTAGE-011：长期无法为新错误分配时释放保护，让新分支重新获得学习机会

- 事件：合格错误反复遇到无可分配预测项，而非简单经过固定周期数。
- 所有权：真实无法分配事件驱动全局老化，原驻留分支仍有自己的身份。
- 效果：保护老化后允许先前受阻的新身份学习，仍有资格的原长 provider 保留。
- 观察：老化前受阻、老化后学习成功，以及原分支的 fresh 预测。
- 保持：老化不清除方向、tag或位置，不将成功分配算成失败。
- 证据：`test_low_tick_reset.py`、常驻模型及 `low_tick_aging` 旧组。固定130次
  循环是场景配方，不是“等待130周期”的功能要求，也不独立证明所有阈值边界。

### UTAGE-012：关闭预测器阻止学习，重新开启仍保有原先的学习

- 事件：有效反馈经过延后处理时关闭模块；随后重新开启并查询不同上下文。
- 所有权：关闭期间的反馈不取得学习资格；原有身份仍属于模块。
- 效果：关闭不分配，预测状态按规定保持；开启后能学习且原有内容没有丢失。
- 观察：关闭反馈后的 cold 查询、重开后学习、关闭查询保持及重开后隔离。
- 保持：不能把禁用视为表项 reset，未涉及历史仍冷。
- 证据：`test_enable.py` 的四阶段实际检查及旧 `utage.enable` 组；不是独立
  reached/checked，也不证明所有使能切换与在途反馈组合。

### UTAGE-013：较晚指导预测到达，意味着更早条件分支应当落空

- 事件：反馈指导结果选择较晚直接/间接跳转，而早级来源还包含更早条件分支。
- 所有权：条件纠正属于更早条件位置，不属于较晚非条件分支。
- 效果：更早 taken 基础预测应学习 not-taken 纠正；原本 not-taken 则无需分配。
  同位置已解析为非条件跳转时，不能凭旧条件来源产生新的方向学习。
- 观察：公开反馈后的更早位置查询和无学习对照，核对类型/位置资格。
- 保持：未执行或无资格位置不被错误分配；其他上下文保持。
- 证据：`test_later_branch.py` 的六格实际检查，旧 `utage.later_branch` 组；
  不代替025对已有 warm 条件项的非条件反馈不变性。

### UTAGE-014：同一取指块的较晚条件分支仍按自己的位置得到纠正

- 事件：多个有效基础条件分支包含空洞，较早分支正确落空、较晚分支错误。
- 所有权：有效性和位置属于每条基础分支，而不是数组槽编号本身。
- 效果：只为应纠正的较晚条件分支学习，较早正确分支不被附带修改。
- 观察：各有效位置的结果与 metadata，另交错不同布局/历史核对返回归属。
- 保持：空洞不取得学习资格，未选位置保持冷态。
- 证据：`test_ahead_btb_vector.py`。槽1/2/3是位置参数，不是三种独立功能；
  该场景不证明多处错误同时竞争分配时的规则，见下方输入契约待核实项。

### UTAGE-017：全局保护老化遵守各表算法，而不损坏已学习方向

后续补强：短/长表的分配、奖励、惩罚分别与维护真正同拍，六项独立UT均通过。
完整共同前后态、真实唯一来源和fresh方向消费者见
[实施资格](../results/production-utage-aging-learning-20261017-v2/qualification.json)。
这是既有要求的证据增强，不是新增六个功能，也不关闭集成INT-051的来源限制。

- 事件：真实无法分配累积到老化条件，并重复触发第二轮。
- 所有权：每个驻留身份保有方向；全局操作改变的是保护程度。
- 效果：短表保护递减、长表折半，零保持；不同前态在下一分配竞争中体现差异。
- 观察：从1/2/3等可区分前态，连续两次老化后用真实新分支学习探测，再读原来源。
- 保持：老化自身不覆盖tag、位置或方向；正常合法分配造成的替换需另行建模。
- 证据：`case/aging_scenario.py`、实际检查和 `two_round_useful_aging` 旧组。
  多 bank 配方不是新增事件；持续失败资格和零边界仍应有专属成对采样。

### UTAGE-018：相同短历史可以共享基础纠正，但不同长历史的学习不能合并

- 事件：两个历史在短窗口相同、长窗口不同，各自建立不同的长 provider。
- 所有权：短表的共同身份与长表的独立身份分开。
- 效果：训练一侧长 provider 不改变另一侧，第三个尚无长 provider 的历史
  仍消费共同短 provider；共享短表只按实际共同反馈更新。
- 观察：正反向交错查询、两侧饱和学习及第三上下文回退，逐阶段比较完整结果。
- 保持：另一长历史、共同短项和未涉及邻居保留。
- 证据：`case/long_history_scenario.py`；物理 bank/older-bit 矩阵是参数，
  `short_alias_long_history` 旧组不是已分离的 reached/checked。

### UTAGE-019：历史哈希冲突不混淆身份，旧真实来源不能借用新身份的方向计数

- 事件：不同长历史 tag 竞争同一索引；保护释放后新身份进入，随后旧来源反馈到达。
- 所有权：逻辑 tag/位置以及原始预测来源，不是当前占用同一行的另一身份。
- 效果：保护未释放时禁止替换；释放后新身份正常学习、旧身份正确回退。
  本 UT 接受旧来源重新学习时，按该来源恢复计数，而不是借用当前异 tag 的值。
- 观察：两份可区分的捕获计数、逐阶段 fresh A/B/邻居查询，以及交错返回。
- 保持：独立邻居和原始捕获 metadata 保持；不能把允许重建旧身份误写成忽略所有迟到反馈。
- 证据：`case/collision_scenario.py` 与 `history_hash_collision` 旧组。
  独立 UT 的来源许可不证明任意集成 FTQ 的迟到反馈仍合法。

## 保留版本与持久性边界

### UTAGE-015：缓冲中的相邻学习按序累计，版本复用不返回旧方向

- 事件：同身份重复反馈与多个独立身份反馈交错，最近版本存储发生循环复用。
- 所有权：逻辑行的最新学习版本，不是可复用的物理 shadow 槽。
- 效果：同身份累计，异身份隔离，尚可旁路的消费者得到最新结果。
- 观察：串行/相邻实际接纳、完整计数和多身份交错读回；不能只检查指针回绕。
- 保持：未被合法替换的身份和来源快照保持。
- 证据：`case/shadow_ring_scenario.py` 的三阶段比较；不代替016脱离全部旁路
  后的SRAM持久性。`shadow_ring`组仍混有物理维度，不能据满组宣称全版本协议。

### UTAGE-022：局部版本复用不损坏仍应保留的较老预测版本

- 事件：仅替换部分最近版本，其他仍有效的旧身份随后被查询。
- 所有权：未淘汰身份拥有自己的完整数据，而不是从新槽位复制。
- 效果：消费者仍得到旧身份的正确 provider、方向和计数。
- 观察：独立部分复用模型比较完整保留状态，实际查询全部未淘汰邻居。
- 保持：其他保留身份、原始上下文和位置不串写。
- 证据：`case/partial_wrap_scenario.py` 与 `UtagePartialWrapChecker`；旧
  `partial_shadow_wrap` 组未分离 reached/checked。部分复用正确不证明全淘汰持久性。
