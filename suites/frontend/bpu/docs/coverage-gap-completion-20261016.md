# 行缺口对应的功能定义补全

## 范围和定义阶段结论

本次先补定义，再设计/实现测试。范围是
`production-feature-domains-20261016-v2` 的 17,377 个未命中原生 DA 键，以及
上一轮 49 组源码职责关联；不是宣称仅凭零计数能推导整颗 BPU 的完整规格。
旧 341 个 ID 不删除、不重复登记，新增两项语义要求，计划成为 343 项：
333 个硬件要求、10 个环境契约。未执行的新要求必须是 NOT_RUN，不能继承旧 PASS。

### 已确认需要新增

| 新功能点 | 真实事件和效果 | 为什么不是已有点改名 |
| --- | --- | --- |
| BPU-MBTB-030 | 合格访问反馈与下一缺失分支分配相邻到达，下一请求必须使用最新替换年龄 | MBTB-024 已有共享年龄、隔离及资格，但原场景逐次等待训练完成，没有要求实际相邻 T1/T0 的最新年龄选择 |
| BPU-INT-097 | 集成 BPU 使用正常发布的两个原始来源接纳上述相邻反馈，真实新分配与幸存分支消费结果正确 | INT-055 是 AheadBTB，不能代替 MainBTB；INT-027 检查相邻反馈的 PC 隔离，未声明这一有区分度的 victim 义务 |

完整合同在 `verification_plan.json`：事件、所有权、效果、观察、不变性、范围均
先于新场景实现登记。单元级和集成级不是按 bank/set 复制；它们验证的输入来源
及系统消费边界不同。

| MainBTB 完整待写版本与清理操作 | INT-093/095；MBTB-025/026/028/029 | 已有保留 owner、完整修正和目的地清理要求。跨 owner/双入口的 116 行仍须因果证据，不重复新增相同语义 |

| 替换策略比较镜像与其他物理副本 | replacement.touch 及对应原 ID | 保留原生分母；辅助实现与物理覆盖不能代替独立语义要求 |

以上处置补齐的是本批缺口的需求登记，不关闭失败、未决根因或 304 个旧点的
逐项语义审查。不能将“已经找到要求”写成“已经验证通过”。

## 定义完成后才进入的测试设计

两项新增要求共享同一逻辑程序和独立 LRU。先用正常反馈在目标行、共享策略
索引但不同 SRAM 行的别名、独立策略索引中各建立两个可区分身份；从独立
模型计算旧受害者，选中恰好能改变该受害者的访问，事先保存另一分配的真实
原始来源。测试不能从观测到的 way 或替换状态选择 golden。

| 场景 | 触发与预期 | 必须有的区分性 |
| --- | --- | --- |
| same-taken | 原目标行 taken 命中反馈紧接新分支分配 | 新 victim 与旧 victim 必须不同，才能检出漏掉最新年龄的错误 |
| alias-taken | 共享策略索引的另一 SRAM 行产生 taken touch，紧接目标行分配 | 必须共享年龄，但不能改写别名的分支内容 |
| independent-taken | 独立索引产生 taken touch，紧接目标行分配 | 目标必须仍按旧年龄分配，检出错误跨索引转发 |
| same-not-taken | 同目标行不跳转反馈紧接分配 | 不更新替换年龄，但合法方向学习仍须正确 |
| alias-not-taken | 共享索引别名的不跳转反馈紧接分配 | 共享地址不自动授予 touch 资格 |
| independent-not-taken | 独立索引的不跳转反馈紧接分配 | 不能把无资格事件当作有效转发证据 |
| lookup-only | 仅查询后正常分配 | 查询本身不改变 MainBTB 的替换年龄，与已有资格要求相互核对 |

每个场景单独 reset，失败不会阻断其他场景。不是物理索引枚举，两个作用域
共 14 个 pytest 参数节点。选择一组代表地址即可，不要求全 bank/set。

### 检查链和覆盖采样

1. 原始来源：单元级正常查询 metadata；集成级由自主 Micro/Main/历史模型关联
   真正发布过的 token。只驱动输入不算 reached。
2. 实际接受：driver 发送所有反馈后统一等待；monitor 证实相邻接纳，测试函数
   不暴露边沿、周期等待、asyncio task/gather 或引脚写入。
3. 独立期望：预先声明完整新分支、最新年龄与应淘汰的身份；错误旧 victim
   是负对照，不读取 DUT 状态修正模型。
4. 消费者：等待实际学习完成，再查询新分支、受害者、所有幸存分支及共享/
   独立邻居。原始 metadata 必须保持不变；未涉及的方向保持，合法方向变化
   仍由现有语义模型比较。
5. reached 仅在真实接受与场景前提成立后采样；checked 仅在全部消费者和
   不变性比较通过后采样。任何失败普通抛出，由 pytest 判 FAIL。

源码关联的 52/21 行主要是物理状态副本，本测试不保证全部命中，更不因低
行增量就增加坐标枚举。新增行应以相同构建和原生分母逐键比较；功能关闭以
实际事件和独立比较为准。

## 已落地的实现与专项证据

定义阶段证据保存在
[定义审查](../results/semantic-gap-completion-20261016-v1/definitions/audit.json)。
其中新增两点明确为 NOT_RUN；此后的专项资格核对两份合同没有因观测到 RTL
结果而改变。原有 341 点的定义身份、普通 FAIL 和严格 XFAIL 不被覆盖。

| 角色 | 实现及职责 |
| --- | --- |
| 逻辑程序与独立模型 | [replacement_overlap.py](../bpuverify/mbtb/model/replacement_overlap.py) 在驱动前声明驻留分支、访问资格、原/新受害者和完整最终状态；复用独立替换状态模型，不读取实际 metadata 来选择 golden |
| 共用比较 | [ReplacementChecks](../bpuverify/mbtb/checker/replacement_overlap.py) 经 xreactor Scoreboard 检查实际输入节拍、全部驻留记录、受害者和原始快照不变性；异常保留 expected/actual 和逻辑程序状态 |
| UT 场景 | [case](../bpuverify/mbtb/case/replacement_overlap.py) 使用正常 reset、查询和原始 metadata，通过既有 agent/driver 提交相邻反馈 |
| BPU 来源与发送 | [env](../bpuverify/bpu/env/main_replacement.py) 复用自主来源与历史检查，两个独立发布的预测寿命各自拥有原始反馈；driver 接受与独立输入 monitor 收据一致 |
| BPU 实际消费者 | [Bundle](../bpuverify/bpu/bundle/main_replacement.py) 只读 memory-direct SDK 端口，[monitor](../bpuverify/bpu/monitor/main_replacement.py) 使用 `@on` 按真实来源寿命关联响应，目标来自实际 MainBTB 输出而非模型结果 |
| 覆盖 | [ReplacementCoverage](../bpuverify/mbtb/coverage/replacement_overlap.py) 每作用域分别采样 reached/checked，每组 7 场景 × 5 义务 = 35 bin；没有 bank/set 维度 |
| pytest 入口 | [MBTB](../tests/mbtb/testcase/test_replacement_overlap.py)、[BPU](../tests/bpu/testcase/test_main_replacement.py) 共 14 节点，仅选择语义参数并调用封装 |

另有 18 项纯模型/检查负对照：手推期望受害者、漏掉最新年龄、错误跨索引转发、
无资格 touch、插入气泡、错误顺序、模型状态隔离等。错误完整结果与正确结果的
条目数相同，不能只靠数量比较侥幸检出。它们不是 18 个硬件功能点。

最终冻结版本的
[128 项专项回归资格](../results/main-latest-age-qualified-20261016-v1/qualification.json)
已完成：**128 PASS**，4 进程，含新增 14 项 DUT 场景、旧替换/学习/重写兼容
场景及框架/模型检查。新增 MBTB-030、INT-097 各 7 项全通过，四个新增覆盖组
均为 100%。owner 62.94 秒，最终产物约 94 MiB，worker 输入已回收。

与同构建完整旧基线逐键比较，该专项只新增 MBTB 原生 DA 两行：
[ReplacerState.sv:270](../rtl/mbtb/ReplacerState.sv:270) 与
[ReplacerState.sv:274](../rtl/mbtb/ReplacerState.sv:274)，分别是物理状态副本
8、10 的赋值；BPU 无新增 DA。该增量是专项集合的测量，不能当作单场景归因，
也不能与旧覆盖取并集后冒充新全量。新功能的价值在于能独立辨别错误受害者，
不是把两个物理赋值解释成两个新功能。

专项通过不等于全量验收。旧 25 项普通 FAIL 和 3 项严格 XFAIL 没有被豁免；
本批 49 组缺口的要求处置已登记，仍有 304 个旧硬件点待逐项语义审查，以及
保留分母的物理/守卫残差和未决因果证据。
