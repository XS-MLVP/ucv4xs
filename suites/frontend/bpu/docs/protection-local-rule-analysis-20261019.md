# 4022个保护缺失行：局部规则与原经验归属分开验证

本轮没有增加硬件用例或命中行，而是收紧最大开放项的归因：UTAGE的1829行和BPU的2193行都属于短历史经验的替换保护。它们不是4022种独立功能，也不应继续笼统称为“方向内容写回缺失”。

先定义[局部语义契约](protection-local-rule-contract.json)，再实现[严格源码检查](../tools/protection_rule_review.py)。没有修改功能编号、旧合同、独立参考模型、RTL、DUT或SDK。

## 检查了什么

两份归因SF文件字节相同，都是512个两位保护单元的同一份短经验规则。完整纳入2560条活动时钟赋值，以及当前值读取的两级选择器、每个写入地址译码、复位和老化的控制层级。未认识的源码形态拒绝出证，不按相似文本默认通过。

具体位置：

- `rtl/utage/BypassShadowBuffer.sv:1697`：保护复位为0。
- `rtl/utage/BypassShadowBuffer.sv:2396`：老化分支优先于普通更新。
- `rtl/utage/BypassShadowBuffer.sv:3688`：从当前完整保护数组取得训练地址的值。
- `rtl/utage/BypassShadowBuffer.sv:3690`：上、下饱和保持及增减。
- `rtl/utage/BypassShadowBuffer.sv:3825`：第一个单元的新建、饱和保持与普通更新；其余单元逐项核对译码及赋值。
- BPU的对应SF文件为 `rtl/bpu/BypassShadowBuffer.sv`，内容及行号相同。

检查不是逐地址仿真。静态投影读取全部复制连线，再由一个任意9位训练地址、任意9位观察地址、任意完整保护数组和六个优先级/资格输入构造符号反例查询。期望使用四级保护的显式转移表，不把RTL加减表达式复制成期望。

实际RTL投影与语义不一致的查询返回 **UNSAT**。五类错误投影——新建初值、复位值、老化步长、读取归属、写入归属——分别返回 **SAT**，保留可重放查询与模型。27项纯检查通过，其中五类错误也直接从内存中的RTL文本变化经过投影，防止只验证手工构造的中间结构。

## 这不是哪些证明

它只检查当前归因源码中的局部一拍递推，不是通用Verilog验证器，不证明现有二进制的编译等价性。SF源码哈希与最近真实执行的源码快照逐项相同，但这不能替代完整编译绑定。

它也不证明父级为哪条原经验选择了训练地址，或奖励、惩罚、分配资格是否正确。已知非条件类型过滤、15位标签、在途来源归属和持久性差异均仍保留。局部算术符合规则，与父级喂给它错误资格可以同时成立。

范围仅为短经验模块；长经验的初始保护和老化规则不同，不能套用这份证书。活动时钟递推与启动随机初始化也明确分开；额外活动写入、条件化复位或老化、数据位宽变化都会拒绝出证。

## 对后续验证的影响

4022行仍留在原生缺口和原分母中，仍逐行关联原人类语义要求，没有提升任何硬件reached/checked或功能通过率。新增限定结论是：局部保护译码、饱和算术和复位/老化优先级已有源码证据；下一步应关注父级原经验归属、反馈资格、可达状态和编译绑定，而不是再造一批同义加减边界程序。

原缺口分类总量也不因局部证明而自动减少：父级及实际DUT范围尚未闭环，不能直接将4022行移成“物理副本全部等价”。最新硬件仍是218项195PASS/23FAIL，所有原生LCOV及测量文件字节未变；BPU仍81.9278%，UTAGE仍83.4525%，总缺失10761行。默认收集从29047增至29074，仅新增27个离线检查，旧节点全部保留。

开发中解析器曾误把相等比较当作赋值、漏支持等价括号写法；另一个负向夹具最初改到了范围外的方向写入资格，而不是保护资格。均已修正并重新验证。前两份失败JUnit作为分析原因保留，不把它们登记成RTL缺陷，也不将过期试验当作当前证明。
