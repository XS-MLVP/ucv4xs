## 本轮先厘清的证据问题

010旧lookup-gate程序在关闭前特意查询MISS_PC；“关闭后仍是miss”不能区分
真正保持已学有效流水内容与错误清空，需要不同有效payload的前态。不能
从测试名有hold就认为所有保持义务已证明。

025旧depth模型描述请求way计数初始化，完整语义参考则要求记录合并的归属
不破坏另一有效身份。请求way与保留owner不是同一概念；弱值2或空邻居使二者
看起来一致。该旧辅助期望不能独立证明owner正确，尤其rawHit=0时的裸counter
不该被提升成架构功能。027的非弱有效邻居反例仍普通FAIL；先登记此模型边界，
后续修正测试/辅助参考时不能删掉或弱化该反例。

MainBTB原生剩50个替换状态副本零DA，逻辑年龄已有024/030合同和场景；分母
保留，不把50份复制当作50种新功能，也不因已有逻辑PASS就假定副本等价。

### MBTB-001：复位完成后冷查询没有旧分支，正常学习仍可使用

- 事件：存储初始化复位后接纳新的取指查询与反馈。
- 所有权：新请求属于复位后的分支寿命，旧记录/待写方向/清除义务不自动复活。
- 效果：初始化就绪，冷查询所有定义有效项为miss，后续合法反馈可正常建立分支。
- 观察：实际初始化完成、独立冷态及新学习消费者比较，不以单纯等待固定周期判就绪。
- 保持：reset中未定义数据不作有效payload，不能把未初始化读取误认为旧分支。
- 范围：当前SRAM初始化与新执行；非空、在途写和cleanup前态复位需独立证明。
- 证据边界：旧用例只在新实例复位后冷查且有时限，不能单独证明所有旧在途义务被清除。

### MBTB-002：同一取指窗口的不同逻辑分支能够共存

- 事件：同块不同位置的合法分支分别被学习，且未超过声明容量。
- 所有权：每个记录由原块tag和分支位置拥有，不因同一PC窗口就合并成一个分支。
- 效果：各分支同时保留完整位置/类型/目标，重新查询仍各自可见。
- 观察：独立原分支列表与完整实际向量、匹配metadata和回访消费者比较。
- 保持：新增分支不改变未替换邻居，原位置与窗口次序正确。
- 范围：当前两way/两对齐窗口内的声明共存，不承诺任意多分支无限容量。
- 证据边界：不同位置共存不证明同位置修正、重复命中清理或所有替换冲突。

### MBTB-003：完整分支记录的属性和目标共同属于原指令

- 事件：不同合法类型/位置/目标的原分支被学习并查询。
- 所有权：类型、RAS动作、位置和完整目标是同一记录，不能从不同反馈拼接。
- 效果：返回完整正确payload，条件方向与非条件属性各按规则解释。
- 观察：独立原payload和有效向量消费者比较，不能只检查目标低位或一个valid。
- 保持：其他分支及原metadata保持，未定义miss payload不参与正确性。
- 范围：声明类型和地址域；完整目标跨区域及属性重写分别见013/014。
- 证据边界：一般payload回读不证明所有RAS动作、地址高位或原来源寿命。

### MBTB-004：条件分支方向双向学习并在两端保持，不回绕

- 事件：已匹配条件分支接纳taken/not-taken反馈，计数跨方向边界及上下限。
- 所有权：方向计数属于原条件分支和匹配来源，不能从当前其他way读值更新。
- 效果：计数正确增减，零/三同向保持，反向仍可离开边界并改变方向。
- 观察：实际完整反馈、独立逐步计数及fresh方向/来源metadata比较。
- 保持：tag、类型、位置、目标与其他身份保持，不为方向学习误分配新记录。
- 范围：2位条件方向及声明反馈节奏；陈旧来源连续重放不自动等同逐拍最新值累计。
- 证据边界：原用例检查0/3及反向恢复，不能把这里的方向饱和与MicroBTB可靠性耗尽混同。

### MBTB-005：已有间接分支改目标时仍更新原记录，不额外制造分支

- 事件：真实命中间接分支的原metadata携带新目标纠正。
- 所有权：新完整目标属于原tag/位置记录，而非新候选way或另一分支。
- 效果：原记录目标更新且只保留一个该分支，类型/位置一致。
- 观察：原来源、实际纠正及fresh完整向量中目标与有效记录数比较。
- 保持：未参与分支和原metadata保持，不把旧/新目标同时有效当作成功更新。
- 范围：真实命中的间接目标修正；复杂coalescing/跨owner和属性变化分别另审。
- 证据边界：单居民用例不能独立证明邻居隔离或同拍不同记录服务。

### MBTB-006：冲突替换只影响所选居民，其他索引与幸存记录保留

- 事件：同物理记录容量发生不同tag冲突，另有独立索引居民。
- 所有权：替换资格属于对应策略索引，tag身份与共享年龄别名需区分。
- 效果：合法受害者被新分支替换，非受害者和独立索引仍正确返回。
- 观察：独立策略前态、实际分配与全部声明居民/新分支消费者比较。
- 保持：无关tag、目标、属性和方向保持，不能从实际消失项反推受害者。
- 范围：当前有限冲突程序；共享策略索引及相邻最新年龄另由024/030明确。
- 证据边界：访问若干set不证明所有物理副本等价，不为每set复制需求。

### MBTB-007：重叠查询按原取指窗口关联完整结果

- 事件：查询在前一响应完成前继续接纳，形成流水重叠。
- 所有权：每个完整向量及metadata属于原窗口快照，不属于最新线上PC。
- 效果：逐笔按协议返回，不错龄、漏笔或重复关联。
- 观察：现有异步driver/monitor与scoreboard按实际接纳/完成比较定义输出。
- 保持：原请求不变，查询不改变学习记录，miss字段不被伪当有效payload。
- 范围：当前两周期响应协议与声明流量；延迟归driver，不以周期数命名功能。
- 证据边界：重复同PC只验证时序，012异质payload才区分原请求归属。

### MBTB-008：越页窗口过滤只限制当前可见性，不删除下一页分支

- 事件：页末起点的预测窗口覆盖下一页已学习分支，随后从下一页合法起点查询。
- 所有权：记录仍属于原下一页指令，当前fetch过滤不拥有将其删除的权利。
- 效果：当前输出不返回越页分支，raw匹配身份保留，新页查询可正确重映射位置并命中。
- 观察：独立页/窗口地址算术、过滤raw-hitmetadata与新页完整消费者比较。
- 保持：目标、类型、方向及其他记录保持，过滤不是SRAM失效。
- 范围：当前4KiB页和两对齐窗口代表边界；不宣称完整MMU或任意异常跨页行为。
- 证据边界：无valid单独不足以区分正确过滤与条目被误删，保留新页消费者。

### MBTB-009：取指起点越过分支后隐藏该分支，但原起点仍能消费它

- 事件：同记录被较晚起点窗口查询，分支位于本次起点之前。
- 所有权：静态记录归原指令位置，当前可见性归本次fetch窗口。
- 效果：较晚查询不返回已越过的分支，回到原块起点仍完整命中。
- 观察：独立位置/窗口推导、raw匹配metadata与两类fresh消费者比较。
- 保持：原记录和其他窗口居民不因过滤被删除或重写。
- 范围：声明起点偏移过滤；不等于页过滤、全部排序或完整FTQ切块证明。
- 证据边界：位置只换数字而不保留原起点回访，无法证明是过滤而非破坏。

### MBTB-010：禁用时不接受新查询替换已保存窗口，恢复后仍可消费原学习

- 事件：预测级已有读取/结果时关闭enable，再提供不同请求，随后重新开启。
- 所有权：已保存窗口属于原请求，关闭期间新PC不拥有替换该窗口的资格。
- 效果：按协议保持已有级内容，rawHit使用资格关闭，恢复后新合法查询正常命中。
- 观察：应以不同有效payload的前态区分保持、清空和追随新请求，并比较恢复消费者。
- 保持：记录内存和方向不因门控清空，不能把rawHit低解释为未保存任何状态。
- 范围：静态关闭查询级保持及恢复；切换当拍既接纳在途义务还需明确协议证据。
- 证据边界：旧程序关闭前先查MISS_PC，held本来就是miss，不能区分错误清空与真正保留有效窗口；需更强前态但不改旧PASS为新证明。

### MBTB-011：禁用不接纳新的目标学习，重新开启后相同纠正可生效

- 事件：已学习间接分支在enable关闭期间收到目标纠正，随后开启重发。
- 所有权：新学习资格属于enable有效的原反馈，不能借旧命中绕过门控。
- 效果：关闭反馈不改原目标，开启后合法纠正更新完整目标。
- 观察：同份真实metadata的关闭/开启正反对照与fresh完整消费者比较。
- 保持：其他居民、原类型/位置及快照保持，查询门控与训练门控不能互代。
- 范围：静态禁用训练；此前已接纳写入在切换边界的完成/取消策略需单独审查。
- 证据边界：不从RTL当前行为盲猜在途策略，不把旧静态用例宣称全动态enable正确。

### MBTB-012：不同PC的重叠查询返还各自位置、类型和完整目标

- 事件：不同分支身份以相邻周期交错查询，payload被预先设计为可区分。
- 所有权：完整向量和metadata属于原接纳PC/窗口，不以同target或重复PC近似关联。
- 效果：逐笔实际响应保持各自身份、位置和属性，反向回访仍正确。
- 观察：提交前冻结独立期望，现有异步scoreboard对实际接纳/完成完整比较。
- 保持：原请求和已学居民不被后来PC覆盖，空槽与无效payload不当真值。
- 范围：声明异质请求流水；不证明任意背压或flush取消协议。
- 证据边界：012与007共享响应归属要求，不把不同PC个数当作新功能数量。

### MBTB-013：局部目标在同区和相邻区域之间完整重建

- 事件：原分支目标分别位于PC同区域、前一区域或后一区域。
- 所有权：完整目标由原PC区域、局部偏移和合法carry/borrow共同拥有。
- 效果：按半字API正确还原完整地址，不因只比较低20位而混淆跨区目标。
- 观察：独立区域算术与实际完整目标消费者比较，分别区分Fit/Overflow/Underflow。
- 保持：原tag、位置、属性和邻居保持，不能将MicroBTB无carry配置套进本模块。
- 范围：20位半字局部目标，即2MiB字节区域及相邻carry；不承诺任意远区域无损。
- 证据边界：三类代表目标不是所有高位/符号边界已覆盖，地址单位必须在适配层保持一致。

### MBTB-014：同位置类型修正复用原记录，并正确重新初始化其方向

- 事件：原分支在条件/直接/间接类型之间被真实来源纠正，且同块有独立居民。
- 所有权：完整新属性属于原tag/位置记录，不能额外分配而留下旧类型版本。
- 效果：原way复用、旧类型消失、目标更新，方向回到规定弱正初态并能继续学习。
- 观察：预先把方向老化到可区分值，逐次实际修正、同位置唯一性和后续条件学习比较。
- 保持：邻居完整记录与方向保持，不能因类型改变重置另一个有效分支。
- 范围：真实fresh命中的声明类型链；陈旧cold重放和跨保留owner另有023/027。
- 证据边界：必须保留非初值前态与邻居，不用“仍为2”证明发生了正确初始化。

### MBTB-015：预测正确也继续学习条件方向，不只在误预测时训练

- 事件：匹配条件分支收到正确taken或正确not-taken反馈，并有误预测翻转过渡。
- 所有权：方向反馈属于原条件分支，不由整份反馈mispredict位统一决定是否学习。
- 效果：正确反馈仍强化/减弱计数并在边界保持，记录不误分配。
- 观察：真实且方向一致的完整来源、逐步独立计数与fresh目标/方向/身份比较。
- 保持：邻居及原完整记录保持，不构造逻辑自相矛盾的“正确结果”来凑覆盖。
- 范围：声明条件方向与正确反馈；不同源的陈旧计数累计规则另行声明。
- 证据边界：训练只看mispredict=1会漏掉此功能，旧正反向消费者和精确计数均保留。

### MBTB-016：同拍不同条件分支各接纳自己的方向结果

- 观察：完整实际向量、独立每分支计数与fresh双方消费者比较。
- 保持：两个目标、类型、位置和未选居民保持，不能只看到一路counter写入。
- 范围：当前同align bank两条合法条件学习，不推断多误预测或同目标冲突优先级。
- 证据边界：串行各训练一次不能证明同拍并存，必须保留真正向量输入。

- 范围：陈旧metadata的独立UT端口程序，不证明集成FTQ能合法形成同样重复源。
- 证据边界：原程序人工暂停cleanup用于制造前态，调度在agent内；同拍训练冲突/清除延期另有026/028。

### MBTB-020：读阻挡时不同方向补丁不丢失，解除后按序服务

- 事件：两个不同原分支的方向反馈相邻接纳，真实同bank预测读阻挡服务。
- 所有权：方向补丁由原分支身份与waymask拥有，不是entry写缓冲的合并版本。
- 效果：两份方向效果均保留并有序写回；异bank流通正对照不能被错误缓冲或丢弃。
- 观察：独立完整补丁、实际容量/阻挡/服务，及fresh目标/邻居方向联合比较。
- 保持：未选way、两类sentinel和原记录payload保持，不用最终同方向掩盖漏一份服务。
- 范围：深度二的两键安全容量、已知计数2前态；不证明溢出、任意饱和值或完整entry版本。
- 证据边界：24次查询只是制造竞争的窗口，不是功能要求中的固定等待；实际阻挡和服务不可省略。

### MBTB-021：同一间接记录的待写纠正合并为最新完整目标

- 事件：相邻两份真实命中来源纠正同一间接分支，服务分别被读阻挡或自由流通。
- 所有权：两份目标是同一逻辑记录的有序完整版本，不是两项独立方向队列义务。
- 效果：阻挡时保留最新完整目标再服务，流通时按实际顺序服务；区域carry与低位必须同属版本。
- 观察：预先区分两个区域目标，实际请求/写回和fresh完整目标及所有邻居比较。
- 保持：原位置、类型与合法方向保持，不能把新版carry和旧版offset混合。
- 范围：两次纠正、初始弱计数与声明区域过渡；不证明满行、flush、陈旧way或跨row优先级。
- 证据边界：latest-only只适用完整记录合并，不能拿它取消020方向FIFO中的独立效果。

### MBTB-022：不同分支的待写纠正不能因共享服务资源而合并或串换

- 事件：同bank两个不同set/tag原间接记录在读竞争中接纳相邻目标纠正。
- 所有权：每份完整目标和carry属于各原键，不因物理owner相同就成同一版本。
- 效果：两项均保留并各自实际服务，输入顺序变化不改变各自最终目标。
- 观察：独立每键期望、实际请求/有序写回与双向重叠全邻居消费者比较。
- 保持：未选way、其他set/bank与原metadata保持，不让另一键覆盖自己的offset或carry。
- 范围：容量内两键安全程序；不承诺无反压满行miss无损或任意陈旧way迁移。
- 证据边界：与021“同键合并”正交，两个不同目标都返回正确还需实际服务链证据。

### MBTB-023：陈旧cold反馈的请求way改变时，原保留记录仍保持自身owner

- 事件：原cold来源被正常保留后重放，替换年龄令新的请求way可能不同于现保留owner。
- 所有权：完整tag/位置记录拥有保留版本，request way不是永久逻辑身份。
- 效果：新纠正更新原保留记录并按原owner服务，不覆盖另一个独立记录。
- 观察：独立LRU预定请求way，实际保留owner/请求/写回及完整消费者共同核对。
- 保持：原coldmetadata、邻居和其他索引保持，不能从实际way反推期望归属。
- 范围：单保留键、两次纠正和计数2前态；不证明非弱邻居方向、完整FTQ或满行仲裁。
- 证据边界：弱/空前态掩盖计数归属差异，027仍是非弱有效邻居反例，不借本点PASS关闭。

### MBTB-025：保留深度改变不改变分支owner，记录与方向归属不能混同请求way

- 事件：两个不同键使保留记录占用下一服务深度，后续陈旧来源提出跨请求way纠正。
- 所有权：记录属于原完整身份/保留owner，方向初始化也不得误伤另一有效分支。
- 效果：正确深度的完整记录被更新和服务，未参与的有效邻居仍保有自己的方向。
- 观察：实际有效/clean深度前态、独立完整请求与owner服务，再查询目标及可区分邻居。
- 保持：其他键和有效非目标方向保持；rawHit=0的裸计数不能被当作架构保留义务。
- 范围：当前两键/两深度程序及弱或空邻居；不证明一般非弱邻居、满行或完整FTQ。
- 证据边界：旧depth辅助模型按请求way写计数2，不能单独充当正确owner的golden；弱值2前态不能区分，027有效非弱邻居FAIL必须保留，后续需纠正辅助期望的范围。

### MBTB-026：重复清理与不同记录训练同拍时，清除不吞掉另一身份

- 事件：真实重复命中触发cleanup，与不同set的正常目标纠正在同一服务边界竞争。
- 所有权：失效属于重复记录的目的槽，训练属于另一完整逻辑分支，不因tag/position零值混作一键。
- 效果：规定重复项被清除，另一目标纠正按其owner保留/服务，其他bank无额外写入。
- 观察：真实清理前态、完整双来源/保留项前后比较及fresh幸存者和邻居消费者。
- 保持：较低重复项、独立记录及原metadata保持，clean/dirty清除都不得伪装普通分配。
- 范围：现有非联合零键、两深度/clean-dirty声明范围；不自动覆盖同端口延期或全部零键。
- 证据边界：联合零tag/position的wrong-owner由029单列且普通FAIL；028的丢失cleanup通知也不可因本点PASS豁免。
