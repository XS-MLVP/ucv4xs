# 容量已满时迁移分支的迟到反馈不淘汰独立学习

待写容量已满，不等于每份新到达反馈都需要替换一个旧结果。若迟到反馈
命中已经迁移的逻辑分支，它必须更新该分支的当前版本，而不是按原物理
owner另插入结果或淘汰另一份独立学习。这细化INT-089的满容量命中义务，
不是为每个bank、set或槽位新建功能点。

## 尚未闭合的语义组合

目前集成写缓冲还有164个原生DA键未闭合。单独满容量命中、目标迁移和
两个逻辑结果共存已有各自证据，但不能推出容量满时跨owner的迁移命中
仍保持全部独立结果。相关残差含保留结果的交叉更新及服务路径；是否
新增行命中须以实际测量为准，不能把164个键当成164个新功能。

## 预先声明的正常事件程序

24步正常准备保存两份不同目标原预测，原A=2、B=5；正常替换后当前A=1、
B=4，两个provider位置互换。再以8、10、10步正常学习分别建立三个独立
历史，每个历史A=2、B=5。它们与目标共享MainBTB身份，但TAGE历史与行
分别由独立模型推导，要求四个逻辑结果不同，不写死启动中的存储索引。

| 相邻反馈 | 必须保留的结果 | 容量语义 |
| --- | --- | --- |
| 三份独立邻居各一份 | 各自A=1、B=6 | 按正常学习形成三份独立待写结果 |
| 迁移后目标的新鲜预测 | 目标A=0、B=5 | 用最新1/4建立第四份结果，达到容量边界 |
| 第一份迁移前目标预测 | 目标累计为0/6，三个邻居仍1/6 | 实际满容量前态下命中当前目标，不应替换 |
| 第二份迁移前目标预测 | 目标累计为0/7，三个邻居仍1/6 | 再次实际满容量命中，不能丢失后继或独立结果 |

六份来源必须是真实发布的不同查询，完整输入和提案分别相邻。旧目标
提案仍为1/6，不能把它当作最终0/7。预测读持续阻挡服务；两份旧目标
内部更新出现时，都必须观察到两个owner的全部四份待写义务仍在，不能
只凭六次公开接纳宣称容量已满。

服务前五个新查询分别看目标1/4、三个邻居2/5、被置换历史双miss。
解除竞争后，每个当前owner必须完整服务三个邻居及目标各一次，共八次
SDK服务。服务后五个新查询分别看目标0/7、三个邻居1/6、被置换历史双
miss。MainBTB完整身份与六份输入metadata保持。缺任一满容量前态、服务、
消费者或快照检查，都不能获得checked。

## 范围与实现边界

这是“满容量下命中当前逻辑身份不淘汰独立学习”，不是“满容量下新key
缺失也永不丢弃”。原容量加一的新key替换合同不变。也不能用较小共存
程序的PASS为本义务授予通过。

Driver负责并行输入，monitor通过memory-direct只读观察及SDK转移确认
实际前态和完整服务；独立MainBTB、TAGE、历史与保留版本模型从复位推进。
不读实际dirty、分配或proposal播种golden，不写内部存储、不伪造metadata，
不在case写引脚、边沿、固定等待或asyncio task/gather。

Useful为0，不关闭已知useful失败；本程序不是完整FTQ调度、全部预测器
组合或任意超容量无损保证。旧合同、旧子义务与用例保留；失败直接抛出，
由pytest判普通FAIL，不新增或扩大XFAIL。行分母全部保留。

## 满容量专项的实际结果

新增67项纯模型及错误注入检查通过；与旧检查合并的237项纯检查不产生
DUT原生覆盖或硬件功能组。相关452项兼容回归通过，原384项判定保持。
单独DUT程序通过，两份旧反馈更新前，两路实际待写向量均为四份有效
义务；随后八次完整SDK服务、十个新查询和六份不可变快照完成全部九项
reached及九项checked。见[精简实际事件](../results/bpu-full-neighbor-migration-evidence-20261017-v1/event-qualification.json)。

实际服务的每路前三份属于三个独立邻居，最后一份属于迁移目标。预先声明
的计数序列分别为1、1、1、7和6、6、6、0；实际完整行、tag、valid、计数和
当前owner均逐笔比较，不能只从最终0/7推断中间学习没有丢失。

专项相对上一完整测量新增15个原生DA键，全部位于WriteBuffer_8的1089至
1097、1299至1302及1619至1622中的实测键。增量来自包括准备在内的整个
正常事件程序，不唯一归因于某份旧反馈；完整复验已确认15键全部保留。
