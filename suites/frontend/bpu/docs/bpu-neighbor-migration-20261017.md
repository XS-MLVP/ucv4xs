# 独立学习尚未写回时保留迁移分支的后续学习

迟到反馈属于原逻辑分支，但必须从当前保留版本继续学习。已有另一条历史
的学习尚未写回时，新鲜目标反馈及其旧反馈不能覆盖这个独立结果；两边
都应在真正获得写服务后，被新的预测查询正确消费。这细化已有 INT-089，
不是为写缓冲的每个物理槽位新建功能点。

## 从缺行到尚未闭合的语义组合

现有集成 TAGE 写缓冲仍有179个原生DA键未闭合。双迁移和双路连续退休
已有实际证据，但没有证明独立待写学习与目标当前版本共存时，后来的旧
反馈仍保持逻辑归属。相关实现含多份保留结果的交叉更新和服务路径；这不
意味着179个键都是新功能，也不预先保证本程序命中全部残差。

直接插入邻居可能淘汰目标的干净保留版本。此时不能继续套用“目标最新
保留计数”的期望。程序先证明另一历史的正常学习，再以一份新鲜目标
反馈建立当前待写版本，最后接纳旧目标反馈；不读实际槽位选择 golden。

## 预先声明的程序与效果

复用24步正常迁移准备，保存两份不同目标原预测：原A=2、B=5，分别由
owner0、owner1提供。正常替换并重新分配后，目标A=1、B=4，owner互换。
再用8步正常反馈为同一PC的独立历史建立A=2、B=5，owner仍0、1。
两条历史的TAGE行索引从各自独立历史推导，要求不同，不写死启动中的行号。

| 顺序 | 实际反馈来源 | 必须形成的逻辑结果 |
| --- | --- | --- |
| 1 | 独立邻居的新预测 | 邻居A=1、B=6，两份学习尚未服务 |
| 2 | 迁移后目标的新预测 | 以当前1/4建立目标A=0、B=5，不继承邻居计数 |
| 3 | 第一份迁移前目标预测 | 原提案仍1/6，但目标当前结果累计为0/6 |
| 4 | 第二份迁移前目标预测 | 原提案仍1/6，目标累计为0/7，邻居仍1/6 |

四份来源必须是真实发布过的不同查询，完整输入相邻接纳，均独立满足无需
训练重读的资格。持续同bank预测读阻挡写服务；接纳不等于存储可见。
写回前的三个新查询分别看到目标1/4、邻居2/5、被置换历史双miss。

解除竞争后，每个当前owner都必须完整服务邻居、目标各一次，共四次SDK
确认。新的三个查询必须看到目标0/7、邻居1/6、被置换历史双miss；MainBTB
的完整位置、目标、属性和四份输入的原metadata保持。缺少任何输入、服务、
消费者或不变性检查，都不能获得 checked。

## 范围和实现边界

Driver负责并行提交，monitor通过memory-direct只读观察与SDK转移确认
实际前态、竞争和完整服务。独立MainBTB、TAGE、历史和保留版本模型从
复位推进；实际dirty或proposal只能用于验证，不能给模型播种或修正答案。
测试入口不写引脚、边沿、固定等待或asyncio task/gather。

本程序只要求两个逻辑结果在有余量时共存，不宣称满容量或任意容量无损。
Useful为0，不关闭已知useful归属失败；也不证明完整FTQ调度或全部预测器
同时开启。原INT-089合同与旧用例保持，新增义务不继承旧PASS。失败直接
抛出，由pytest判普通FAIL，不新增或扩大XFAIL。行分母全部保留。

## 专项实际证据

新增61项纯模型／错误注入检查及原109项检查共170 PASS；相关兼容384 PASS，

服务后目标0/7、邻居1/6，被置换历史双miss；四份输入metadata保持。见
[精简实际事件](../results/bpu-neighbor-migration-evidence-20261017-v1/event-qualification.json)。

相同构建对照上一完整测量，专项新增15个原生DA键，均在
`rtl/bpu/WriteBuffer_8.sv`：899、900、901、902、903、904、907、1231、1232、
1233、1234、1563、1564、1565、1566。它们来自整个正常语义程序，包含准备、
新鲜学习和迟到学习，不能全部唯一归因于某一份旧反馈，也不是15个新功能。
专项增量本身不证明全量没有其他旧命中损失。

下一项满容量下迁移命中仍需独立DUT证明；本程序只验证两个逻辑结果共存。
