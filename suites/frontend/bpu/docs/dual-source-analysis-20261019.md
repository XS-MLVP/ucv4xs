# 同一反馈内的两条温态分支各自学习，非条件位置不应偷学

## 缺少什么功能语义

已有多槽向量用例主要覆盖“较早来源正确、较晚冷来源新分配”，类型过滤则只有单个温态来源。两种独立证据不能证明同一原预测中短、长经验已各服务不同指令位置时，它们仍按真实执行前缀各自学习。

本次先定义[联合功能契约](dual-source-contract.json)，再开发40程序；只扩展013/014/021/025的明确义务及证据，保留353个功能编号、全部旧契约和另外349个定义。没有把物理槽或存储索引变成功能点。

| 指导结果 | 语义要求 | 本轮结果 |
| --- | --- | --- |
| 较晚条件跳转 | 较早NT与较晚T各按自己的原贡献学习 | 8 PASS |
| 整窗NT | 两条已执行条件各学NT，只有原错误者受罚 | 8 PASS |
| 较早条件跳转 | 只教导较早条件，未执行后序完整保持 | 8 PASS |
| 较晚解析为直接/间接跳转 | 同位置温态条件不学；仍合格的较早条件继续学习 | 16 FAIL |

短表服务较早/较晚、正序/逆序槽位且带空洞、串行/相邻反馈分别交叉。每份输入最多一处方向错误，遵守源码已有的输入假设；没有使用尚未确认的“多错误同时竞争分配”。PC沿用旧向量程序，不枚举bank/set或搜坐标。

## 如何检查

正常reset后建立两条经验，不播种DUT状态。复用未修改的完整 `UtageReference`，另以独立的指令位置与原贡献算术声明预期。两份真实原向量在学习之前捕获，随后各只反馈一次；第二笔必须在当前版本累计，不能重用旧计数重启。

检查完整载荷、每笔短/长实际版本、全部1,024保护状态、原件不可变性和fresh完整向量消费者。新增轻量游标bundle从已有MEM_DIRECT绑定直接观察两表实际版本发生，不用参考模型判断“没写”；只保存发生学习时的摘要，不保存逐周期JSON。即使一表状态未改变，也核对合格写入或不合格保持的实际边界和内容。

## 16个失败是不是新问题

不是新根因。历史完整回归中，025的direct/indirect两个单来源温态过滤用例已经普通FAIL；本次的16种组合复现同一类型资格问题。

首轮把较晚计数准备到上界7，只看到额外写入，不能仅凭它证明数值功能出错。因此保留首轮证据，并强化非条件保持场景：通过正常学习把较晚计数准备为内部值6，再由公开新消费者检查。

最终16种组合全部确认：

- 反馈前，实际原查询和原生状态中的较晚计数均为6。
- 解析为非条件跳转后，这条本应保持的经验实际写成7。
- 公开新查询报告独立参考要求6、DUT实际7；不只是指针变化。
- 较早仍合格来源的实际写入符合预期，因此不能以跳过整份反馈修复此语义。

原Scala `MicroTage.scala:281` 的 `trainHasAbtbBranch` 只检查位置不晚于结果；`dut/utage/UtageDut.v:1483` 等实际生成valid赋值同样没有对“位置相等且解析非条件”排除。错误检测资格和普通温态更新资格不一致。这里只定位原因，未修改RTL、DUT、SDK或独立参考。

四个扩展功能在本轮实际feature报告中均为FAIL；不能因为旧冷态或局部控制曾通过，就称扩展后的功能已完成。原完整回归的历史字段仍原样保留，二者按定义和执行范围分开报告。
