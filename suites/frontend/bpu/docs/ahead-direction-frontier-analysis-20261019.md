# 早期方向缺口：哪些是功能，哪些还只是独立模块见证

## 人能理解的要求

集成Ahead剩余4,043个未命中行，不对应4,043个新功能。对照原Chisel、生成RTL和现有契约，它们实现三类已有义务：

| 功能语义 | 对应的缺失实现行 |
| --- | ---: |
| 只让已执行条件接受“不跳转”证据：较晚跳转否定前序条件，整窗不跳转否定所有实际命中条件；未执行后序不受罚 | 2,787 |
| 本分支的跳转结果增强自己的方向信心，不给其他分支奖励 | 755 |
| 新分支替换旧居民后取得自己的弱初值，不能继承旧强方向 | 501 |

边界保持、反向恢复、类型隔离及原来源归属是上述事件的必要判别条件，已有ABTB-010/011/013/014/036/037定义。不能因同一规则复制到多个存储单元，就新增相同功能编号或开发bank/set枚举。

## 原生数据的实际源码

独立ABTB实际编译主文件 `dut/abtb/AbtbDut.v` 内是完整的 `AheadBtb` 模块，不是纯picker包装；其内容与 `rtl/abtb/AheadBtb.sv` 字节相同。覆盖见证必须在实际编译主文件中找，不能因LCOV没有使用后一条文件路径就认为其代码没进入分母。

对每个集成缺失行，使用唯一的九行局部代码窗口映射到独立主文件；只移除注释，不重命名标识符。4,043行全部一一对应，行号偏移均为366。这个可复算的局部源码对应，不是整个模块形式等价，也不是父模块合法输入可达性证明。

## 命中、通过、集成通过必须分开

独立ABTB累计行覆盖为100%，这些对应行全部有历史命中。但该轮ABTB判定是72 PASS/1普通FAIL；失败是不同待写目标的归属丢失。因此不能把整个历史混合执行当作4,043行的全PASS见证，更不能授予BPU集成信用。

本次复用六个已有语义控制，当前源码下通过生产入口四进程隔离执行，全部PASS：双向边界与邻居隔离、同组分支独立学习、前后序资格、整窗NT与选择性恢复、混合类型隔离，以及强旧居民替换后的弱初值。常驻独立 `AbtbReference`、输入/输出monitor和scoreboard同时工作。

通过执行实际命中17个新身份初始化、14个减弱、6个增强的方向赋值点。在集成仍缺失的4,043行中，只为22行提供本次独立全PASS局部实现见证；另4,021行没有本次单独通过见证。没有据同一规则外推物理副本等价，没有增加任何集成命中或全量功能通过。
