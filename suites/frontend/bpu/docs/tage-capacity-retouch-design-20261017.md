# 满容量重访之后的新学习替换

上一批置信度边界程序闭合了四种算术轨迹，却没有减少137个集成TAGE缓冲开放键。
本批组合“满容量重访”和“随后新身份替换”，没有枚举饱和计数、bank或物理
保留槽。设计方确认命中应刷新近期关系；六个真实程序中两个对照通过，
四个区分访问型与插入型策略的程序发生普通FAIL，RTL暂不修改。

## 已有证据之间的缺口

[满容量重访程序](../bpuverify/bpu/model/tage/service.py)的输入顺序是A、B、C、D、A，
要求四个待写身份都保持；[满容量替换程序](../bpuverify/bpu/checker/direction_replacement.py)
则是A、B、C、D、E，固定由原策略淘汰A。它们没有组合验证：A被重新访问并
累计之后，新的E应基于更新后的近期关系选择另一受害者，而不是仍淘汰A。

## 功能要求与程序

满容量时再次学习一个身份，应从它的当前结果累计，并更新该身份的近期关系。
紧接着的新身份学习必须使用已经更新的替换策略。新身份从自己的原预测初值
开始，不能继承被淘汰身份的饱和计数；其余存活身份的学习和完整来源保持。

先准备四个不同真实历史，再分别使用A后E、A后C后E、C后A后E三个逻辑程序。
它们区分一次重访、两次不同重访及输入顺序；受害者由独立既定策略预先计算，
不是从实际rank、PLRU位或SRAM读出。每笔仍须不同原预测，另行检查历史重建
资格和辅助队列接纳，不能复用同一个checkpoint制造额外近期事件。

增加C后E、D后E两个受害者不变的对照，以及A后E在前一学习完全成熟后才接纳
新历史的对照。它们区分算术/身份串改、替换近期关系遗漏与流水重叠，不按
物理保留位置拆功能ID。所有程序使用不推进PHR的正常fall-through读流，
每笔原训练折叠历史与其独立checkpoint比较，辅助Main更新必须真正ready接纳。

## 替换策略与模型边界

设计方已确认：命中也刷新PLRU近期关系。默认参考已改为每次接纳学习都更新
近期关系，原先仅新身份建立时更新的策略只保留为显式诊断对照，不能作为
通过条件或自动容错。
生成RTL也只在`io_write_valid && !hit`时更新替换状态，见
[WriteBuffer_8.sv:1641](../rtl/bpu/WriteBuffer_8.sv#L1641)。源码虽然构造命中的
hitTouchVec，但[WriteBuffer.scala:268](../XiangShan/src/main/scala/xiangshan/frontend/bpu/WriteBuffer.scala#L268)
使用Scala集合过滤组装访问列表。这里的差异需要实际提案、保留结果和消费者
验证，不能只看命名推断已实现命中刷新。

新程序采用“每次学习都算访问”的确认策略，并用只维护逻辑分组与最近访问
身份的第二份模型独立预测受害者。不根据实际victim选择golden，也不在两种
策略之间自动容错。是否存在实际RTL差异，仍由真实接纳和完整保留结果的
比较判定，不能把策略模型测试当作DUT证据。RTL不修改。

## 检查闭环

正常满容量前提、每笔实际原提案和接纳必须成立。比较重访累计结果、被取代
的唯一旧义务、所有存活义务及完整SDK服务；随后查询全部原历史与新历史，
要求受害者没有虚假的未服务更新，新身份及受保护居民能被新消费者完整消费。
漏服务、错误受害者、用旧快照覆盖当前值及改变邻居都必须由负向检查拒绝。

这细化INT-087/088的组合，不为三个物理受害位置新增功能ID。静态Bundle、
现有异步driver的接纳策略、monitor、独立模型和checker分别实现；pytest只
选择语义程序，不处理边沿、裸信号或并发任务编排。当前长来源的PHR资格
失败不在本批关闭范围。

## 定向执行结果

[定向事件证据](../results/retouch-replacement-dut-20261017-v1/event-qualification.json)
保留了六个程序的实际原历史资格、满容量、重访后完整保留值和首次失配。
60项义务中36项reached、20项checked；两个通过程序各有8笔完整SDK服务和
10个新消费者，共16笔服务、20个消费者。全部38笔新场景实际训练输入通过
原来源历史比较，不能把本次失败归为此前长程序的PHR资格问题。

| 满容量后的顺序 | 预定受害者 | 结果 |
| --- | --- | --- |
| A再E | C | 新E实际替换A，普通FAIL |
| A再C再E | B | 新E实际替换A，普通FAIL |
| C再A再E | D | 新E实际替换A，普通FAIL |
| C再E | A | 全部服务和消费者通过 |
| D再E | A | 全部服务和消费者通过 |
| A成熟后再E | C | 新E实际替换A，普通FAIL |

四个失败都发生在E学习的实际后态。此前的完整输入、双owner提案、四历史
容量以及重访算术都已比较通过；完整后态显示只把A换成E，其他身份保持。
等待前次学习完全成熟仍复现，因而差异不是仅在流水重叠时出现。对照证明
重访算术及完整写回可工作，但不能代替命中刷新PLRU要求的通过证据。

默认参考修正后，相关目录13,416项测试通过，包含模型、检查器与接口层测试，
不能全部称为纯模型测试；其中新增63项为纯模型、检查器和接纳策略测试。
真实运行另有三个既有容量、替换、转发对照通过。全量结果与
原生行增量另以本批完整测量报告为准，不把定向混合运行冒充全量结论。

[本批完整测量](../results/production-retouch-access-20261017-v1/README.md)已完成：
新增69项后，全部旧用例判定保持；BPU增加24个原生行点，其中22点由单例PASS
独立见证，另外2点只见于混合失败运行。开放写缓冲键137减到113，但INT-088
因命中刷新合同差异变为FAIL，不能把行命中增加解释成功能已经通过。

## 用例组合的经验

“满容量命中累计正确”和“新身份替换正确”分别通过，不能推出“命中改变近期
关系之后再替换”正确。近期关系是会影响后续决策的语义状态，需要用后续
事件检验，而不是只观察本次计数变化或读PLRU寄存器。一次重访、顺序交换、
受害者不变和等待成熟的对照一起开发后再跑全量，比按物理位置增加用例更
容易发现遗漏，也减少了每增加一个小用例就全量回归的轮数。
