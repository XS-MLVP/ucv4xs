# BPU 问题报告

本目录记录 10 组模块验证差异。模块里观察到错误路径、输入字段合法、整条事件序列能由 SoC 生成，是三件不同的事，必须分别判断。

本次继续追查 IFU、FTQ、后端提交、CSR 和 BPU 生产者约束。重要修正是：08 原用例不是合法的 fastTrain 字段组合；03、06、09 仍缺真实上游时序见证。此前“模块根因已定位”不能直接理解为“SoC 正常运行缺陷已确认”。

完整依据和补充动态见证见[输入合法性与 SoC 可达性](input-contracts.md)。即使输入合法，预测器也允许失误；是否违反设计约定、是否影响预测精度或架构行为，还须分别说明，不能要求预测器永远预测正确。

## 这次复核改变了哪些判断

- **03**：不是仅凭赋值先后猜“同拍自己清自己”，而是实际观察到后一条反馈用过期槽号清掉前一条的新版本。
- **06**：旧报告误读了清理掩码。实现本来只选一份重复记录；实际错误发生在写缓冲把清理请求转到另一条 SRAM 通路。
- **09**：训练前已经检查 tag。丢更新发生在更后的写缓冲合并，不是训练阶段完全缺少 tag 检查。
- **04、05**：禁用门控与返回并调用是独立问题；后者的 7 个原有 FAIL 已归到 10，不新增或重复计算失败。
- **07**：差异仍然存在，但不能因为模型要求忽略反馈，就默认设计必须这样做。
- **输入域**：08 原快训练组合被真实生产者约束排除；给它换成合法字段后仍失败，也不能跳过整条事件序列的可达性证明。

每篇保留“触发步骤、预期与实际、根因、上游输入审核、复现与对照”，先解释行为，再解释信号。

## 几个容易混淆的词

- **表项／记录**：预测器保存的一条分支信息，例如地址、跳转目标和方向计数。
- **位置（position）**：分支在取指块内的偏移。不同地址可以有相同偏移，不能只用它识别分支。
- **tag**：区分地址的标签。同一取指块的不同分支可能有相同 tag；tag 也不等于某次写入的物理目的地。
- **way**：同一组存储中的不同位置。对一份副本的清理不能误写到另一份上。
- **预测元数据（metadata）**：预测时保存、随执行反馈返回的辅助信息，描述的是那次预测。
- **dirty**：缓冲中仍有未写入存储的更新。清除它可能取消待写操作，不只是修改诊断标记。

方向计数、保护值、有效标志含义不同；报告中的表格会明确比较哪一种。

## 怎样复现

在仓库根目录运行各篇末尾的命令。生产入口只选择对应单例，保留按 DUT 隔离的执行方式，不需要跑全量；对照参数或函数在正文中列出。

需准备对应 DUT 和项目依赖，每次使用新的 `results/` 子目录。如果示例目录已存在，请换一个目录名。这些命令运行的是现有 pytest 检查，正文中的小范围诊断复核不冒充一次新的全量回归。

复现到同样差异时应保留 FAIL，不改成跳过或 XFAIL。修复后应同时验证失败场景和通过的对照，不能只让一个用例不再报错。
