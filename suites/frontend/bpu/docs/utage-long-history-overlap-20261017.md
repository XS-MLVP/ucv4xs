# 不同长历史路径的并发学习不能混合

UTAGE-018已有共享短历史、不同长历史的串行学习及交错查询。尚缺的判据是：
两条路径的预测都已独立发布，反馈随后相邻交错到达，各自必须累计自己的
学习，不能借用另一条路径或旧预测快照的方向计数。原生useful分配、增减和
饱和缺口关联这一要求，但不能按每个未访问地址再造一个功能点。

## 来源与预先声明的状态

同一分支的两条历史路径共享短表经验，长表经验相反：A为NT3、保护2，B为
T4、保护2；第三条路径C尚无长表经验，应回退到共同短表T4、保护0。另留
不同短历史的冷邻居，不能由主程序意外学会。先通过正常冷查询和反馈建立
这些状态，不能从实际provider或内部内容选择期望。

每份待反馈来源都先通过独立预测接纳和monitor返回保存，再消费一次。A/B
元数据在批次开始时相同并不等于复用同一来源，必须有不同的实际查询身份。
serial是对照；adjacent必须证明实际相邻接纳，不能由循环次数冒充重叠。

## 必须分别证明的事件

| 事件 | 预先声明的效果 | 区分能力 |
| --- | --- | --- |
| 两路径交错学习 | 三份A正确反馈使NT3→0，三份B正确反馈使T4→7，保护各2→3并保持 | 每条路径使用自己的当前计数，不能从旧metadata重复起算或跨历史转发 |
| 相反两端继续正确 | 新A/B来源分别维持0和7，保护均保持3 | 有真实同向反馈，不靠闲置保持冒充饱和 |
| 两路径反向恢复 | 另外的新A/B来源分别错误，方向0→1、7→6，保护3→2 | 两次最长provider错误各记一次失败，不能反向分配或误当奖励 |
| 共同短表经验保留 | 新C消费者仍回退到短表T4、保护0 | 长表学习不能污染共有基础经验，C也不能借到A/B长表 |
| 冷邻居与旧来源保留 | 冷邻居仍miss，全部已发布metadata不变 | 不从实际命中挑选邻居，也不修改旧来源掩盖错误 |

比较实际反馈完整载荷、接纳节奏、完整1024保护单元、各路径完整预测与最终
消费者。独立事件账本只按逻辑路径和原来源累计；现有自主周期模型继续开启。
reached需要实际事件，checked等待全部效果和消费者通过。失败正常抛给pytest。

## 范围

采用一个可区分的历史三元组和一个邻居，不遍历bank/set。UT允许的历史切点
不直接证明集成BPU全部FTQ来源；FastTrain不是后端提交真值。旧018场景继续
保留，不能用它的PASS或旧矩阵满组自动关闭新增并发义务。不改RTL、DUT或SDK，
不使用VPI或内部写入。

## 已完成的专项验证

两种通信模式及30项纯模型／负向检查共32项全部PASS。完整MicroTAGE兼容
选测608项为601 PASS／7个既有普通FAIL；旧576项nodeid和判定逐一保持，
新32项全PASS。7个旧失败未豁免，不能将新场景通过说成模块整体通过。

每种模式分别保存两批共10个不同的实际预测身份。三次交错正确反馈使A的
计数3→2→1→0，B为4→5→6→7，保护各自到3；新来源证明两端保持，再由
另两份原来源反向恢复到1／6及保护2。每阶段都检查实际完整载荷与节奏、
全部1024保护单元，以及晚于实际学习完成的新A/B消费者。C始终回退短表
方向4、保护0，独立冷邻居仍miss，全部旧来源metadata保持不变。

两个新reached／checked组各20项义务均100%，是018的证据条件，不是20个
新功能点。旧串行矩阵组仍收集且保留在legacy证据中，不将其伪装成成对组。
错误最终计数、另一条路径／共同短表／冷邻居的保护变化、丢或错反馈、重复
来源、错误顺序、气泡、串行化、缺失／旧消费者和旧快照修改均被拒绝。
