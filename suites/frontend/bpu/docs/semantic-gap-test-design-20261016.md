## UTAGE-017/INT-051下一步：维护与学习必须真正同拍

在SC全量源码冻结期间仅复核后续设计，尚未新增本节刺激。已有
`UtageReference` 的共同前态老化及只读monitor会比较全部1024个useful单元，
但 `UtageUsefulReference`/`UtageUsefulChecker` 专项明确只支持128次失败之前，
并把age期望固定为0。新重叠检查不能删掉旧拒绝条件后继续把它称作完整模型；
应保留其范围，复用完整语义参考和memory-direct只读观察，补独立的完整输入、
实际age/学习同时资格、方向消费者与共同前态比较。

两表分别检查分配、奖励、惩罚，共六个语义上下文。选取的保护前态须有
区分力，而不是一律用3：奖励用1（长表1>>1=0，而先奖励再折半为1）；惩罚
用2（正确只老化为短表1/长表1，双重惩罚后再老化会变0）；新分配用0，
同拍新方向应建立，但保护为原0的老化结果而非新初值1/2。另保留保护3且
内容不同的邻居，检查全局变化与全部身份/方向不受维护清空。

正常建立独立最高provider作为失败源，真实错误反馈累积到阈值，不内部设置
tick/useful。前127次按独立语义预期计数，最后一次失败与目标学习相邻发送，
由monitor确认第128次失败后的维护确实与目标学习同拍；不能在每笔排空后
再等待若干周期冒充重叠。失败源与目标索引不相交、目标来源在先前真实查询
中冻结且只用一次；反馈资格和计数不从DUT维护寄存器选择。
若准备阶段已有失败，必须从独立计划明确扣除，不能盲目再发送128次。
UT允许的切点不直接证明集成S3/FTQ输入机会，集成INT-051另需自主来源证据。

一次正常输入的纯模型可行性推演已确认短表奖励组合：正常学习建立独立最高
provider作失败源、目标短表保护1/负方向计数3；127次真实最高provider错误
后，将第128份失败与目标原始来源相邻接纳。维护和目标学习确在同一模型边界，
保护为共同旧值1的老化结果0而非先奖励后老化的1，fresh目标计数仍学到2。
未设置model或DUT的tick/useful状态；此结果仅决定下一步合法刺激的方向，
不是DUT实测、RTL缺陷或六种组合全部验证的证据。
