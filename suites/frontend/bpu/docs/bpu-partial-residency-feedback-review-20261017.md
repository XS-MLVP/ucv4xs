# 部分原分支已被替换时迟到学习的归属

延迟反馈到达时，原分支可能仍驻留、已经迁移，也可能已被替换。已有迁移
程序证明仍驻留的逻辑身份可以跟随当前owner继续学习，却没有决定原身份
已不再驻留时，它与另一条当前分支争用同一目的地的允许行为。本项先列为
模型与规格边界，不将其直接登记为RTL错误或新的无损保证。

## 剩余行缺口与功能问题

集成TAGE写缓冲仍有149个原生DA键属于输入、身份、效果和消费者尚未完全
闭合的职责。它们包含跨owner更新和同目的地替换的候选路径，但不能从行
号推断每一处都对应一个独立功能。本次部分服务后复用的实际程序补齐了
一种生命周期，未新增原生DA键；因此不能据此宣布149键已解释完。

下一条人能理解的问题是：两条真实旧反馈中，一条仍能找到当前逻辑身份，
另一条已经失去驻留身份。后者按旧物理提议重新学习时，能否替代前者？若
允许替代，必须明确生效的完整版本及不受影响的分支，不能混合来源计数和
标签；若要求保留某一条，也必须有明确优先规则，不能凭现有实现猜测。

## 正常事件已暴露模型边界

沿原双迁移的正常准备执行前23步，保存两份不同原预测，原A=2、B=5。
在最后一次B重分配之前停止：当前A已到另一owner且计数为2，原B已经
不在驻留集合。两份原快照保持，未设置DUT或模型表状态、dirty或计数。

给一份真正旧来源发送原先合法的A不跳、B跳指导，会产生两条完整学习
提议：A应沿其当前owner，B则没有当前保留身份，仍提议原owner。此时二者
可能争用同一个目的地。当前独立RecentLearning模型抛出“同时更新不能
共享保留目的地”，尚不能用于验证该正常到达的状态。见
[纯模型复现](../results/production-bpu-partial-reuse-20261017-v1/partial-residency-model-gap.json)。

这份推演不是DUT执行、RTL反例或覆盖率信用；它证明的是当前参考模型的
输入范围还有未处置的边界。来源属于有界预测／反馈程序，尚未证明完整
FTQ中两份旧来源在这些重定向之后都仍有提交资格；来源存活和撤销资格
也须审查。两个原身份都重新驻留的既有PASS不能替代本项证据。

## 先明确允许结果再设计DUT用例

需要核对的合同包括：已失去驻留身份的旧provider学习能否重新安装记录；
同目的地多个完整提议是否允许一份替代另一份；以及优先关系是否属于
公开微架构合同，或应由独立合法结果集合表达。不能把RTL端口循环的最后
赋值天然当作规格，也不能默认所有旧反馈都保证无损。

只有这些条件明确后，才扩展语义模型及错误注入，再设计真实来源、实际
提议、完整服务和新消费者的DUT程序。既有容量加一替换、迁移、部分服务
及useful归属合同保留；不扩大XFAIL，不跳过主模型，也不靠写内部状态
绕过这一模型缺口。

## 已验证的确定分解事件

另立[失驻旧身份重新学习合同](tage-partial-residency-cases-20261017.md)：只反馈仍
驻留的 A，或用真实原 A=0 且当前 A=0 的饱和资格抑制 A 写，从而单独验证
B 的重新学习。干净占位者、待写占位者及两个旧身份先后重新建立的三个
程序归 INT-098，驻留 A 控制归 INT-089。四个 DUT 程序通过，372 项定向
PASS，32 项配对义务闭合；新增原生 DA 为 0，尚未进行本批完整回归。

这些程序不采用本页原 A=2、B=5 的双提案竞争，不修改其主模型拒绝条件，
也不规定竞争优先级。另有两路逻辑服务顺序不同的正常事件程序，已通过
独立模型推演但尚无 DUT 信用；不得用以上确定分解的 PASS 关闭原竞争边界。
