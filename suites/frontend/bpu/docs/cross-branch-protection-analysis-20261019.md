# 不同分支的旧反馈仍按原贡献奖惩

先前缺口归因把方向内容持久性和替换保护混在一起。逐条检查生成 RTL 的邻近赋值及原 Chisel 后确认：UTAGE 的1,843行、集成BPU的2,193行直接更新短历史经验的保护，而不是写回方向内容。已有持久性失败不能解释这些保护状态缺口的全部原因。

## 功能要求及已有证据的不足

功能是“自己的旧反馈，只按自己当时的贡献改变自己的经验保护”：

- 原预测纠正了错误的基础方向，后来确认正确，应获得奖励。
- 原预测只是同意本来就正确的基础方向，不应凭空获得奖励。
- 原预测错误，即使其他反馈已使当前方向变正确，也不能追认旧预测正确。
- 方向计数累计到当前版本；正确性、基础方向和分支身份仍来自原预测，不能借用另一分支。

已有单分支短/长九类保护事件、两分支共存及竞争替换并未完整证明上述多份迟到原件组合。尤其不同读取祖先不等于不同匹配分支。本次先写[语义契约](cross-branch-protection-contract.json)，再实现程序；仅扩展现有UTAGE-021/023，其他351个定义不变，不新增功能编号。

## 程序与独立预期

每个程序使用四个真实匹配PC，两对相邻分支分属两个代码块，初始方向相反。正常建立经验，捕获不同原件，先用其他反馈反转当前方向，再返回原正确/基础同意原件，最后返回反转期间捕获的原错误原件。

同/不同读取祖先、串行/相邻反馈、捕获/反向返回顺序构成8个程序。分支身份用于区分资格归属，不是枚举bank或set。每个程序16笔真实反馈，20个阶段及最终短/长新消费者；短/长完整版本、全部1,024个保护状态、每个反馈间隔及全部原件不可变性均检查。

预期来自未修改的独立 `UtageReference`、`ProtectionState` 及语义程序。未从DUT寄存器恢复预期；case不直接操作IO、边沿或固定等待。原始15位tag承诺不缩窄以迁就DUT。

## 实测及边界

最终源码冻结下：

- 主批次89项：84 PASS、5个既有普通FAIL；旧81项逐项保持。
- 新8程序全部PASS，112/112 reached及checked。
- 独立8项全PASS回放确认同样的14个新增UTAGE原生行，均为保护更新；没有仅靠失败执行新增的行。
- 1,986项相关纯模型/检查器测试及9项框架关键门禁通过。
- UTAGE累计由9,210/11,053增至9,224/11,053（83.4525%）；BPU仍38,130/46,541（81.9278%）。全部模块剩余未命中由10,775降至10,761。

早期收集曾误用双参数feature标记；已改为框架支持的两个单参数标记。框架预检另发现测试夹具的同名常量被另一模块导入覆盖，6项门禁因此失败；修正独立别名后重新冻结并重跑，9项门禁全部通过。早期结果不冒充最终源码证据。

本范围是独立UTAGE公开训练切点，不是完整BPU/FTQ合法性证明。高tag截断、在途归属、退休后持久性等既有失败没有豁免；未修改RTL、DUT或SDK，也没有新增XFAIL。剩余4,022个保护相关行仍保留原分母；本次有界通过不证明所有物理副本等价。

## 后续

不重复这8个原资格程序，也不改换物理坐标争取行数。继续从较大的早期方向及剩余保护缺口，核对是否缺少“有效贡献如何经集成基础方向竞争形成”“旧资格遇到真正替换或恢复后的归属”等独立要求；先区分已有完整程序、已知失败阻断和真正未证明组合，再决定新增case。

原始历史试跑已删除。最终89项现已被后续专项回归替代，其必要事实与独立通过回放的精简LCOV、精确JUnit、原件见证和源码身份，均按原逻辑路径收入 `results/current/evidence.zip`，索引逐条校验。当前实际目录以 `results/README.md` 为准；旧DAT、波形和逐周期轨迹不保留。
