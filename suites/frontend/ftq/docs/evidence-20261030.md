## 本轮证明了什么

- 验证包已按 agent / driver / monitor / checker / transaction 分层运行：测试只使用
  事务 API，引脚所有权、缺失引脚和非法编码在 fixture 边界报错；三个 module agent
  和共享 `common` 层在 109 PASS（含功能用例与检查器自检）中实际执行。
- 三个 DUT 的合法功能点、时序竞争、背压、复位、重定向、容量（8 分支以内）、64 索引
  meta 在本次运行中通过或被明确记录。
- 顶层闭包行覆盖从 97.4% 提升到 100.0%；R-02（顶层 IFU 命中 fallback 枚举缺口）关闭。
- 两个 strict XFAIL 继续证明并保留 ResolveQueue 的一个真实缺陷：分支槽越界回绕覆盖
  已有报告。
- 顶层指针不变量每拍检查，替代被生成流程去掉的 `XSError` 断言；它不等于形式证明。

## 没有证明什么

- 检查器自检（`tests/checkers/`）在 Python expected/模型层注入错误，用于证明比较路径
  不是空跑；它们不是 RTL mutant，也不证明 RTL mutation coverage。
- 不证明未修复的 R-01；不证明 100% 分支/toggle（R-03/R-04/R-09）；不证明同拍 IFU
  合并臂在顶层可达（当前配置结构不可达）。
- 不证明 ICache/IFU/BPU/后端的消费行为，也不证明整机取指正确。
- 未做上游差分（R-07）；未保留/启用全部 RTL 内部断言（R-05）。
- 结果只对上述基线、工具、闭包和种子成立；修改 RTL/工具/用例后需新目录重跑。
