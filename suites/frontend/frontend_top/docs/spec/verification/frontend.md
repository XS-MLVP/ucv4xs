## 范围与假设

验证 `Frontend` 的实际闭包，包含 BPU、FTQ、ICache、IFU、IBuffer、InstrUncache 等真实
子模块；外部后端、TL/PTW/CSR 生产者须有明确合法域。子模块 UT 的用例和 PASS 不自动
算作本层证据，也不把外部生产者替身的行为算成真实后端/L2 验证。

当前源码接线可定位于 `Frontend.scala:220–268`，仅用于确认验证切点；独立预期来自
经评审的接口/ISA/协议合同，不能把源码接线本身当作正确性 oracle。以下为待评审责任草案。

## 完成条件与缺口

认领时逐条确认合法域、接受/取消事件、独立预期和观察点；缺少观察不能记 PASS。
构建与冒烟、功能判定、覆盖分别留下当前基线与实际选择的证据。每条已接受要求应有
合法对照和能区分关键错误的检查器对照，未覆盖和不可达范围明确记录。

`instrUncache.io.flush := false.B` 是当前源码事实，不等于取消行为已正确。设计确认与
未证明范围继续链接唯一的
[FRONTEND-FLUSH-CONNECT](../../../../instr_uncache/docs/bugs/open/FRONTEND-FLUSH-CONNECT.md)；
