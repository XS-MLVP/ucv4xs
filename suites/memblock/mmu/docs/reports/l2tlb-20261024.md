  `Bitmap`、`BitmapCache`、`PMP`、`L2TlbMissQueue`、`L2TlbPrefetch` 和 arbiter。

- 功能覆盖：`l2tlb` 组 **100%**（88 samples；event/page/stage/port 全部 bin 命中）。
- DUT-only 行覆盖：**17081/22249 = 76.772%**。
- DUT-only branch：**4329/6304 = 68.67%**。
- DUT-only toggle：**96615/255430 = 37.82%**。
- 首轮集成（`l2tlb-tests-03`）为行 69.68%、branch 3607/6304、toggle
  63583/255430；两轮补测后行覆盖提升 6.62 个百分点。
- **第二阶段已闭合**：bitmap deny/allow、PMA/PMP 页表属性交互、scoped sfence
  重走、satp.changed+sfence；PTW full_gvpn 在独立 leaf 闭合。
- **仍未闭合/边界**：all-address sfence（strict XFAIL）、LLPTW 多 allStage 与
  Bitmap 多 miss（由各自 leaf XFAIL 记录）、PtwCache 物理 way/DFT 残余。
  >2 outstanding 已闭合（mem_latency=7 下 4 个请求全部完成）。不能据此声称

## 5. 未覆盖项逐项分类

### 5.1 已有功能点的情况枚举缺失（补测可继续收敛）

- **PtwCache sfence 地址/ASID 哈希与替换**：已有“缓存命中/重走/有限容量”功能点，
  但只覆盖了部分地址低位和方式；需要按 set/way 定向构造请求。属于情况枚举缺失。
- **LLPTW 多 entry**：已有“2MB 触发 LLPTW、4KB 走表”功能点，但没有同时排队 8 条
  LLPTW 请求；需要多请求/等待向量场景。属于情况枚举缺失。
- **PTW full_gvpn**：已有“VPN 透传/高页大小”功能点，但没有构造 512GB 级 VPN 的
  高 `full_gvpn` 分支；属于情况枚举缺失。
- **PMP 高位 entry/UART 边界**：已写 32 个 entry 寄存器并验证 allow/deny/TOR，
  但 PMP checker 的边界/锁定组合未全枚举；属于情况枚举缺失。

### 5.2 整体功能点缺失（尚未定义/验收）

- **PMA（`0x7xx` CSR）配置语义**：当前只扫描 PMP 段；PMA 基址/掩码/映射没有
  功能点，未验证。写入 `0x7C0..0x7FF` 会改变内存属性，本轮没有建立可恢复的
  语义模型。
- **Bitmap deny / MPT 权限失败**：只验收“all-ones bitmap 允许”。all-zero bitmap
  仍观察到成功，deny 极性/检查位未建立，因此不把 deny 写成已验收功能点。
- **MBIST/DFT**：`MbistBitmapCache`/`MbistPipePtwL0`/`MbistPipePtwL1` 的 MBIST
  端口未驱动，属于整体 DFT 功能点缺失，不在本轮 UT 范围。
- **PtwCache/PTW/LLPTW/Bitmap 独立 DUT 叶级闭环**：它们只在 L2TLB 顶层以
  真实 RTL 验证；尚未逐块建 DUT、定义叶级功能点、独立审计。不能用顶层覆盖数字
  代替。HPTW 已另行建立独立 DUT 并闭合（见 `hptw-20261024.md`），其 133/133 行、
  97/98 branch 的结果与顶层集成结果相互独立。
- **L2TLBWrapper**：曾未建 DUT；2026-10-25 已补齐独立组合 DUT，最终
  `l2tlbwrapper-final-05`（46 PASS + 1 strict XFAIL，包装层本体 40/40 行），
  详见 [L2TLBWrapper 报告](l2tlbwrapper-20261025.md)。

## 6. 已知问题/观察

1. `satp.changed` 后不执行 sfence，同一 VPN 曾直接返回旧 PtwCache 翻译且无新内存读。
   软件语义要求在 satp 更新后执行 sfence；最终用例改为 satp.changed + sfence 后
   验证新根页表。作为行为观察记录，未据此判定 RTL 缺陷。
2. `sfence` 的 rs1=0/rs2=0（全地址编码）在本次序列中没有触发重新走表；带
   rs1=1 的地址/ASID 形式和全地址形式已验证。该编码的预期语义需要设计确认，
   未豁免。
3. `PtwCache` 的 12 条翻译重放会因容量/替换重新走表；这是有限 cache 的预期行为，
   用例只断言结果正确，不断言“全命中”。
4. L2TLB 顶层 branch 仍缺 2007 个点，toggle 缺 159727 个点；主要是大容量
   cache/LLPTW/bitmap/PMP 的未枚举状态，不能声称闭合。

## 第二阶段更新（2026-10-25）

新增并通过的功能点：

- **bitmap deny/allow**：`test_bitmap_deny_and_allow`，全 1 bitmap 的 cf=1 返回
  `s1_af=1`，全 0 bitmap 返回正确 PPN；旧“all-zero 成功”观察是未检查 `s1_af`。
- **PMA/PMP 页表属性**：`test_pma_cacheable_page_tables_walk` 用 TOR 覆盖页表，
  C=1/R=1 时完成 root/mid/leaf 三次读；C=0 或 R=0 时在表读前返回 `s1_af=1`。
- **scoped sfence 重走**：修改 PTE 后 `rs1=1,rs2=0,addr` 返回新 PPN 并产生新表读。
- **all-address sfence（未闭合）**：`rs1=0/rs2=0` 返回旧 PPN 且无新表读，strict
  XFAIL `test_sfence_all_rewalks_after_pte_change`，known-issue
  `L2TLB-SFENCE-RS1RS2-ZERO-NO-REWALK`。
- **>2 outstanding（已闭合）**：4 个不同 4KB 请求在内存服务延迟 7 拍时全部完成；
  零延迟模型会丢失第二个 D beat，已确认是 harness 时序问题，不是 RTL 在途限制。
- **satp.changed 无 sfence**：不在软件契约内；supported 的 satp.changed+sfence
  路径仍由 `test_satp_change_with_sfence_rewalks` 验证。

最终 run `l2tlb-final-12`：40 PASS + 1 XFAIL，行 17081/22249，branch 4329/6304，
toggle 96615/255430，功能 100%。
