## 2. 测试环境

HPTW 的公开接口分为请求/响应、64 位页表内存、M/PMP、bitmap、refill 和
l0_way_info。测试侧只实现：

- 稀疏字节内存 `PageMemory`，按 `io_mem_req_bits_addr` 返回 64 位 PTE；
- PMP 响应（`ld=0,mmio=0` 表示允许；`ld=1` 或 `mmio=1` 表示故障）；
- bitmap 请求/响应握手（`cf=0` 表示通过）；
- CSR hgatp/satp/vsatp/mbmc/mPBMTE 与 sfence 驱动。

没有内部信号探针，没有用 Python 模型替代 HPTW 的走表状态机。

注意：HPTW 生成 RTL 的 `accessFault` 只由 flush 清除，而不是同步 reset；环境在
reset 后额外插入一次 sfence flush，避免随机初始化残留造成假 gaf。这是本叶级
DUT 的初始化约定，已写入 env 注释。该行为同时记录为候选 RTL 缺陷
`HPTW-ACCESSFAULT-NOT-RESET`：若 SoC 在 reset 后、首次 G-stage 走表前没有 flush，
可能出现一次假 guest access fault，需要设计确认。
