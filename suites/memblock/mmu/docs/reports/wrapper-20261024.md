## 2. 基线与层次

- RTL：`soc-split/rtl/TlbStorageWrapper.sv`（SHA-256
  `f93a734ac9aff6912735d43d49dc0305bb499a786729edac35481b526197963d`）
  与 `TLBFA.sv`、`ClockGate.sv` 原样复制。
- 真实层次：`TlbStorageWrapper` 内部实例化 `TLBFA` 48-way 叶子；wrapper 只做
  读/回填/失效透传和 PLRU 选择。
- 运行无内部信号、无运行时波形；touch_ways 通过真实子块输出驱动 PLRU。

## 3. 功能点与用例

功能点文档：[functional-points-wrapper.md](../functional-points-wrapper.md)。

覆盖的关键语义：

- 复位清空真实叶子和 PLRU 状态；初始 victim 序列从 way 0 开始。
- 纯 tree-PLRU 选择 victim；读命中改变下一 victim；回填 touch 也更新 PLRU。
- 回填只在下一拍可见；同拍查找对正在回填的 way 被屏蔽。
- 读命中的 PPN/权限/上下文原样来自真实 TLBFA。
- sfence/hfence 原样透传，不重置 PLRU；无匹配失效不误清条目。
- 48 个 victim way 都被实际选中；前 60 次回填只覆盖 46 个 way，补充 steering
  后覆盖全部 48 个。

## 4. 覆盖率闭环

首轮 `wrapper-initial-03`（5 用例，全 PASS）：

| 指标 | 首轮 | 最终 |
|---|---:|---:|
| 功能覆盖 | replace 98.96%、fence 50%、timing 66.67% | 5 组全部 100% |
| DUT 行 | 2859/3431 = 83.33% | 3431/3431 = 100% |
| toggle | 9195/18798 = 48.92% | 18798/18798 = 100% |
| branch | 632/1022 | 1019/1022 |

缺口定位与补测：

1. **victim_way 15/31 缺失**：已有替换功能点的情况枚举不足。前 60 次回填的纯
   PLRU 序列未选中 15/31；增加 way 15、47、31 的定向回填与 way 32 读命中 steering，
   48/48 victim way 覆盖。
2. **fence 形式缺失**：补 `addr_asid`、`hfenceg`（rs2=0/1）、`all_asid`、
   `addr_all_asid` 和 hfencev rs2=0；对应 TLBFA 每 way 的失效表达式全部执行。
3. **timing valid_drop 缺失**：在查找撤销请求后采样响应有效拍结束。
4. **toggle 48.92%**：缺口是 sfence 地址/ID、CSR ASID/VMID 高位和 hit 路径输入位。
   补 `test_wrapper_context_and_fence_input_bits_toggle` 与 63 次 all-ones/复位/
   63 次 all-zeros 回填，完成存储位和输入位双向覆盖。
5. **行覆盖 83.33% → 100%**：补 hfenceg rs2=1、all-ASID 地址形式，使 TLBFA 每
   way 的地址/ASID 失效表达式全部执行。

## 6. 新发现：PLRU 不优先使用无效 way

从复位状态连续回填时，纯 tree-PLRU 的 victim 序列为
`0, 32, 16, 40, 8, 36, 24, 44, ...`。前 60 次回填只选中 46 个不同 way，
way 15 和 31 仍保持 invalid；第 61/63 次才分别选中它们。wrapper 没有使用
`replaceWrapper` 的“无效 way 优先”逻辑。

这不是功能错误（旧翻译不会被错误命中，替换仍只写一个 way），但会造成冷启动
阶段反复覆盖已有 way、无效 way 闲置的性能问题。已在
`WRAPPER-PLRU-NO-INVALID-PRIORITY` 记录，未修改 RTL。
