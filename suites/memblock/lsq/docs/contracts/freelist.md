# FreeList：槽位所有权、延迟回收与分配可用性的合同

基线：开源 `893e1580b`，`mem/lsqueue/FreeList.scala`；功能点先于测试实现定义。测试实际生成的四个独立 DUT，不更改 RTL 或添加虚构端口。

## 微架构行为

FreeList 管理业务队列条目的所有权，不是普通 ready/valid FIFO。复位使全部槽位可分配，初始分配顺序为槽位编号顺序。`doAllocate` 的置位数表示本拍确认消耗的前缀槽位数；调用者使用自己的压紧 offset 取得槽位，不能把稀疏确认 lane 误解为同编号槽位选择。现成实例的 `allocateReq` 已常量化。

释放通知不是立即返还容量：同一回收通道（slot modulo 4）积压的槽位依次回收；每个通道优先处理编号较小的待回收槽位，同批按通道顺序追加。输入通知先登记，下一拍选择，再下一拍返回可分配池。其他通道不能因某通道积压而丢失回收。

非预分配变体公开当前可用槽位；预分配变体先准备窗口，最近一拍新归还的容量不能立刻被当作预分配窗口已就绪。只比较有效 offer；容量不足时的无效 allocateSlot 是 don't-care。不能为提高覆盖而分配无效 offer。

参考采用独立的可用槽位队列、持有者集合、按回收通道的等待集合和已选择回收批次；不读取 DUT 的 freeList/headPtr/tailPtr/freeMask/allocateWindow。

## 合法域、观察与时序

- 输入释放的槽位必须仍由调用者持有，不得重复释放；不得超出当前可分配前缀确认分配。
- 每拍可分配 0～3 个槽位；释放通知可包含多个已持有槽位，积压由回收机制处理。
- reset 中不发分配/释放；复位终止旧所有权与待回收批次。释放 reset 后留出预分配流水初始化窗口。
- 在 DriveStable 被动采样本拍真实输入和 offer，在 RisingEdge 被动采样更新后的输出。模型按前者输入演化，checker 比较两处有效观察，不用 driver 的发送日志替代输入观察。
- `validCount` 是尚未返回可用池的占用数，含在途回收；`empty` 表示可用池空，不等于所有业务请求退休。

| key / top | 槽位数 | 预分配 | 真实公开状态 |
|---|---:|---|---|
| freelist_rar / FreeList | 96 | 否 | canAllocate[3]、validCount |
| freelist_raw / FreeList_1 | 56 | 是 | canAllocate[3]、empty |
| freelist_replay / FreeList_2 | 120 | 是 | empty；没有 canAllocate |
| freelist_uncache / FreeList_3 | 16 | 是 | canAllocate[3]；没有 empty/validCount |

Replay 变体不具备可用前缀输出，激励用独立模型限制合法确认数；只声明验证其保留的接口行为，不把删去的 canAllocate 算作已测。Uncache 类似地不能伪造 occupancy 输出。

## 人类可读功能点

| ID | 行为要求 | 必需情形 | 判断依据 |
|---|---|---|---|
| FL-RESET | 复位重新建立完整槽位所有权，不携带旧使用者或回收请求 | 初始复位；活动/积压期间再复位 | 复位后有效 offer 和公开容量符合初始顺序，旧槽位不会重复归还 |
| FL-ALLOC | 接受一个或多个分配后，按顺序且不重复地交付空闲槽位 | 单个、部分批次、满带宽；稀疏确认计数 | 被动采到的确认与有效 offer；独立所有权账本 |
| FL-IDLE | 未确认分配且没有回收时，槽位所有权与下一可用前缀保持 | 有空闲；耗尽；预分配连续空拍 | 前后有效输出及公开占用一致 |
| FL-CAPACITY | 槽位耗尽后不能向调用者承诺不存在的容量 | 仅余 1/2 个；完全耗尽；回收后恢复 | 有效前缀/empty/validCount，按各实例实际接口检查 |
| FL-RETURN | 已释放槽位经过回收流水后重新可用，不能早用、丢失或重复 | 单次释放；全部槽位回收 | 释放接受、等待批次与重新分配之间的所有权关联 |
| FL-CONGESTION | 同一回收通道积压不会丢回收，其他通道仍能推进 | 同通道多项；多通道混合；边回收边继续通知 | 逐批返回顺序、总量和完整槽位集合 |
| FL-OVERLAP | 分配与释放/回收重叠时，分别更新所有权且总量守恒 | 新通知与分配同拍；已选择回收与分配同拍 | 输入观察、分配槽位、模型与公开容量 |
| FL-WRAP | 多次使用整个池后仍正确区分新旧槽位生命周期 | 分配指针回绕；回收指针回绕；多轮复用 | 完整分配序列和不重复所有权，非 2 幂边界同样检查 |
| FL-PREFETCH | 预分配窗口在连续消费和回收边界上不交付陈旧槽位 | 预分配变体连续批次；空池恢复；部分批次后满批次 | 有效 offer 与参考可用前缀；新回收尚未准备好时禁止消费 |
| FL-ORDER | 回收顺序由实际回收通道和积压决定，而非通知顺序 | 乱序归还；同通道大小编号混合 | 独立回收账本预测的再分配顺序 |

功能覆盖在观察路径记录 reached，在完成对应比较后记录 checked；case 名称或“设置过某参数”不能产生功能命中。容量/流水的 finer scenarios 从实际账本状态和真实输入识别，不把 RTL 寄存器组合枚举当功能点。

### 第一轮缺口驱动的情形细化

`results/freelist-initial-02/line-audit.json` 逐行记录了四个真实 DUT 的未覆盖位置。首轮所有未覆盖执行行属于已有功能点缺少回收情形，而不是删去或不可达的逻辑：回收写槽位、推进回收尾部，以及四个回收通道的选择/批次寄存。补例必须实际重新分配回收槽位，以比较整个返回顺序，不能只发出释放通知。

- 同一通道先通知较大编号，再在下一拍通知较小编号：已经选中的批次不能被改写，尚未选中的积压按编号优先，而非通知年龄优先。归入 FL-ORDER 的 `priority_over_notification_age` 情形。
- 变长释放批次和单通道长积压在池的各个位置落地，覆盖回收写入、紧凑追加、回绕；这些是 FL-RETURN/FL-CONGESTION/FL-WRAP 的实现情形，不把每个存储单元另列一个功能点。
- 分别在只持有槽位、通知尚未选择、已有在途批次时复位，复位持续至少三拍，随后重新使用完整池并检查旧回收不泄漏。
- 对延迟回收、拥塞、释放重叠、回收顺序和回收回绕，`reached` 记录真实输入触发，`checked` 延后到对应槽位经实际有效输出重新分配且比较通过。复位取消的旧义务不记作通过。即时容量和分配比较仍在当拍完成。

首轮尚未产生这些回收情形的 checked 命中；补例阶段将 checked 合同细化为上述时序完成口径，不能把第一拍的输出比较称作完整回收检查。

## 首轮与补例规则

首轮先运行复位、分配、耗尽、空闲场景，保存原生行覆盖。逐段查看未覆盖执行行，区分已有功能点的缺失情形与缺失行为，再补回收、拥塞、重叠、回绕、复位打断和合法随机用例。每轮保留独立输出目录与前后统计，不覆盖旧证据。无法通过公开有效域到达的行需说明，不通过非法分配或修改 RTL 消除缺口。
