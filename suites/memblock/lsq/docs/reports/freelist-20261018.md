1. 条件回收写入每个池位置：缺少 FL-RETURN/FL-CONGESTION/FL-ORDER/FL-WRAP 的释放、同/多通道、变长批次和回绕情形。

## 功能检查而非只跑激励

参考是“可分配 ID 序列 + 使用者集合 + 通道等待集合 + 在途回收批次”，不是 RTL 的指针/位矩阵翻译。模型只接收被动 monitor 的真实引脚观察，不读取 DUT 内部寄存器，不以 driver 日志为答案。

- 每个真实周期在 DriveStable 比较有效分配前缀，在 RisingEdge 后比较更新前缀及实际保留的 `canAllocate`/`empty`/`validCount`；fixture/test 切换时产生的真实空拍也逐拍消费和检查。
- `validCount` 包含未真正返回池的回收在途占用，不能等同于仍被业务持有的 ID 数。
- 所有返回都由旧使用者持有；每拍确认数不超过合法有效前缀；每轮检查完整 ID 集合、不重复、顺序与分配/回收的关联。
- 对回收类情形，checked 还要求相关 ID 经实际有效输出被重新分配并比较成功。复位取消的旧义务不计为通过。该时序口径比首轮的即时 checked 更严格；首轮原本就没有这些回收命中。

补充用例位于 `tests/freelist/test_returns.py`，每个 DUT 额外 10 例，共 13 例/DUT：

| 行为要求 | 实际补充情形及断言 |
|---|---|
| FL-RETURN、FL-CAPACITY | 空池整批释放，N、N+1 不回收、N+2 开始返回，三轮完整复用；分别观察剩 2、剩 1、耗尽和恢复 |
| FL-CONGESTION、FL-WRAP | 每个回收通道长积压；轮换领先通道，使各通道回收遍历全池位置；重新分配顺序必须等于独立构造的完整序列 |
| FL-ORDER | 同通道先通知 12/8，再通知 4/0，实际再分配必须是 `(8, 0, 4, 12)`：已选项保持、未选项按编号而非通知年龄优先 |
| FL-OVERLAP、FL-PREFETCH | 分配与新通知、在途回收同拍；连续/部分批次与空池恢复不交付陈旧 ID |
| FL-RESET | 分别在只持有、等待选择、已有选中批次时复位；重建 `0..size-1` 完整池，继续空拍确认旧回收不泄漏 |
| 合法并发随机 | 各变体种子 `88`、`20261018`，每种子 1200 拍；填充/释放波浪、稀疏确认、乱序归还；最后归还全部使用者并重新分配完整池 |

Verilator 原生初始化种子固定为 1，Python 随机种子出现在 pytest 参数 node ID 和冻结源码中。

## 失败保留与限制

- `freelist-initial-01` 和 `freelist-timing-debug-01` 保留最初的测试台时序适配失败。原因是 async fixture/test 切换有真实空拍，但早期消费者错误地假定“一次 send 对应队列中下一条观察”；修正为按 tick 消费并检查每条观察后，`initial-02` 12/12 通过。没有为此修改 RTL。
- 首轮未冻结完整测试源码；该证据缺口已由补例运行的 verification-source/hash 机制补上，不能声称首轮也有同样快照。
- 四个实际 top 的端口不同：Replay 没有 canAllocate，Uncache 没有 empty/validCount。不存在的接口不计为已验证；只在合同合法可用域比较 offer。
- 不测试超额分配、重复 free、未持有 ID free 或复位期发操作等非法输入。预分配窗口的复位初始化留出暖机拍，复位保持三拍；不声称支持任意短复位脉冲。
- 现成 RTL 的来源由元数据和静态层次核对，未重新 elaboration 证明源码逐文件对应；当前 release RTL 未保留的断言/功能不能据此宣称已覆盖。
- 行覆盖 100% 不是形式化穷尽证明，也不是父块连接已验证。后续仍必须逐块验证 CAM、AgeDetector、业务队列和真实 LoadQueue/StoreQueue/LsqWrapper。

## 复现

在独立 LSQ 根目录，保留原生包后执行新目录运行，不覆盖旧证据：

```sh
python3 -B tools/run.py --name freelist-recheck-<唯一后缀> --workers 1 -- tests/freelist
python3 -B tools/coverage_audit.py freelist-recheck-<唯一后缀>
```

实际调用参数和工具版本见 `command.json`、`manifest/toolchain.json`、DUT 的 `build-provenance.json`。安装版本不符会在 fixture 门禁报错，不退化到其他工程的模型。
