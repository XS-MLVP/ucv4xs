## 2. RAR-REL-001：一拍valid/address错位

已冻结合同要求新条目在 `nc || dataValid && (本拍或前一拍完整line release命中)` 时置released。源码注释 `LoadQueueRAR.scala:130-138` 说明release延迟1拍以捕获分配窗口；183～189行使用该窗口。实际生成RTL却为：

```systemverilog
release2Cycle_valid <= release2Cycle_valid_REG;
if (io_release_valid)
  release2Cycle_bits_paddr <= io_release_bits_paddr;
release2Cycle_valid_REG <= io_release_valid;
```

地址在当前有效边沿保存，valid比它多延迟一级；新分配条件直接使用两者。只发孤立release并随后不再release，公开端口得到：

| release相对分配的距离 | dataValid=true、nc=false的合同预期nuke | 实际nuke | 三lane结果 |
|---:|---|---|---|
| 同拍0 | true | true | 通过 |
| 前拍1 | true | **false** | 全部漏报 |
| 两拍2 | false | **true** | 全部误捕获过期标记 |
| 三拍3 | false | false | 通过；之后late release能真正标记记录 |

dataValid=false的全部距离反例通过；已有记录的late release、hash碰撞保守标记以及同拍新记录不参与查询也有实际检查。

最小序列：reset保持6拍并暖机；边沿N输入 `release.valid=1,paddr=0x18007`；N+1在任一lane分配ROB=2、SQ无关、LQ=2、paddr=0x18000、dataValid=1、nc=0；N+2输入ROB=1、LQ=head=0、同地址的老load查询，得到resp.valid=1但nuke=0（预期1）。在分配前插入一拍idle则得到相反的过期标记误报。

## 3. 模型、观察与证据审计

`lsqverify/rar/` 使用唯一UID、解环ROB/LQ年龄、语义记录和独立FreeList延迟回收账本；真实父DUT仍包含全部原生FreeList/CAM及三份直连辅助模块。参考不读取DUT内部寄存器。ready、full、三个resp及两个perf均逐拍比较；无效resp payload不比较。有效query响应不等于分配成功，full是少于6个空槽而不是零空槽。

分配需唯一正probe；删除需先正后负；未released与复用需先负后正；未分配路径要求紧接下一边沿的同key老查询；活动reset需先证明旧记录存在、reset后旧记录负probe消失，再证明新记录存在。reset清空未完成义务不算通过。
