## 3. 实测语义（与直觉不同之处）

1. **通道 valid 不看 bank 位图**：`io_pseudoError_*_valid` 只由 `ese`、`comp` 与延迟
   条件决定。`bank=0` 时仍会产生一次通道有效、payload 全无效的请求，并消费掉非 persist
   的 `ese`。bank 位图只决定 payload 中各 bank 的 valid。
2. **单次注入在“捕获”时清 ese，而不是在消费者接收时**：即使 `ready=0` 让请求停在
   输出，读回 ctrl 已看到 ese=0；消费者之后接收也不会再产生新请求。
3. **延迟寄存器写入同时加载 counter**：`ede=1` 时，先写 delay 再由 ctrl 使能；首次注入
   出现在 ctrl 提交后第 `delay+1` 个时钟沿。persist 模式在每次 fire 时按 `delay` 重装
   counter，因此消费后按 `delay+1` 周期重复。
4. **persist + 延迟在 ready 连续为高时呈脉冲**：一次 fire 与下一请求的捕获可以同拍，
   但流水输出会在下一拍被消费，形成周期脉冲；若 ready 在单次握手后立即撤销，新请求会
   留在流水里，下一次握手可立即完成。
5. **data mask 是 16-bit、零扩展到 36-bit**：`io_pseudoError_1_bits_*_mask[35:16]`
   恒为 0，这是接口位宽决定的。

### 4.3 Toggle（DUT-only 664 点未覆盖）

| 类别 | 数量 | 归因 |
|---|---:|---|
| `io_pseudoError_1_bits_*_mask[35:16]` | 640 | data mask 寄存器只有 16 bit，接口 36 bit 的高 20 位恒 0；32 bank × 20 bit |
| pipeline `data_*_mask[35:16]` / `io_out_bits_*_mask[35:16]` | 24 + 少量 | 同上，寄存器快照的高位恒 0 |
| A/D opcode 未用编码 | 12 | 寄存器节点只使用 Get(4)/PutFullData(0)/AccessAck(0)/AccessAckData(1)，其余 opcode 位不会出现 |
| size 固定 3、address 低 3 位恒 0 | 14 | 8 字节寄存器访问，`size=3`、字节偏移 0 |
| queue ram 的 size 位 | 2 | 同上，固定 size 的 1→0 不会发生 |

这些点都是协议/位宽常量，不是遗漏的功能情形；所有可写的 64-bit 寄存器、tag mask
36 位、32 个 data mask 的低 16 位、32 个 bank 输出都完成了双向 toggle。
