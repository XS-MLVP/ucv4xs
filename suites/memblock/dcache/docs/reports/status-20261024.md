## 3. 顶层 load/refill 已闭合

通过 VPI debug 构建（`dut/dcache-debug`，仅调查用，不参与 UT 证据）确认了三个原因：

1. tag/meta SRAM 复位后需要 **256 拍**逐 set 清扫，清扫完成前 MainPipe 的
   tag/meta ready 为低；
2. `GrantData` 必须用 **size=6**（64B = 2 个 32B beat）；size=5 时 `r_beats1=0`，
   MissEntry 把第一个 beat 当成整行完成；
3. 重放 load 的响应只在 S2（接收后第 2 拍）有效，不能提前采样。

修正后 `tools/probe_dcache_refill.py` 与 `tests/dcache` 均观察到
“冷 miss → AcquireBlock(6,size6) → 2×GrantData → 重放命中，数据逐字节一致”。
`results/dc-final-05` 的 15 个用例覆盖了 load/miss/refill/双通道/store/probe/error。
