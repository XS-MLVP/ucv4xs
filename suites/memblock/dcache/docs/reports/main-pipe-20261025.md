## 4. 未覆盖项逐项归因

### 4.1 分支（剩余 7 个点）

| 位置 | 未覆盖分支 | 归因 |
|---|---|---|
| `MainPipeDut.v:1205` | `pseudo_error.bits_0.mask` 选择 | **范围限制**：伪错误注入寄存器（`io_pseudo_error_*`）由 CtrlUnit 控制，本轮 UT 不驱动该注入路径。属整体功能点“ECC 伪错误注入”未纳入，而非已有功能点情形缺失。 |
| `MainPipeDut.v:1302`、`3469` | `pseudo_error.valid` 与真实 tag 匹配组合 | 同上，伪错误注入路径。 |
| `MainPipeDut.v:7556` | `if (reset)` 的内层 else 分支 | **工具/结构限制**：Verilator 对复位块产生的影子分支；复位只在用例开始时断言一次，该嵌套条件在正常时序下不可达。 |
| `MainPipeDut.v:7793`、`7796` | ternary 的 `3'h0` 默认臂 | **工具/结构限制**：`probe_param` 与 coh 的 12 种合法组合已全部覆盖（到 `3'h5`），`3'h0` 是防御性默认值，合法输入不可达。 |
| `MainPipeDut.v:210` | `io_data_write_bits_data_10` 端口声明 | **工具影子点**：端口声明行被 Verilator 记为分支，无 RTL 行为。 |

### 4.2 Toggle（DUT-only 72.67%）

未覆盖 toggle 按类：`public_port_bit` 11984、`data_or_mask_bit` 2364、
`other_internal_bit` 1054、`handshake_bit` 255、`state_or_tag_bit` 239。
主要来源是 512-bit store/refill 数据通路与 128-bit AMO 数据：功能检查按字节/字比对
数据正确性，但不要求每个数据位都发生 0→1 和 1→0 翻转。已通过 refill 全 1、全 0、
逐 bank 递增、store 全行/部分掩码等模式提高翻转；剩余部分属于**数据位未穷举**
（工具/范围限制），不影响行、分支与功能结论。

## 6. 结论与边界

- MainPipe 的行覆盖在公开端口驱动下达到 100%，分支 99.0%，18 个功能点全部有
  行为级断言，功能覆盖 100%。
- 未覆盖分支均可归因为伪错误注入范围、Verilator 结构影子点或不可达默认臂，
  不是“已有功能点缺少情形”而遗漏的功能行为。
- 不声称 LR/SC 与 MissQueue 的跨模块时序、伪错误注入、`sms`/`bloom_filter` 预取
  已经验收；这些在 DCache 顶层或后续阶段处理。
